# Localization & Number Formatting Parity

> **Human-GUI caveat (audit 2026-11-15):** the catalog checks below cover translation data, `ui.inspect`, PDF/SVG export, and headless QA. Below the desktop window's native `egui` menu bar, the rendered desktop and web canvas still draw chrome text with an uppercase-only 5×7 ASCII bitmap font (`draw_text_5x7` in `crates/ui-egui/src/compositor.rs`), so non-ASCII translated strings (CJK, Arabic, Hebrew, Greek, accented Latin) are not legible in the GUI a person sees. Proportional Unicode typography and a glyph-coverage gate are tracked in [`R10.9`](ROADMAP.md#r109-proportional-typography-unicode-coverage--glyph-gate); translations for new `R10` strings in [`R10.21`](ROADMAP.md#r1021-translations-for-new-ui-strings).

## Scientific & Regional Number Conventions
- [x] Configurable decimal separator (period `12.34` vs. comma `12,34`) independent of OS locale for reproducible journal figures (`LocalePreset`, `LocaleNumberPolicy`, `Format > Decimal Separator`, and `grid_view::parse_localized_number_input` preserving `=` formulas)
- [x] Configurable thousands/grouping separator (none, thin space `12 345`, comma, period) (`LocaleNumberPolicy::thousands_separator` across `lumencraft-text`, `lumencraft-format`, and `lumencraft-ui-egui`)
- [x] CSV/clipboard import locale presets (`en-US` comma-delimited vs. European semicolon-delimited `;` with decimal comma) (`CsvOptions::csv()` / `LocalePreset::comma_semicolon`, tested in `grid_view`, `format`, and Wave 7 live macOS `/usr/bin/pbcopy`+`/usr/bin/pbpaste` `de-DE` comma + `=A1*2` formula roundtrip `macos_clipboard_live`)
- [x] Localized *p*-value formatting presets (APA no-leading-zero `.004`, NEJM, Nature/Cell exact $p = 2.4 \times 10^{-5}$, or configurable star thresholds) (`PValueFormat::{FourDecimal, Apa, Nejm, Custom}` + `format_pvalue_label`)
