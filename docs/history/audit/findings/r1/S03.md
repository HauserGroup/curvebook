### R1-S03-01 · S1 · Poisson and robust fits report profile CIs exactly half the Wald width (profile computed on the wrong objective)

- **Base:** ebcc622b32fc526c545aad8439e3e580d04b478c
- **Location:** `crates/fit/src/solver.rs:1529` (also `:1675`), `crates/fit/src/solver.rs:2193`, `crates/fit/src/solver.rs:2224-2227`, `crates/fit/src/solver.rs:2293`, `crates/fit/src/diagnostics.rs:447`, `crates/fit/src/diagnostics.rs:556`
- **Category:** wrong-result
- **Defect:** With `PoissonDeviance` or `RobustCauchy`, `ss_min` passed to `compute_profile_likelihood_cis` is the Poisson deviance (`:2193`) or the Cauchy-reweighted SS from `work_obs` (`:2224-2227`). The profile subproblem evaluates the ordinary SS on the original `obs` weights (`:1531` → `:2293`/`:2330`), so the profile SS is far above `ss_crit` even at θ̂. The first trial step "brackets", `brent_root` returns `bracket_sign` because both ends are positive, and the fallback reports the bracket midpoint.
- **Failure scenario:** `Y = A*exp(-K*X)`, X = 0..9, counts ≈ 200·e^(−0.3X). This is the default config with `profile_likelihood_ci = true`, which is the `NonlinearFitSpec` default (`result.rs:312`). Both parameters get a "profile" CI of exactly θ̂ ± 0.5·t·SE, which is half the Wald interval, and status is `Converged`.
- **Evidence:** Probe `p1`:
  ```
  == Poisson: status Converged weighted_ss 4.158702 df 8
    A est 203.203053 profile [194.458571, 211.947535] sym [185.714090, 220.692017] ratio lo 0.5000 hi 0.5000
    K est 0.303469 profile [0.290392, 0.316546] sym [0.277315, 0.329623] ratio lo 0.5000 hi 0.5000
  == RobustCauchy: ... ratio lo 0.5000 hi 0.5000 (both parameters)
  == LeastSquares: ratios 0.96–1.05 (sane)
  ```
  The step length is `t·SE` (`diagnostics.rs:452`), the bracket is `(θ̂, θ̂ ± t·SE)` (`:517`), and `:556` returns `0.5*(a+b)`.
- **Suggested fix:** Profile against the same objective and weights the fit minimised (deviance for Poisson). For Cauchy, profile CIs are not applicable at all (see R1-S03-06). Never report a midpoint (R1-S03-02).
- **Related:** R1-S03-02, R1-S03-06

### R1-S03-02 · S1 · Profile-likelihood bound falls back to the bracket midpoint when Brent fails

- **Base:** ebcc622b32fc526c545aad8439e3e580d04b478c
- **Location:** `crates/fit/src/diagnostics.rs:541-557`
- **Category:** wrong-result
- **Defect:** `trace_profile_endpoint` maps every `brent_root` error (`bracket_sign`, `f(x)` non-finite because `profile_solve` returned `None` and the closure produced `NaN`, `NotConverged`) to `CiBound::Finite(0.5 * (a + b))`, a value that does not solve `SS(θ_k) = SS_crit`. This is the same pattern as the Koopman `unwrap_or(endpoint)` Known defect, applied to fitted-parameter CIs.
- **Failure scenario:** Any bracket where the re-solved profile at an endpoint disagrees in sign with the search pass. Examples: the model leaves its domain for the warm-started nuisance values inside the bracket (`solve_profile_subproblem` returns `None` at `solver.rs:2293`), or the profile solve converges to a different local minimum. The bracket comes from steps that grow by 1.8×–2.5× (`diagnostics.rs:530`), so it can be many SEs wide and the midpoint can sit far from the true bound. R1-S03-01 reaches this path on every Poisson or robust fit and gives a bound exactly half the correct width.
- **Evidence:** Code at `diagnostics.rs:554-557`: `Ok(r) if r.is_finite() => CiBound::Finite(r), _ => CiBound::Finite(0.5 * (a + b))`. `brent_root` returns `Err` on same-sign or non-finite endpoints (`math/src/roots.rs:45-56`, `:110-112`). Reproduced end to end through R1-S03-01, probe `p1`.
- **Suggested fix:** Return `CiBound::Open` (or a distinct "not computed" state plus a parameter note) when the root solve fails, as the guide prescribes for unresolved bounds.
- **Related:** R1-S03-01; Known defect `G8` Koopman (same pattern, different crate)

### R1-S03-03 · S1 · ROUT in the independent-curves (96-curve batch) path pools the residual scale across curves

- **Base:** ebcc622b32fc526c545aad8439e3e580d04b478c
- **Location:** `crates/fit/src/solver.rs:1750-1760`, `crates/fit/src/diagnostics.rs:1210-1214`
- **Category:** wrong-result
- **Defect:** With more than one dataset and no shared parameter, each curve is fitted separately (`fit_independent_datasets`). ROUT, however, concatenates all curves' Cauchy residuals and calls `rout_detect_outliers` once (`:1760`), so a single RSDR (`diagnostics.rs:1214`) is the scale for curves with completely different noise levels. The single-curve general path applies RSDR per fit.
- **Failure scenario:** Two straight-line curves. Curve A has noise ≈ 0.01 and one point 1.0 too high (about 100 SD). Curve B has noise ≈ 5. Fitted alone, A loses its outlier. Fitted together in one analysis, which is the typical plate layout, the pooled RSDR is 4.33, so A's outlier is not excluded and A's intercept is biased. Nothing in the result signals the problem. Excessive exclusions in the noisy curve are the mirror case.
- **Evidence:** Probe `p3`:
  ```
  quiet alone: outliers excluded 1 params [1.00285, 1.99958]
  quiet+noisy independent: outliers excluded 0 quiet params [1.10441, 1.99612] rsdr Some(4.327)
  ```
- **Suggested fix:** Run `rout_detect_outliers` per dataset with that dataset's residuals and `k_free`, and merge the audits. For shared-parameter global fits, a pooled scale remains appropriate.
- **Related:** none

### R1-S03-04 · S2 · Implicit-equation solver uses absolute tolerances and a fixed search range

- **Base:** ebcc622b32fc526c545aad8439e3e580d04b478c
- **Location:** `crates/fit/src/dsl.rs:443-483`
- **Category:** wrong-result
- **Defect:** `eval_implicit` returns a guess as the root when `|f(guess)| < 1e-13` (`:452`), and accepts a Newton iterate when `|f| < 1e-7` (`:482`). Both are absolute and independent of the problem's scale. Bracketing only covers consecutive pairs of the fixed guesses `[0, 1, -1, 10, -10, 100, 0.1, -0.1, 1e-4, 1000]` (`:446`), and the Newton fallback is clamped to ±100 per step for 40 steps (`:467-480`), so roots beyond about `[-3000, 5000]` are unreachable.
- **Failure scenario:** `Y = A*(X - Y)` (true `Y = A·X/(1+A)`), A = 1. At X = 5e-14 (molar-scale binding data) it returns `Y = 0`, a 100 % error, silently. At X = 12000 or 2e5 (CPM or fluorescence units) it returns `None`, so the fit fails with `BadInitialValues` on valid data.
- **Evidence:** Probe `p4`/`p11`: `X=5e-14: got Some(0.0) truth 2.5e-14`; `X=9000: got Some(4500)`; `X=12000: got None truth 6000`; `X=200000: got None truth 100000`.
- **Suggested fix:** Scale the tolerances by `|LHS|`/`|RHS|` magnitudes, and bracket by geometric expansion from the data or previous-root scale (for example the observed Y range) instead of a fixed guess list.
- **Related:** none

### R1-S03-05 · S2 · `hyp1f1` and `hyp2f1` return truncated partial sums as values

- **Base:** ebcc622b32fc526c545aad8439e3e580d04b478c
- **Location:** `crates/fit/src/dsl.rs:2382-2393`, `crates/fit/src/dsl.rs:2403-2414`
- **Category:** wrong-result
- **Defect:** When the 300-term (1F1) or 400-term (2F1) series has not met its tolerance, the function returns the partial sum (`if sum.is_finite() { Some(sum) }`) instead of `None`. This is a last-guess fallback.
- **Failure scenario:** `Y = hyp1f1(1, 1, X)` at X = 300 returns 1.00e130 against e^300 = 1.94e130 (−48 %). At X = 400 the error is −99.99999 %. `Y = hyp2f1(1, 1, 2, X)` at X = 0.999 returns 6.214 against 6.915 (−10 %). A fit that uses these functions gets wrong predictions with no signal.
- **Evidence:** Probe `p11` (references: e^z, and −ln(1−z)/z, which are the closed forms of these special cases).
- **Suggested fix:** Return `None` when the loop exits without convergence, or switch to asymptotic or transformation formulas for large |z| and |z| → 1.
- **Related:** S01 (special-function accuracy)

### R1-S03-06 · S2 · Robust (Cauchy) fits report SEs, CIs, bands and AICc/F comparisons that the guide says are not applicable

- **Base:** ebcc622b32fc526c545aad8439e3e580d04b478c
- **Location:** `crates/fit/src/solver.rs:1470`, `:1505`, `:1529-1535`, `:1558`, `:2046-2061`, `:2125-2157`; `docs/implementation/curve-fitting-implementation.md:38`
- **Category:** contract-drift
- **Defect:** The guide says pure Robust mode omits asymptotic SEs, CIs, covariance, confidence bands and F/AICc comparisons, reporting `NotApplicableInRobustMode`. No such marker exists anywhere in `crates/`. `FitMethod::RobustCauchy` flows through the same covariance, profile CI, band, information-criteria and `compare_models` code as least squares, using the Cauchy-reweighted SS as if it were a Gaussian SS.
- **Failure scenario:** Any robust fit shows a full "Std. Error / Confidence Interval" table, confidence bands, AICc and BIC. These are computed from `sigma² = Σ w_cauchy r² / df`, a quantity without a sampling interpretation, and the CIs are additionally wrong per R1-S03-01. A user comparing two robust models gets an F-test p-value.
- **Evidence:** `grep -rn NotApplicableInRobustMode crates` finds nothing. Probe `p1` RobustCauchy prints SE 3.66 for A and finite CIs.
- **Suggested fix:** For `RobustCauchy`, skip covariance, CIs, bands and comparisons, and mark them not applicable as documented (ROUT's second stage, which is ordinary least squares, is unaffected).
- **Related:** R1-S03-01

### R1-S03-07 · S2 · Batch (independent-curves) path accepts curves with fewer points than parameters and reports SE 0, R² 1, Sy.x 0

- **Base:** ebcc622b32fc526c545aad8439e3e580d04b478c
- **Location:** `crates/fit/src/solver.rs:1314-1317`, `:1640-1652`, `:1891`, `:2036-2043`; `crates/fit/src/diagnostics.rs:168`, `:189-190`
- **Category:** wrong-result
- **Defect:** `fit_nonlinear` checks only the total points against the total `k_free` (`:1315`). `solve_single_dataset_unit` has no per-curve check and uses `df_d = n_d.saturating_sub(p_d)` (`:1652`). The same 3-point curve fitted alone gets `InsufficientData`; in a batch it is "fitted". Separately, `compute_covariance_diagnostics` sets `sigma2 = 0` when `df == 0` (`diagnostics.rs:168`), so every SE is reported as the finite number `0`, not undefined. This affects the general path whenever n == k too.
- **Failure scenario:** 4PL batch with curve A (12 points) and curve B (3 points). B's parameters print with `Std. Error 0.0000`, R² = 1 and Sy.x = 0. The global df is reported as 7, counting B's −1. Only the overall `Ambiguous` status hints at a problem. In a 96-well batch, one well with missing points silently gets a "perfect" curve.
- **Evidence:** Probe `p8`: `short alone: Err(InsufficientData { required: 4, actual: 3 })`; batch: `status Ambiguous df 7`, `HillSlope dsSome(1) est 1.1892 se 0.0000 ci Open Open`, `ds1 sy_x 0 r2 1`.
- **Suggested fix:** Apply the `n_d >= p_d` check per curve (fail that curve or mark it explicitly), and report SE as NaN or not-computed when `df == 0`.
- **Related:** none

### R1-S03-08 · S2 · `Y0 = expr` in a non-ODE equation is silently discarded and `Y0` becomes a fitted parameter

- **Base:** ebcc622b32fc526c545aad8439e3e580d04b478c
- **Location:** `crates/fit/src/dsl.rs:810-812`, `:917-922`, `:390-392`, `:406-415`
- **Category:** wrong-result
- **Defect:** `parse_statement` classifies any line whose LHS is `Y0` or `Y(0)` (and `Y(<number>)`) as `OdeInitial` regardless of equation kind. For explicit or implicit equations the init statements are never compiled into the body, but their RHS identifiers are still collected as parameters. The user's local definition is dropped, and `Y0` in the body becomes a free parameter.
- **Failure scenario:** `Y0 = 5` then `Y = Y0*exp(-K*X)`: parameters become `["Y0", "K"]`. With `Y0 = 1, K = 0` the model evaluates to 1, not the intended 5, so the fit estimates an extra parameter instead of using the constant. A relation such as `Y0 = Bottom + Span` is likewise lost. No compile error or warning is raised.
- **Evidence:** Probe `p9`: `Y0-local: kind Explicit params ["Y0", "K"]`, `eval at X=1, K=0 (intended 5): Some(1.0)`.
- **Suggested fix:** Treat `Y0`/`Y(t0)` as initial conditions only when the equation has an ODE derivative line; otherwise parse it as an ordinary local assignment, or reject it with a compile error.
- **Related:** none

### R1-S03-09 · S2 · DSL compile cost grows quadratically with source size, with no total cap

- **Base:** ebcc622b32fc526c545aad8439e3e580d04b478c
- **Location:** `crates/fit/src/dsl.rs:1215-1221` (`[Transforms]`), `:1188-1203` (`[InitialValues]`), `:1042-1057` and `:1083-1094` (branches per dataset class), `:977-1010` (signature per mentioned dataset), `:755-781` (per-line cap only), `:439-441` (runtime `rfind` + `Vec::contains`)
- **Category:** resources
- **Defect:** Each `[Transforms]` and `[InitialValues]` line recompiles all prior lines as locals, giving O(L²) bytecode. Each output branch clones and recompiles the active locals. `MAX_DATASET_EXPANSION` (10 000) is enforced per line, so L dataset-prefixed lines create L classes over up to 10 000·L indices. Compilation does O(L²·10⁴) `contains` scans plus `mentioned × L/64` u64 signature words, and every model evaluation then scans up to L programs × 10⁴ indices. Nothing caps total source length, line count or bytecode size, and the equation text arrives from untrusted project files (`NonlinearFitSpec::custom_dsl` → `result.rs:275`) and MCP requests.
- **Failure scenario:** A 39 KB equation with 4000 `[Transforms]` lines compiles in 1.5 s, quadrupling per doubling: about 400 KB would take minutes, with bytecode ≈ L² × 16 B in the GB range, which aborts on wasm. A 5 KB equation with 200 lines `<i*10000:i*10000+9999> Y = A*X` compiles in 0.72 s, and each `eval` costs 0.37 ms instead of microseconds. At 1000 such lines (≈25 KB) the signature table alone is ≈ 1.3 GB.
- **Evidence:** Probe `p5`: `n=1000 compile 113 ms; n=2000 394 ms; n=4000 1.54 s`; `size_of OpCode = 16`. Probe `p6`: `lines=50 compile 132 ms, 1000 evals 52 ms; 100 → 296 ms / 120 ms; 200 → 724 ms / 369 ms`. The GB figures are extrapolated from these measurements and the allocation sizes in the code; they were not run.
- **Suggested fix:** Cap total source bytes, lines and emitted opcodes. Compile shared locals once (store them in slots shared across transforms and branches). Cap total dataset indices across all prefixes, and use a sorted or bitset lookup for `DatasetFilter::matches`.
- **Related:** Known defect `G9` (separate: AST depth); X1 if the cap belongs at the engine or MCP boundary

### R1-S03-10 · S3 · ODE models re-integrate from `t0` per point with a per-evaluation step ceiling and no overall budget

- **Base:** ebcc622b32fc526c545aad8439e3e580d04b478c
- **Location:** `crates/fit/src/dsl.rs:486-505`, `:24`, `:655-709`; `crates/fit/src/solver.rs:1126-1133`, `:1145-1157`
- **Category:** resources
- **Defect:** Every `eval(x)` integrates from `ode_t0` to `x` from scratch (O(N·X_max) per residual vector rather than one sweep), allowing up to 50 000 RK45 steps each time. Points that exhaust the ceiling cost ~30 ms each and return `None`, after which the Nelder–Mead rescue and restarts repeat full residual evaluations. Nothing bounds total work per fit.
- **Failure scenario:** `Y0 = A; dY/dX = -K*(Y - sin(X))`, X = 1..50, initial K = 2000 (moderately stiff). Points X ≥ 44 exceed the ceiling. `fit_nonlinear` blocks for 154 s, then returns `BadInitialValues`; the run with default config (profile CIs on) took 150 s. On the single-threaded wasm host this freezes the UI.
- **Evidence:** Probes `p10`/`p12`: `K=2000 failing X: [44..50] total 809 ms` for one residual vector; `fit (no profile/hougaard/bands): Err(BadInitialValues …) in 154.4 s`; `fit (defaults): … in 150.1 s`.
- **Suggested fix:** Integrate once over the sorted X values per dataset per parameter vector (cache by θ), and add a total work or time budget per fit that returns a structured error.
- **Related:** none

### R1-S03-11 · S3 · References to non-existent predictors (`X2`, `X3`, …) silently evaluate to 0

- **Base:** ebcc622b32fc526c545aad8439e3e580d04b478c
- **Location:** `crates/fit/src/dsl.rs:1825-1832`, `:1923-1925`

### R1-S03-12 · S3 · Interpolated unknowns extrapolate up to 50 % of the X span without a flag; documented out-of-range flags do not exist

- **Base:** ebcc622b32fc526c545aad8439e3e580d04b478c

## Checked, no finding

- **Weighting with zero, negative or non-finite Y, X or SD:** every scheme rejects zero or non-finite denominators with `ImpossibleWeights`. Negative Y is handled through `abs`. `GeneralPowerY` checks the computed denominator, and the final weight is checked for finiteness (`solver.rs:414-470`). Poisson rejects Y < 0 (`solver.rs:2168-2172`).
- **Profile that never crosses `SS_crit`:** returns `CiBound::Open` on a flat plateau (`diagnostics.rs:520-523`), on reaching a box limit (`:487-499`, `:524-526`), and after 24 expansions without a bracket (`:534-536`). The defects are only in the post-bracket root solve (R1-S03-01/02).
- **Non-convergence reporting:** `HitMaxIters` is set when the LM iteration cap is reached (`solver.rs:903`) and propagated (`:1587`, batch `:1870-1876`), but it is shown only as a footnote string (`result.rs:392-395`). Two cases return the last iterate with status `Converged` and no flag: the IRLS loops' fixed caps (Poisson 12 at `:2178`, Cauchy 15 at `:2217`), and LM inner-loop exhaustion (`:891-893`). In probe `p7` the Cauchy point was within 9e-7 relative of the true fixed point, which is immaterial. I could not build a concrete input where either cap matters, so neither is reported.
- **Parser and AST recursion (beyond Known defect `G9`):** depth limits for parentheses and calls (`dsl.rs:1397-1407`), `^` chains (`:1484-1490`) and unary chains (`:1523-1529`). All AST walkers are iterative: `Drop` (`:108-152`), `canonicalize_init_expr` (`:1134`), `expr_references_y` (`:1226`), `collect_free_idents` (`:1271`), and `compile_expr` (`:1742`). The remaining recursion hazard is the derived `Clone` used at `:1020-1025` and `:1050`, which is already the `G9` Known defect.
- **Bytecode jump targets and VM safety:** targets are back-patched to in-range or end indices (`dsl.rs:1764-1765`, `:1774`, `:1782`, `:1794`, `:1800`). The VM bounds `ip < len` (`:1916`), caps steps at 100 000 (`:1918`), uses `?` on every pop and `locals.get` (`:1928-1932`), and checks `CallBuiltin` arity against the stack (`:1972-1976`; the compile-time arity check is at `:1726`). `OpCode` is public but `CompiledProgram` is private and not deserialisable, so no untrusted bytecode can enter.
- **Dataset prefixes:** per-line range expansion uses `checked_sub`/`checked_add` and is capped (`dsl.rs:761-769`). All slicing is on ASCII delimiters (`:751-752`). `parse_ds_token` is ASCII-only (`:786-797`). The total across lines is not capped; see R1-S03-09.
- **ODE integration termination:** 50 000-step cap (`dsl.rs:655`), positive `min_h` (`:620-623`), non-finite stage and error handling (`:672-690`), and a stalled-time guard (`:693-694`). The integration always terminates; its cost is R1-S03-10.
- **Bessel order:** capped at 100 000 and checked finite before the `as i32` cast (`dsl.rs:2116-2125`).
- **Panics in the solver on untrusted shapes:** the `n_datasets - 1` underflow (`solver.rs:353`) is unreachable because empty inputs are rejected (`:1287-1289`, `:1298-1300`). `n_obs - k_free` (`:1504`) is guarded by `:1315` and `:1481`. Per-slot indexing in the batch merge is consistent because the per-dataset layout comes from `rules_for_dataset` (`:374-388`, `:1826-1847`).
- **96-curve fast path versus the general solver:** the batch path is `fit_independent_datasets`. Apart from R1-S03-03 and R1-S03-07, its parameter mapping, initial guesses, CI choice and status aggregation match fitting each curve alone. Least-squares profile CIs in probe `p1` were within 0.96–1.05 of the Wald half-widths, which is plausible for this mildly nonlinear model.

### Verdict R1-S03-01 · CONFIRMED
- **Evidence:** Test `r1_s03_01_poisson_profile_ci_matches_wald_scale` fails: `Poisson profile/Wald half-width ratios 0.5000 0.5000 (expected ~1)`; the least-squares control in the same test passes (ratio in 0.8..1.25).
