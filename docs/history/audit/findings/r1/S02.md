### R1-S02-01 · S1 · Contingency counts near `u64` range hang the 2×2 path and panic the R×C path

- **Base:** ebcc622b32fc526c545aad8439e3e580d04b478c
- **Location:** `crates/stats/src/categorical.rs:186` (and `:792`, `:805`, `:628`–`:650`); counts admitted by `crates/doc/src/archetypes.rs:516` (S05)
- **Category:** no-panic
- **Defect:** Count magnitudes are unbounded. `analyze_contingency` sums counts in `u64` with no overflow check, then sizes an allocation from a column sum. For every 2×2 table, whatever method was chosen, it also runs a Fisher loop (and a McNemar loop) whose iteration count equals the cell count.
- **Failure scenario:**
  1. A 2×2 table with cells of `1e12` (an untrusted project file or a paste) makes `analyze_contingency` (`:834`–`:835`) call `fisher_exact_2x2`. Its loop `for x in lo..=hi` (`:186`) runs about 1e12 times with four `ln_factorial` calls each. At the measured ~64 ns per iteration that is about 18 hours, so the session hangs. `mcnemar_test` (`:792`) and, when odds ratios are requested, `noncentral_hypergeom_p` (`:898`, `Vec::with_capacity(hi - lo + 1)`) have the same scaling. The last one aborts on allocation.
  2. A 3×2 table with cells `[[2^63, 2^63], [0, 5], [0, 0]]` passes `count_at` (`v <= u64::MAX as f64`). In release builds `total_count` wraps to 5 (`:805`). That passes the `<= 20_000` gate (`:836`), so `fisher_exact_rxc` calls `col_pool.resize(len + 2^63, …)` (`:650`), which panics with `capacity overflow`. Debug builds panic earlier on the overflowing `sum()`. On `wasm32`, `cnt as usize` also truncates.
- **Evidence:** Probe: `fisher_exact_2x2(1e6,…)` took 62.7 ms and `(1e7,…)` took 643.9 ms, which scales linearly. `run_analysis` on the 3×2 table above under `catch_unwind` gave `Err(Some("capacity overflow"))`.
- **Suggested fix:** Cap the total count, for example at the `fisher_exact_rxc` permutation limit, and above it skip or approximate the exact tests. Compute all sums with `checked_add` and return `InvalidParameter` on overflow.
- **Related:** S05 (`count_at` accepts values up to 2^64), X1

### R1-S02-02 · S1 · "Fisher's exact", "McNemar's" and "Cochran–Armitage" rows silently show the Pearson chi-square P

- **Base:** ebcc622b32fc526c545aad8439e3e580d04b478c
- **Location:** `crates/stats/src/categorical.rs:1370`, `:1376`, `:1378` (gates at `:834`–`:854`)
- **Category:** wrong-result
- **Defect:** When the requested test is not computed, the primary P falls back to `res.chi_square_p` through `unwrap_or`, and the row label stays the requested test's name. This happens for Fisher when rows or columns exceed 6 or the total exceeds 20,000, for McNemar on any table that is not 2×2, and for Cochran–Armitage when neither dimension is 2.
- **Failure scenario:** On a 7×2 table, choosing `FisherExact` gives a row labelled "Fisher's exact test" with P = 0.2381, which is the asymptotic chi-square P. That is exactly the case (sparse, expected counts < 1) where the user chose an exact test. `McNemarPaired` or `CochranArmitageTrend` on a 3×3 table reports P = 0.0008 under those names. That value is again the chi-square P, so a test that cannot be defined for this table gets a value that looks significant. The df column shows the chi-square df (4) in both cases.
- **Evidence:** Probe `fisherfallback`: the row `"Fisher's exact test"` has `PValue { raw: 0.23810330555354423 }`, and the scalar `Chi-square P value = 0.23810330555354423`. `McNemarPaired 3x3` and `CochranArmitageTrend 3x3` both show `raw: 0.0008251774515685003` with df 4.
- **Suggested fix:** Return `IncompatibleTable`/`InvalidParameter` when McNemar or the trend test does not apply. For Fisher beyond the exact cap, either run the Monte Carlo path with the label "Monte Carlo" or return an error. Never substitute the chi-square P.
- **Related:** Same pattern as the Koopman Known defect, but a different function

### R1-S02-03 · S1 · ROC: perfectly separated groups report P = 1 and a zero-width CI for AUC = 1

- **Base:** ebcc622b32fc526c545aad8439e3e580d04b478c
- **Location:** `crates/stats/src/roc.rs:154`–`:170`
- **Category:** wrong-result
- **Defect:** Under complete separation, every DeLong structural component equals AUC = 1. `s10` and `s01` are then 0, and Hanley–McNeil's numerator is also 0. The code turns SE = 0 into `p_value_vs_05 = 1.0` and CI = `[1, 1]`.
- **Failure scenario:** With controls {1,2,3,4,5} and cases {6,…,10}, a perfectly discriminating biomarker is reported as AUC = 1, CI 1.000–1.000, "P value (vs. 0.5) = 1.0000 ns". The exact Mann–Whitney P for the same data, which tests the same hypothesis, is 0.0079. Separated biomarker data is common, so this is not a corner case.
- **Evidence:** Probe `roc`: `ROC delong auc=1 se=0 ci=(1.0, 1.0) p=1`, `ROC HM auc=1 se=0 … p=1`, `MW same data two-tailed p=0.007936507936507936`.
- **Suggested fix:** When `se == 0`, compute P from the Mann–Whitney U distribution (AUC = U/(n0·n1)), or report P as not computable, and use a CI method that does not collapse at the boundary.
- **Related:** R1-S02-07 (same `se == 0 → P = 1` pattern)

### R1-S02-04 · S1 · Dunn's test after Kruskal–Wallis, and "Dunn" after ordinary ANOVA, report unadjusted P as "Adjusted P"

- **Base:** ebcc622b32fc526c545aad8439e3e580d04b478c
- **Location:** `crates/stats/src/multiplicity.rs:772`–`:776` and `:287`–`:297`; `crates/stats/src/multiplicity.rs:338`/`:355`–`:360`; reached from `crates/stats/src/anova.rs:1719` and `:1989`
- **Category:** wrong-result
- **Defect:** `adjust_p_values` falls through `_ =>` and returns the raw P unchanged for every procedure it does not implement. `compare_dunn_ranks` remaps only `DunnRankSum`/`None` to Bonferroni. With Tukey, Dunnett, Newman–Keuls, Fisher LSD or Games–Howell selected, Dunn's P-values are therefore left unadjusted. In the other direction, `DunnRankSum` on a parametric ANOVA reaches `compare_pooled_or_fdr` and is also left unadjusted. The engine accepts any method with any test (`crates/engine/src/cmd_sci.rs:938`).
- **Failure scenario:** Kruskal–Wallis on 4 groups with multiplicity "tukey" produces the tab "Dunn's multiple comparisons" with C0 vs C1 adjusted P = 0.0422, flagged significant. Bonferroni over 6 comparisons gives 0.253. Ordinary ANOVA with "dunn" shows "Adjusted P" equal to the raw pooled-*t* P for all 6 pairs.
- **Evidence:** Probe `kwtukey`: `C0 vs. C1: raw=0.042236… adj=0.042236…`, and the same raw = adj for every row of both runs.
- **Suggested fix:** Make `adjust_p_values` exhaustive and return an error for procedures that cannot apply to raw P-values. Reject method and test combinations that do not fit (for example rank-based Dunn after a parametric ANOVA), or map them explicitly with a footnote.
- **Related:** S07 (engine accepts the combination)

### R1-S02-05 · S1 · Cox PH: a singular information matrix ships SE = 1000, or SE = 1 from an identity fallback, and non-convergence is never reported

- **Base:** ebcc622b32fc526c545aad8439e3e580d04b478c
- **Location:** `crates/stats/src/survival.rs:508`–`:521` (fallback), `:465`–`:506` (`converged`), `:1134`–`:1184` (result sheet)
- **Category:** wrong-result
- **Defect:** When Cholesky fails on the information matrix, the covariance becomes the inverse of `info + 1e-6·I`, and if that also fails, `DenseMatrix::identity`. The SE reported for a covariate is then a damping artifact: 1/√1e-6 = 1000, or 1. `CoxPhResult::converged` and `iterations` are never written to the `ResultSheet`, so the user gets no signal.
- **Failure scenario:** Monotone likelihood: every subject with x = 1 has its event before every subject with x = 0 (times 1–5 against 6–10). The result shows β = 39.26, SE = 1000.0, HR = 1.1e17, Wald P = 0.9687 "ns", while the likelihood-ratio P is 0.0009. The Schoenfeld check is marked "Pass". `converged` came back `true`. Collinear predictors take the same damping path.
- **Evidence:** Probe `cox`: `converged=true iters=39 beta=39.26… se=1000 hr=1.125e17 ci=(0.0, inf) p=0.9687 LR p=0.00088`. The `cox-ph` tab row shows `Number { value: 1000.0 }` for SE, and the checklist only has `"Proportional hazards assumption (Schoenfeld)" Pass`.
- **Suggested fix:** If the information matrix is not positive definite at the solution, report SE/CI as not estimable (or `CiBound::Open`) and add a checklist warning about separation or collinearity. Drop the identity fallback. Surface `converged`/`iterations` and warn when the fit did not converge.
- **Related:** none

### R1-S02-06 · S1 · One-tailed Mann–Whitney and Wilcoxon P-values ignore the direction of the effect and contradict the one-tailed *t* tests

- **Base:** ebcc622b32fc526c545aad8439e3e580d04b478c
- **Location:** `crates/stats/src/two_group.rs:501`–`:508`, `:546`–`:548`, `:684`–`:689`; `crates/stats/src/column.rs:1220`–`:1226`, `:1256`–`:1264`
- **Category:** wrong-result
- **Defect:** With `two_tailed = false`, every rank test returns the upper-tail P(U ≥ u_a) or P(W⁺ ≥ w). `TwoGroupSpec` has no direction field. The *t* tests use the observed direction (`t_tail_p`, `two_group.rs:161`–`:169`; `column.rs:1103`–`:1109`), so a one-tailed P is half the two-tailed one. The rank tests return about 1 − P/2 whenever group A is smaller.
- **Failure scenario:** A = {1..5}, B = {6,7,8,9,10.5}, one-tailed. The unpaired *t* test gives P = 0.00064, while Mann–Whitney gives P = 1.000. The paired *t* test gives P < 1e-6, while Wilcoxon matched pairs gives P = 0.988. The one-sample *t* test against 10 gives P = 0.00029, while the one-sample Wilcoxon gives P = 1.000. Large samples that use the normal approximation behave the same way (P = 0.99990).
- **Evidence:** Probe `tails`: `two_tailed=false: unpaired t p=0.000643 MW p=1.000000 | paired t p=0.000000 Wilcoxon p=0.988174 | one-sample t p=0.000292 one-sample W p=1.000000`, and `approx MW two_tailed=false p=0.999896`.
- **Suggested fix:** Use the tail in the observed direction, as `t_tail_p` does: the lower tail when u_a or W⁺ is below its mean. Alternatively, add an explicit direction to `TwoGroupSpec` and apply it to every test.
- **Related:** none

### R1-S02-07 · S2 · Zero residual variance gives F = 0, P = 1 in RM ANOVA, and P = 1 for every post-hoc pair after an F test with P < 0.0001

- **Base:** ebcc622b32fc526c545aad8439e3e580d04b478c
- **Location:** `crates/stats/src/anova.rs:649`–`:652`; `crates/stats/src/multiplicity.rs:371`–`:377`, `:422`–`:428`, `:468`–`:474`, `:547`–`:556` (also `anova.rs:1560`, `:1566` nested)
- **Category:** wrong-result
- **Defect:** `rm_one_way_anova` sets `f_treat = 0` when `msr == 0`. Every pairwise engine maps `se == 0` to statistic 0 and P = 1. Ordinary one-way ANOVA handles the same case as F = ∞, P = 0 (`anova.rs:396`–`:403`), so the omnibus test and its post-hoc tests contradict each other.
- **Failure scenario:**
  1. Perfectly additive repeated measures, rows `[1,2,3]`, `[4,5,6]`, `[10,11,12]`, `[2,3,4]`, give RM ANOVA F = 0, P = 1 (G-G P = 1). Friedman on the same blocks gives P = 0.018.
  2. Ordinary ANOVA on {1,1,1}, {2,2,2}, {3,3,3} reports P < 0.0001 "****", while Tukey reports every pair as P = 1.0000 "ns" with zero-width CIs. Integer-valued or rounded data hits these cases.
- **Evidence:** Probe `rm`: `RM additive: F=0 p=1 pGG=1`, `Friedman same: Q=8 p=0.0183`. Probe `zeromse`: the ANOVA row shows `PValue { raw: 0.0, formatted: "< 0.0001" }`, and the comparison rows show `PValue { raw: 1.0 … "ns" }` and `ConfidenceInterval { Finite(-1.0), Finite(-1.0) }`.
- **Suggested fix:** Treat zero residual variance consistently. Either return `StatsError::ZeroVariance`, as the *t* tests do, or report an infinite statistic with P = 0, never P = 1.
- **Related:** R1-S02-03

### R1-S02-12 · S3 · Mann–Whitney does not match its documented exactness: ties always use the normal approximation, and large-sample "Hodges–Lehmann" is a difference of medians

- **Base:** ebcc622b32fc526c545aad8439e3e580d04b478c
- **Location:** `crates/stats/src/two_group.rs:537`, `:582`–`:588`; `crates/stats/src/column.rs:1274`–`:1278`; `docs/implementation/statistics-implementation.md:90`
- **Category:** contract-drift
- **Defect:**
  - The guide promises exact tie permutation and an exact Hodges–Lehmann estimate. The code drops to the normal approximation on any tie (`ranked.tie_counts.is_empty()`).
  - When n_a·n_b > 40,000, the code returns `median(a) − median(b)` labelled "Hodges-Lehmann median diff." with no CI.
  - The one-sample pseudomedian becomes the sample median when n > 2000.
- **Failure scenario:** For a = {i²}, i < 201, and b = {3i}, i < 200, the code reports HL = 9701.5. The true median of pairwise differences is 9702.5. Small tied samples (for example 5 vs 5 with one tie) get an asymptotic P although the guide says they get an exact one.
- **Evidence:** Probe `hl`: `HL n=201x200: reported=9701.5 ci=None true median of pairwise diffs=9702.5`.
- **Suggested fix:** Either implement the bounded exact tie distribution and an O(n log n) Hodges–Lehmann selection (Monahan's algorithm), or correct the guide and label the approximations in the result tab.
- **Related:** none

## Checked, no finding

- **Unpaired, Welch, paired, ratio and lognormal *t* formulas and df.**
  - Pooled df is n₁ + n₂ − 2 and Welch–Satterthwaite df is computed correctly (`two_group.rs:233`, `:297`–`:298`).
  - The paired test uses n − 1 df on the differences (`:388`). Zero variance returns `ZeroVariance` (`:235`, `:293`, `:384`), and n < 2 is rejected (`:223`–`:228`).
- **Excluded cells.**
  - Every extractor goes through `Cell::active_number`, which returns `None` for excluded cells (`crates/doc/src/cell.rs:94`–`:96`).
  - Paired extraction is complete-case by row (`common.rs:284`–`:289`).
- **Mann–Whitney.**
  - The tie-corrected variance (n₁n₂/12)(N + 1 − Σ(t³ − t)/(N(N − 1))) is correct (`two_group.rs:542`). The exact DP is only used without ties (`:537`).
  - The two-sample KS exact path is only used without cross ties (`:733`).
- **Kruskal–Wallis and Friedman.**
  - KW: H, the tie divisor 1 − Σ(t³ − t)/(N³ − N), and df k − 1 are correct (`anova.rs:790`–`:794`).
  - Friedman: the tie-corrected denominator and Kendall's W are correct (`:827`–`:832`).
  - Dunn's SE uses the global tie correction (`multiplicity.rs:750`).
- **Ordinary one-way ANOVA.**
  - Two-pass grand mean; df k − 1 and N − k (`anova.rs:373`–`:392`).
  - Residual df = 0 is rejected (`:367`–`:369`). All-blank or empty groups return `EmptyInput` through `validate_finite_slice` rather than being dropped silently.
- **FDR procedures.**
  - BH and BY step-up are monotone and never fall below the raw P (`multiplicity.rs:233`–`:250`).
  - BKY two-stage gives discoveries at q ⇔ rejections at q/(1 + q)·m/m̂₀ (`:255`–`:282`).
  - The Holm step-down keeps a running maximum (`:200`–`:217`).
- **Kaplan–Meier.**
  - Greenwood, log-log CIs (`survival.rs:160`–`:216`) and the Brookmeyer–Crowley median CI (`:238`–`:242`) are correct.
  - Log-rank and Gehan hypergeometric variance are correct (`:379`–`:391`). Reduced-rank Cholesky has a least-squares fallback (`:271`–`:277`).
- **Exact binomial median CI.** The coverage is 1 − 2·P(Bin(n, ½) ≤ r), and the achieved level is reported (`column.rs:37`–`:77`).
