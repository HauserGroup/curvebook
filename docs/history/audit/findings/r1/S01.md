### R1-S01-01 · S1 · Noncentral *t* large-δ branch uses `E[U]·df/2` as the mean, so CDF/SF and Cohen's *d* CIs are wrong for |δ| > 447

- **Base:** ebcc622b32fc526c545aad8439e3e580d04b478c
- **Location:** `crates/math/src/dist/noncentral.rs:99` (branch), `:103`–`:106` (formula); reached from `noncentral_t_ci` via `solve_nct_delta` `:281`–`:303`
- **Category:** wrong-result
- **Defect:** When `0.5·δ² > 1e5` the normal approximation computes `c_df = sqrt(2/df)·Γ((df+1)/2)/Γ(df/2)` (which already is `E[U]`) and then sets `eu = c_df * (0.5 * df)`, inflating the mean of `U` by `df/2` and forcing `var_u` to 0, so the returned probability is essentially 0 or 1.
- **Failure scenario:** `nct_cdf(512.6, 10, 500)` returns `1.0` (`nct_sf` returns `0.0`); Monte Carlo gives `0.4838`. `nct_cdf(450, 10, 448)` returns `1.0`; Monte Carlo `0.448`. Because `solve_nct_delta` brackets out to `t_obs ± span` (`:285`–`:302`), any CI whose bracket crosses |δ| ≈ 447 lands in this branch: `noncentral_t_ci(300, 10, 95)` returns `(1461.07, 1464.99)` and `noncentral_t_ci(400, 100, 95)` returns `(19948.1, 19952.0)`, intervals that do not even contain the observed `t`. Below the threshold the same function is correct (`noncentral_t_ci(250, 10, 95) = (142.44, 357.81)`, confirmed by Monte Carlo at 0.0250 per tail). Callers (`stats/src/two_group.rs:190`, `:204`, `:209`, `:414`; `stats/src/column.rs:1117`) turn these into Cohen's *d*, Hedges' *g*, Glass's Δ and *d_z*/*g_z* CIs and show them without any warning. A two-group comparison with *t* ≈ 300 on 10 df (low-noise assay replicates, CV ≈ 0.1 %) is enough.
- **Evidence:**
  ```rust
  let c_df = (0.5 * df).sqrt() * (ln_gamma(0.5 * (df + 1.0))? - ln_gamma(0.5 * df)?).exp() / (0.5 * df);
  let eu = c_df * (0.5 * df);
  let var_u = (1.0 - eu * eu).max(0.0);
  ```
  For df = 10, `c_df` = 0.9754 = E[U] and `eu` = 4.877, so `var_u` = 0 and `z_eff = (t·4.877 − δ)`. Probe output: `nct_cdf(t=512.6, df=10, delta=500) = Ok(1.0)`; `noncentral_t_ci(t=275, df=10) = Ok((1339.15, 1343.07))`, `(t=300, df=10) = Ok((1461.07, 1464.99))`. R Monte Carlo (seed 1, N = 4e6): `512.6 500 0.483812`, `450 448 0.448037`, `460 448 0.486477`, `600,30,600 0.4658795`.
- **Suggested fix:** Use `eu = c_df` and `var_u = 1 − eu²`, or drop the normal approximation and evaluate `P(T ≤ t) = ∫ φ(z) · P(U ≥ (z + δ)/t) dz` with `chi2_sf`, which is exact for any δ. Add a regression test with δ > 447 against a Monte Carlo or analytic bound.
- **Related:** S02 (effect-size CIs in `two_group.rs`, `column.rs`).

### R1-S01-02 · S2 · Noncentral F and χ² cap the Poisson mode at 500 000, so λ > 1e6 gives CDF = SF = 0 and a truncated upper CI limit

- **Base:** ebcc622b32fc526c545aad8439e3e580d04b478c
- **Location:** `crates/math/src/dist/noncentral.rs:362` (`ncf_eval`), `:477` (`ncchi2_eval`); forward-sum truncation `:375`–`:385`, `:489`–`:499`; CI solve `:427`–`:431`, `:549`–`:560`
- **Category:** wrong-result
- **Defect:** `k0 = (lam_half.floor() as usize).min(500_000)` starts the Poisson-weighted sum at a fixed index far from the true mode once λ/2 > 500 000; `p_k0` then underflows to 0, both directions sum to 0, and the function returns `Ok(0.0)` for both the CDF and the survival function instead of an error. Separately, the forward loop stops after `MAX_POISSON_TERMS = 4096` terms without reporting truncation.
- **Failure scenario:** `ncf_cdf(6e5, 1, 10, 1.5e6)` and `ncf_sf(6e5, 1, 10, 1.5e6)` both return `0.0` (R: 0.005346 / 0.994654). Just above the cap, `λ = 1.01e6` gives cdf 0.00805 + sf 0.0937 (R: 0.0781 / 0.9219). In `noncentral_f_ci`, the upper-limit solve brackets across the cap, sees a false sign change, and converges to the cap: `noncentral_f_ci(6e5, 1, 10, 95)` returns upper `1 008 874.8`, while the true root is `≈ 1 229 002` (R `uniroot` on `pf`; analytic check `f·χ²₁₀,0.975/10 = 1.228991e6`). The lower limit `194 812.6` matches R. `stats/src/anova.rs:243` converts this into partial η² and Cohen's *f* CIs. The Cohen's *f* upper limit `sqrt(hi/N)` is about 10 % too low and nothing is flagged. Any ANOVA with `F·df_effect` between about 5e5 and 1e6 on a small error df hits this; above that the lower solve fails and the CI is silently dropped. The 4096-term cap also loses up to ~3e-9 of mass near the cap (probe: cdf + sf = 0.99999999658 at λ = 9.9e5).
- **Evidence:** Probe output: `lam=1.5e6 ncf_cdf=Ok(0.0) ncf_sf=Ok(0.0)`; `lam=1.5e6 ncchi2_cdf=Ok(0.0) ncchi2_sf=Ok(0.0)`; `noncentral_f_ci(6e5,1,10,95) = Ok((194812.61390033626, 1008874.7912273466))`. R 4.5.2: `pf(6e5,1,10,ncp=1.5e6)` = 0.005345997 (with a `pnbeta` precision warning; the analytic bound above agrees with R's root).
- **Suggested fix:** Return `MathError::NotConverged` (or use a normal/Wilson–Hilferty approximation in λ) when `lam_half` exceeds the cap, and report non-convergence when the forward loop exhausts `MAX_POISSON_TERMS` while `pk` is still above tolerance. Do not let `solve_positive_noncentrality` treat a capped evaluation as a sign change.
- **Related:** S02 (`anova.rs` effect-size CIs, `categorical.rs:861` Cramér's V CI).

### R1-S01-03 · S2 · `sym_eigen` declares convergence against an absolute threshold floored at 1.0, so small-scale matrices stop after one Jacobi sweep

- **Base:** ebcc622b32fc526c545aad8439e3e580d04b478c
- **Location:** `crates/math/src/linalg/cholesky.rs:151` (`scale = frobenius_norm().max(1.0)`), `:178` (convergence test); same floor in `cholesky` symmetry check `:31`
- **Category:** wrong-result
- **Defect:** The stopping rule `max_off <= 2·eps·max(‖A‖_F, 1)` is absolute for any matrix with ‖A‖_F < 1. When every entry is below ~4e-16, the first sweep already satisfies it, and the matrix returns after one cyclic sweep that has not converged.
- **Failure scenario:** The same 4×4 SPD matrix scaled by `s` returns eigenvalues/s `[4.865607, 2.519938, 1.706035, 0.908420]` for s = 1, 1e-8 and 1e-14, but `[4.862238, 2.523075, 1.706261, 0.908426]` for s = 1e-17 and 1e-20. A 6×6 Hilbert-like SPD matrix scaled by 1e-16 gives a product of eigenvalues (determinant) 4.187e-6 instead of 4.096e-6 (+2.2 %) and Greenhouse–Geisser ε 0.27514 instead of 0.27432. `stats/src/anova.rs:736` feeds the repeated-measures contrast covariance into `sym_eigen` for GG/HF ε and Mauchly's W. Data entered in SI units (for example nanomolar concentrations as `5e-8` M, SD ~1e-8) give covariance entries ~1e-16, so sphericity corrections and Mauchly's test change with the unit of measurement. Nothing signals this. The Cholesky symmetry check has the same floor: `[[2e-15, 1e-15], [0, 2e-15]]` (completely asymmetric) is accepted and silently symmetrized.
- **Evidence:**
  ```rust
  let scale = a.frobenius_norm().max(1.0);
  ...
  if max_off <= 2.0 * f64::EPSILON * scale {
  ```
  Probe output lines `scale=1e-17 eig/scale=[4.862238146584849, 2.523075375419938, ...]` vs `scale=1e0 eig/scale=[4.865606941813077, 2.5199376514323375, ...]`; `asym tiny chol ok? Ok(DenseMatrix { ... })`. The one-sided Jacobi SVD uses a relative cosine test (`svd.rs:102`) and does not have this problem.
- **Suggested fix:** Use the matrix's own scale (`frobenius_norm()`, returning early for the zero matrix) in both the convergence test and the Cholesky symmetry tolerance, or test `|a_pq| <= eps·sqrt(|a_pp·a_qq|)` per pair as the rotation skip already almost does (`:173`).
- **Related:** S02 (`anova.rs` sphericity, `multivariate.rs:1286`).

### R1-S01-04 · S3 · `cholesky` detects singularity only by `pivot <= 0`, so exactly collinear Gram matrices factor and invert to ~1e14

- **Base:** ebcc622b32fc526c545aad8439e3e580d04b478c
- **Location:** `crates/math/src/linalg/cholesky.rs:50`
- **Category:** wrong-result
- **Defect:** The positive-definiteness test is unscaled (`sum_val <= 0.0`), so a rank-deficient PSD matrix whose last pivot rounds to a tiny positive number is accepted. §1.3 asks for scaled rank checks, and the QR path has them (`qr.rs:104`).
- **Failure scenario:** For `X = [x, k·x]` with seven values and `k` in {0.3, 3, 7, 1/3, 0.7, 2.9, 13, 0.01}, 8 of 10 exactly singular `XᵀX` matrices factor (`L22` ≈ 1e-8…7e-7) and `inverse()` returns diagonals of 2e14–6e14; only k = 0.1 and 1.1 return `NotPositiveDefinite`. `qr_col_pivoted` reports rank 1 for all ten. Callers use `Err` from `cholesky` as their singularity signal (`stats/src/survival.rs:271` falls back to least squares; `regression.rs:529` and `survival.rs:509` choose other branches), so with collinear covariates they report the Ok branch's huge covariance and standard errors instead of taking the singular path.
- **Evidence:** Probe output `k=0.3: chol OK, L22=1.4901161193847656e-8, inv[0][0]=4.0532396646334456e14 / qr rank 1`; `8/10 exactly-collinear Gram matrices accepted by cholesky`.
- **Suggested fix:** Reject pivots below `n·eps·max_i a_ii` (or relative to the original diagonal entry) with `NotPositiveDefinite`, matching the QR rank threshold.
- **Related:** S02. Note for S02: when `cholesky` does fail, `regression.rs:529`–`532` and `survival.rs:517`–`520` substitute the identity matrix as the covariance, which reports SE = 1. That is outside this slice.

### R1-S01-05 · S3 · Inverse incomplete gamma/beta solvers return the bracket midpoint as `Ok` after the iteration budget

- **Base:** ebcc622b32fc526c545aad8439e3e580d04b478c
- **Location:** `crates/math/src/special/inc_gamma.rs:348`, `:387`, `:431`; `crates/math/src/special/inc_beta.rs:312`–`313`, `:376`–`:377`
- **Category:** wrong-result
- **Defect:** After 32/40/48 safeguarded Halley-or-bisection steps, every quantile solver returns `Ok(0.5 * (lo + hi))` whether or not the bracket has converged, instead of `MathError::NotConverged`.
- **Failure scenario:** `reg_gamma_q_inv(0.001, 0.05)` and `reg_gamma_q_inv(0.001, 0.3)` both return `x = 2.3306e-10`, where `Q(0.001, x) = e^-3.8457 = 0.0214`. The true roots are ≈1e-22 and ≈1e-131, unreachable by 32 halvings of `[0, 72]`. `reg_gamma_p_inv(0.001, 0.7)` returns the same `x` with `P = 0.979`. Equivalent to `chi2_isf(q, 0.002)`. No current caller passes shape < 0.05 (callers are `chart/multivariate_layout.rs:444` with df = 2 and the Clopper–Pearson calls `stats/categorical.rs:143`–`144` with shapes ≥ 1), so this is latent. Any future caller with small shape (gamma-distributed simulation, fractional-df χ² quantiles) gets a plausible non-root.
- **Evidence:** Probe round-trip grid: `BAD gq a=0.001 q=5e-2 x=2.3306347429752347e-10 lnq=-3.8456906385460567 target=-2.995732273553991`, same `x` for `q=3e-1`.
- **Suggested fix:** Return `NotConverged` when the loop ends without meeting the bracket or step tolerance; for tiny shapes, solve in `u = ln x` as the deep-tail branches already do.
- **Related:** none.

### R1-S01-06 · S3 · `reg_beta_inv_pair` derives the second component as `1 − x`, losing all precision when the quantile is near 1

- **Base:** ebcc622b32fc526c545aad8439e3e580d04b478c
- **Location:** `crates/math/src/special/inc_beta.rs:243`–`:248`, `:288`, `:292`, `:301`, `:308`, `:313`; consumer `crates/math/src/dist/core.rs:274`–`:275`
- **Category:** wrong-result
- **Defect:** The pair inverse picks the variable by the smaller *probability*, not the smaller *quantile*. When that branch solves for an `x` that rounds to 1, the returned `y = 1.0 − x` keeps only absolute precision ~1e-16, while the docs promise "full significand precision".
- **Failure scenario:** `reg_beta_inv_pair(1.0, 0.001, 0.3, 0.7)` returns `y = 1.11e-16`; the closed form `I_x(1, b) = 1 − (1 − x)^b` gives `y = 0.7^1000 = 1.25e-155`. `student_t_two_sided_isf(0.05, 5e11)` computes `t = sqrt(df·y/x)` from this tiny `y` and returns `1.9599701` instead of `1.9599640` (round-trip *p* 0.0499993, relative error 1.4e-5). At df = 1e9 the round-trip error is ~1e-8. Not reachable with today's sample-size caps (`doc::MAX_ROWS = 1_000_000`), so latent.
- **Evidence:** Probe round-trip grid lines `BAD beta a=1 b=0.001 p=3e-1 x=9.999999999999999e-1 y=1.1102230246251565e-16` and `BAD t df=500000000000 a=0.05 t=1.959970073122296 p=0.049999288309572884`.
- **Suggested fix:** Choose the solved variable by which of `x`/`y` is smaller (for example from the initial guess against `a/(a+b)`), or solve for `y` directly when `x > 0.5`. Alternatively, lower `HUGE_DF_NORMAL_CUTOFF` for the quantile path to ~1e7.
- **Related:** none.

### R1-S01-07 · S3 · `ColorRamp::Custom` copies and sorts every stop on every sample, and the stop count is unbounded

- **Base:** ebcc622b32fc526c545aad8439e3e580d04b478c
- **Location:** `crates/palette/src/colormap.rs:183`, `:209`–`:216`
- **Category:** resources
- **Defect:** `sample_custom_stops` allocates a filtered copy of `stops` and runs `sort_by` on it for each call. `ColorRamp` is deserialized from projects (`doc/src/graph.rs:373`, `Continuous { ramp: ColorRamp, .. }`) with no cap on `stops.len()`, and the chart samples once per point (`chart/src/multivariate_layout.rs:226`, `:1108`).

- **Suggested fix:** Validate and sort stops once (cap the count, for example at 256, at deserialization or in a `ColorRamp::new`), then binary-search per sample.
- **Related:** S05 (document caps), S08 (chart compiler).
