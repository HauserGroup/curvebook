Privacy policy · Effective 2026-11-18 · Updated 2026-11-23

Local by design.
Zero telemetry.

CurveBook runs locally on your computer or inside your browser tab. In every distribution, it collects no personal data, sends no telemetry or crash reports, makes no outbound network connections, and has no auto-updater.

This page is the full technical privacy disclosure. It covers on-device storage paths, local control ports, and hosting operators. For a quick overview of CurveBook, start with the home page or the FAQ.

  • Distributions covered: This policy covers the native desktop installers and archives (macOS, Windows, and Linux AppImage), the Tier 2 FreeBSD archive that contains only the command-line tool, and the Windows MSIX / Microsoft Store channel (JakobSture.CurveBook). It also covers the command-line tool and the Model Context Protocol server (curvebook-cli and curvebook-cli mcp), and the WebAssembly browser bundle (curvebook-web, which is deferred until CurveBook 1.0).
  • No personal or scientific data collection: CurveBook never collects, transmits, sells, or shares your name, contact details, identifiers, usage activity, or research datasets. CurveBook has no user accounts and no sign-in.
  • No telemetry or crash reporting: CurveBook contains no analytics libraries, usage beacons, or automatic crash-reporting agents.
  • No outbound network connections: CurveBook makes no internet or cloud requests. Automated repository checks (cargo xtask telemetry) reject HTTP client crates, telemetry SDKs, non-loopback network sockets, and external browser requests.
  • No built-in updater: CurveBook never checks for updates in the background. It is updated only when you install a new release yourself, or when you update it through the Microsoft Store or your operating system’s package manager.

On-device files and browser storage

What CurveBook stores locally

1. Data written on your device

  • Project, template, and exported files: CurveBook writes these files only to paths you explicitly choose when you save or export, and it writes them atomically. This applies to .curvebook archives, unpacked .curvebook.d/ directories, .cbtemplate templates, and exported figures or tables (.csv, .tsv, .svg, .pdf, .png, .tiff, .emf, .json). A saved project stores your data sheets, formulas, statistical results, graphs, layouts, notes, and named checkpoints. It also stores the local paths of any external CSV/TSV files you have explicitly linked to a table.
  • User preferences (preferences.json and shortcuts.json): These files store only your chosen interface language (locale), your visual theme (light, dark, or high-contrast), and any custom keyboard shortcut overrides (shortcuts). CurveBook writes preferences.json only when you change a preference from its default or when the file already exists.
  • Crash-recovery write-ahead journal (recovery/): This folder protects unsaved desktop edits if the process stops or the power fails unexpectedly. It holds snapshot.curvebook, an atomically written baseline of the workspace. It also holds ops.journal, an append-only write-ahead log of the workspace commands run since the last checkpoint. This log uses versioned (v2) newline-delimited JSON with CRC-32 checks; legacy v1 records are upgraded after CRC verification. A local writer lease, curvebook.lock, records the owning process or window ID, timestamps, the lease duration, and a non-secret identifier for the local OS, architecture, and hostname. CurveBook uses this identifier only on the same machine, to detect stale locks. Secondary windows and --new-instance runs use isolated win-<n> or instance-<pid>-... subdirectories. Closing a session after you save or discard it releases the lock cleanly and clears pending recovery entries.
  • Temporary loopback control token (control-<port>.token): CurveBook creates this file in the configuration folder (with mode 0600 on Unix) only while curvebook --control <port> is running. Local tools running under the same user account use it to authenticate, and CurveBook removes it automatically when that session exits.
  • Recent files: CurveBook does not keep a recent-files (MRU) history file on disk or in browser storage. Your operating system’s native file dialogs or desktop shell may keep their own list of recent items, governed by your operating system’s privacy settings.
  • Headless command-line runs (curvebook-cli): The one-shot CLI subcommands (info, convert, export, run, batch) and curvebook-cli mcp in its default headless mode read and write only the file paths you specify. They do not create preferences.json or background recovery/ folders.

2. Where each platform keeps local data

  • macOS: ~/Library/Application Support/CurveBook/ stores preferences.json, shortcuts.json, the temporary control-<port>.token file, and the recovery/ folder.
  • Windows (MSI installer and portable or standalone executable): %APPDATA%\CurveBook\ holds preferences.json, shortcuts.json, and the temporary control-<port>.token file. Crash-recovery files are stored in %LOCALAPPDATA%\CurveBook\recovery\.
  • Windows (MSIX / Microsoft Store JakobSture.CurveBook): The WindowsApps package directory is read-only and never stores user data. Preferences and crash-recovery files stay in per-user AppData storage outside the package (%APPDATA%\CurveBook\ and %LOCALAPPDATA%\CurveBook\recovery\). When package redirection applies, the Windows Desktop Bridge maps these folders, per user, to %LOCALAPPDATA%\Packages\JakobSture.CurveBook_<publisherId>\LocalCache\.
  • Linux and FreeBSD: Preferences, shortcuts, and temporary control tokens are stored in $XDG_CONFIG_HOME/curvebook/ (by default ~/.config/curvebook/). Crash-recovery files are stored in $XDG_DATA_HOME/curvebook/recovery/ (by default ~/.local/share/curvebook/recovery/). Beta GitHub Releases do not include Linux Flatpak packages. For self-built or future Flatpak installs (org.curvebook.CurveBook), these paths are inside ~/.var/app/org.curvebook.CurveBook/config/curvebook/ and ~/.var/app/org.curvebook.CurveBook/data/curvebook/recovery/. On Unix, when HOME and the XDG variables are unset, CurveBook uses a private per-UID directory (mode 0700) under $XDG_RUNTIME_DIR/curvebook or $TMPDIR/curvebook-uid-<uid>.
  • Portable mode and environment overrides: Passing --portable-dir <dir>, or placing portable.txt next to the desktop executable, keeps preferences, shortcuts, and recovery/ inside <dir>/curvebook-data/. Setting CURVEBOOK_CONFIG_DIR=<dir> stores both configuration and recovery files under <dir>. Setting CURVEBOOK_NO_PREFS=1 stops CurveBook from writing preferences and crash-recovery data to disk for that session.
  • WebAssembly browser bundle (curvebook-web, deferred to 1.0): Beta GitHub Releases omit this bundle. When you build it locally, or once it is deployed for 1.0, it runs entirely inside your browser tab and uploads no files to any server. Files you open or drop stay in local memory, and saves or exports use your browser’s local download or File System Access picker. Preferences and crash-recovery autosave data stay in origin-scoped window.localStorage under the keys curvebook.v1.preferences and curvebook.v1.autosave.<doc_id> (the current single-slot browser shell uses curvebook.v1.autosave.default, bounded to a 5 MiB quota with least-recently-used eviction). To coordinate locks between tabs on the same computer, the bundle uses navigator.locks and BroadcastChannel, with short-lived curvebook.v1.lock.<doc_id> entries as a fallback.

3. How to delete local data

  • Desktop (macOS, Windows, Linux, FreeBSD): Quit CurveBook and delete the platform folder or folders listed above (or <dir>/curvebook-data/ in portable mode). For Microsoft Store / MSIX installs, use Settings → Apps → Installed apps → CurveBook → Uninstall (or Advanced options → Reset) to remove the per-user app data container. For Flatpak, run flatpak uninstall --delete-data org.curvebook.CurveBook. Delete any saved .curvebook, .curvebook.d/, .cbtemplate, or exported files from the folders where you placed them.
  • Browser bundle: Clear site data or local storage for the hosting origin in your browser settings, or remove curvebook.v1.* entries in browser developer tools.

Local IPC and AI assistants

Loopback control and MCP modes

1. Local-only transports

  • Disabled by default: Normal desktop, CLI, and browser launches open no network listeners.
  • Stdio MCP mode (curvebook-cli mcp): In this mode, CurveBook exchanges JSON-RPC messages with a parent MCP client on the same computer over standard input and standard output (stdin/stdout), and opens no network sockets. Passing --workdir <dir> restricts file reads, saves, exports, and external CSV/TSV links strictly to <dir>.
  • Loopback TCP control (curvebook --control <port> and curvebook-cli mcp --control-port <port>): When you explicitly enable this mode with --control <port> or CURVEBOOK_CONTROL_PORT, CurveBook binds only to the local loopback address (127.0.0.1 / ::1) and refuses non-loopback addresses. Every connection must authenticate with a per-session bearer token, supplied through --control-token, CURVEBOOK_CONTROL_TOKEN, or the control-<port>.token file. CurveBook answers HTTP request lines with 403 Forbidden, so web pages in a browser cannot probe the local port.

2. External AI clients and model providers

CurveBook itself never connects to AI services or external APIs. When you connect an AI assistant, IDE, or language-model client over MCP or --control, that client may request table cells, column labels, notes, statistical outputs, figure previews, screenshots, or project metadata. That data is handled under the privacy policy and data-retention terms of the AI client and its model provider, not CurveBook’s. If your AI client sends prompts and tool results to a cloud model, your data leaves your machine through that client. Use local models, or de-identified or synthetic data, whenever confidentiality, institutional review, or data-governance rules require it.

Distribution and hosting

Third-party platform operators

  • Microsoft Store: Downloading, licensing, and receiving Store-delivered package updates for the Windows MSIX distribution (JakobSture.CurveBook) are governed by Microsoft’s Privacy Statement and your Windows privacy settings. CurveBook adds no Store telemetry or in-app tracking SDKs.
  • GitHub Releases and repository hosting: Downloads of installers, archives, SHA256SUMS.txt, and Sigstore build provenance attestations from github.com/HauserGroup/curvebook ↗ are governed by GitHub’s Privacy Statement. The same statement covers browsing repository files and participating in issues or discussions.
  • GitHub Pages (this website): index.html, privacy.html, and the reference manual under manual/ are static HTML and CSS pages with no JavaScript, cookies, forms, analytics, or external asset requests. They are served with Referrer-Policy: no-referrer and a strict Content-Security-Policy. As the web host, GitHub Pages logs visitor IP addresses for security and operational reliability under GitHub’s Privacy Statement. If you or your institution host the static curvebook-web bundle on another server, that server’s operator governs its standard HTTP access logs.
