Privacy Policy · Effective 2026-11-18 · Updated 2026-11-23

Local by design.
Zero telemetry.

CurveBook runs locally on your computer or inside your browser tab. Across every distribution, CurveBook collects no personal data, sends no telemetry or crash reports, makes no outbound network connections, and has no auto-updater.

  • Distributions covered: native desktop installers and archives (macOS, Windows, and Linux AppImage), the Tier 2 FreeBSD CLI-only archive, the Windows MSIX / Microsoft Store channel (JakobSture.CurveBook), the command-line tool and Model Context Protocol server (curvebook-cli and curvebook-cli mcp), and the WebAssembly browser bundle (curvebook-web, deferred until CurveBook 1.0).
  • No personal or scientific data collection: CurveBook never collects, transmits, sells, or shares your name, contact details, identifiers, usage activity, or research datasets. No user account or sign-in exists.
  • No telemetry or crash reporting: CurveBook embeds no analytics libraries, usage beacons, or automatic crash-reporting agents.
  • No outbound network connections: CurveBook makes no internet or cloud requests. Automated repository checks (cargo xtask telemetry) reject HTTP client crates, telemetry SDKs, non-loopback network sockets, and external browser requests.
  • No built-in updater: CurveBook never checks for updates in the background. Updates happen only when you install a new release yourself or update through Microsoft Store or your operating system’s package manager.

On-device files & browser storage

What CurveBook stores locally

1. Data written on your device

  • Project, template, and exported files: .curvebook archives, unpacked .curvebook.d/ directories, .cbtemplate templates, and exported figures or tables (.csv, .tsv, .svg, .pdf, .png, .tiff, .emf, .json) are written atomically only to paths you explicitly save or export to. A saved project stores your data sheets, formulas, statistical results, graphs, layouts, notes, named checkpoints, and the local paths of any external CSV/TSV files you explicitly linked into a table.
  • User preferences (preferences.json and shortcuts.json): stores only your selected interface language (locale), visual theme (light, dark, or high-contrast), and custom keyboard shortcut overrides (shortcuts). CurveBook writes preferences.json only when you change a preference away from defaults (or when the file already exists).
  • Crash-recovery write-ahead journal (recovery/): protects unsaved desktop edits if the process or power stops unexpectedly. The directory holds snapshot.curvebook (an atomic workspace baseline), ops.journal (an append-only versioned v2 CRC-32 newline-delimited JSON write-ahead log of workspace commands since the last checkpoint, upgrading legacy v1 records after CRC verification), and curvebook.lock (a local writer lease recording process/window owner ID, timestamps, lease duration, and a non-secret local OS/architecture/hostname identifier used solely on the same machine to detect stale locks). Secondary windows and --new-instance runs use isolated win-<n> or instance-<pid>-... subdirectories. Closing a saved or discarded session cleanly releases the lock and clears pending recovery entries.
  • Temporary loopback control token (control-<port>.token): created in the configuration folder (mode 0600 on Unix) only while curvebook --control <port> is running so local tools under the same user account can authenticate, then removed automatically when that session exits.
  • Recent files: CurveBook does not persist a recent-files (MRU) history file on disk or in browser storage. Your operating system’s native file dialogs or desktop shell may maintain their own recent-items list under your OS privacy settings.
  • Headless command-line runs (curvebook-cli): one-shot CLI subcommands (info, convert, export, run, batch) and default headless curvebook-cli mcp read and write only the file paths you specify and do not create preferences.json or background recovery/ folders.

2. Where each platform keeps local data

  • macOS: ~/Library/Application Support/CurveBook/ (contains preferences.json, shortcuts.json, temporary control-<port>.token, and recovery/).
  • Windows (MSI installer & portable/standalone executable): %APPDATA%\CurveBook\ for preferences.json, shortcuts.json, and temporary control-<port>.token; %LOCALAPPDATA%\CurveBook\recovery\ for crash-recovery files.
  • Windows (MSIX / Microsoft Store JakobSture.CurveBook): the WindowsApps package directory is read-only and never stores user data. Preferences and crash-recovery files stay in per-user package-external AppData storage (%APPDATA%\CurveBook\ and %LOCALAPPDATA%\CurveBook\recovery\, which Windows Desktop Bridge maps per user under %LOCALAPPDATA%\Packages\JakobSture.CurveBook_<publisherId>\LocalCache\ when package redirection applies).
  • Linux & FreeBSD: $XDG_CONFIG_HOME/curvebook/ (default ~/.config/curvebook/) for preferences, shortcuts, and temporary control tokens; $XDG_DATA_HOME/curvebook/recovery/ (default ~/.local/share/curvebook/recovery/) for crash recovery. Linux Flatpak packages are omitted from Beta GitHub Releases (R0.28); for self-built or future Flatpak installs (org.curvebook.CurveBook), these paths live inside ~/.var/app/org.curvebook.CurveBook/config/curvebook/ and ~/.var/app/org.curvebook.CurveBook/data/curvebook/recovery/. When HOME and XDG variables are unset on Unix, CurveBook uses a private 0700 per-UID directory under $XDG_RUNTIME_DIR/curvebook or $TMPDIR/curvebook-uid-<uid>.
  • Portable mode & environment overrides: passing --portable-dir <dir> or placing portable.txt next to the desktop executable keeps preferences, shortcuts, and recovery/ inside <dir>/curvebook-data/. Setting CURVEBOOK_CONFIG_DIR=<dir> stores both config and recovery files under <dir>, and setting CURVEBOOK_NO_PREFS=1 disables on-disk preferences and crash-recovery writes for that session.
  • WebAssembly browser bundle (curvebook-web, deferred to 1.0): omitted from Beta GitHub Releases (R0.28); when built locally or deployed for 1.0, it runs entirely inside your browser tab without uploading files to any server. Files you open or drop are processed in local memory, and saves/exports use your browser’s local download or File System Access picker. Preferences and crash-recovery autosave data are kept in your browser’s origin-scoped window.localStorage under curvebook.v1.preferences and curvebook.v1.autosave.<doc_id> (curvebook.v1.autosave.default in the current single-slot browser shell, bounded to a 5 MiB quota with least-recently-used eviction), alongside local multi-tab lock coordination (navigator.locks / BroadcastChannel, or short-lived curvebook.v1.lock.<doc_id> fallback entries).

3. How to delete local data

  • Desktop (macOS, Windows, Linux, FreeBSD): quit CurveBook and delete the CurveBook folder(s) listed above for your platform (or <dir>/curvebook-data/ when using portable mode). For Windows Store / MSIX installations, Settings → Apps → Installed apps → CurveBook → Uninstall (or Advanced options → Reset) removes the package’s per-user app data container. For Flatpak, run flatpak uninstall --delete-data org.curvebook.CurveBook. Delete any saved .curvebook, .curvebook.d/, .cbtemplate, or exported files from the folders where you placed them.
  • Browser bundle: clear site data / local storage for the hosting origin in your browser settings (or remove curvebook.v1.* entries in browser developer tools).

Local IPC & AI assistants

Loopback control and MCP modes

1. Local-only transports

  • Disabled by default: normal desktop, CLI, and browser launches open no network listeners.
  • Stdio MCP mode (curvebook-cli mcp): exchanges JSON-RPC messages with a parent MCP client over standard input and standard output (stdin/stdout) on the same computer with zero network sockets. Passing --workdir <dir> confines file reads, saves, exports, and external CSV/TSV links strictly within <dir>, and --gui-only restricts automation to interactive GUI widget actions.
  • Loopback TCP control (curvebook --control <port> and curvebook-cli mcp --control-port <port>): when explicitly enabled via --control <port> or CURVEBOOK_CONTROL_PORT, CurveBook binds strictly to local loopback (127.0.0.1 / ::1) and refuses non-loopback addresses. Every connection requires per-session bearer-token authentication (--control-token, CURVEBOOK_CONTROL_TOKEN, or control-<port>.token), and HTTP request lines receive 403 Forbidden so web pages in a browser cannot probe the local port.

2. External AI clients and model providers

CurveBook itself never connects to AI services or external APIs. When you connect an AI assistant, IDE, or language-model client to CurveBook over MCP or --control, any table cells, column labels, notes, statistical outputs, rendered figure previews/screenshots, or project metadata that you or your client request through MCP are handled under that AI client’s and model provider’s own privacy policy and data-retention terms, not CurveBook’s. If your AI client transmits prompts and tool results to a cloud model, data leaves your machine through that client. Use local models or de-identified/synthetic data whenever confidentiality, institutional review, or data-governance rules require it.

Distribution & hosting

Third-party platform operators

  • Microsoft Store: downloading, licensing, and receiving Store-delivered package updates for the Windows MSIX distribution (JakobSture.CurveBook) are governed by Microsoft’s Privacy Statement and your Windows privacy settings. CurveBook adds no Store telemetry or in-app tracking SDKs.
  • GitHub Releases & repository hosting: downloading installers, archives, SHA256SUMS.txt, or Sigstore build provenance attestations from github.com/HauserGroup/curvebook ↗, browsing repository files, and participating in issues or discussions are governed by GitHub’s Privacy Statement.
  • GitHub Pages (this website): index.html, privacy.html, and the reference manual under manual/ are static HTML/CSS pages with no JavaScript, cookies, forms, analytics, or external asset requests, served with Referrer-Policy: no-referrer and a strict Content-Security-Policy. As the web host, GitHub Pages logs visitor IP addresses for security and operational reliability under GitHub’s Privacy Statement. If you or your institution host the static curvebook-web bundle on another server, standard HTTP access logs are governed by that server’s operator.
