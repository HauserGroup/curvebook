File formats · .pzfx · .prism

Open .pzfx and .prism files.
Export tables to CSV or data-only .pzfx.

CurveBook is a free, open-source biostatistics and graphing application that reads data tables and info sheets from .pzfx and .prism files, plus read-only analysis result snapshots and preview images from .prism files. Export tables to CSV/TSV or data-only .pzfx, merge projects with origin badges, or save a full .curvebook project and re-run analyses offline on macOS, Windows, and Linux.

Import & export scope

What CurveBook reads and writes

Format Import (read) Export (write) Notes
.pzfx (XML) All 8 table archetypes, info sheets, exclusions, rich text & Symbol font, floating notes Data tables & info sheets only Analyses, graphs, and layouts stay in .curvebook.
.prism (ZIP) All 8 table archetypes, info sheets, exclusions, rich text, read-only preferred analysis snapshots, preview PNGs Import-only at Beta Opaque PCFFGRA4 binary graphs/layouts and undocumented .dt digests block conformant write support.
.pzf / binary PCFF Refused with clear error Not supported Legacy binary format (~15–18% of public .pzfx-named files); re-save as XML .pzfx or .prism.
.curvebook / .curvebook.d/ Full project Full project Native published JSON Schema format; zero proprietary binary blobs; Git-friendly diffs.
  • .pzfx files (XML import): all eight table archetypes (XY, Column, Grouped, Nested, Contingency, Survival, Parts of Whole, and Multiple Variables), including <HugeTable>, <Table1024>, and XSLT-wrapped files. Imports replicate subcolumns, parametric summary modes (mean with SD/SEM/%CV and N), two-subcolumn mean/SD and mean/SEM modes, Column asymmetric interval and quartile summary modes (mean with +/- error, upper/lower limits, median/IQR), row/column/subcolumn titles, display decimals, rich text and Symbol-font characters, excluded-value markers, floating notes, and top-level or per-table info sheets. Graphs, analyses, and layouts inside .pzfx files are not imported; rerun analyses in CurveBook (analyses reference).
  • Legacy binary .pzf files (not supported): older binary .pzf files — including binary PCFF-prefixed files carrying a .pzfx extension (observed in roughly 15–18% of public .pzfx-named files) — are not supported. CurveBook refuses them with a clear error message; re-save them as XML .pzfx or .prism before opening.
  • .prism files (import-only at Beta): reads data tables across all eight archetypes (headerless archive CSVs resolved by sheet ID, including generated X sequences, replicate/summary/offset modes, subcolumn titles, and display decimals), cell exclusions, rich text, and info sheets. Preferred analysis results are imported as clearly labelled read-only snapshots that show the stored values without feeding CurveBook calculations or hooks; opaque binary graphs and layouts surface typed warnings and retain raster preview PNGs when present. .prism export is not shipped as a supported format at Beta because real .prism archives contain undocumented binary and digest entries; use .pzfx export for data interchange instead.
  • .pzfx data-only export: .pzfx export saves your data tables and info sheets only. Analyses, graphs and layouts stay in your .curvebook project. Every export is a separate copy (leaving your active .curvebook file path and unsaved state untouched) and reports every dropped non-tabular item. Written to match the .pzfx structure of real files; not tested in other applications — structure-conformant files may still be rejected by other applications for non-structural reasons such as checksums, cross-references, or version gates.
  • Merging projects (File › Merge Project…): combine another .curvebook, .curvebook.d/, .cbtemplate, .pzfx, .prism, or .xlsx file into your open project as a one-time copy with automatic sheet ID remapping and removable navigator origin badges (showing only the source filename and format, never full directory paths). Merged sheets have no live cross-file links.

What is actually inside a .prism file (why it is not FAIR)

The .prism ZIP container puts raw tables in CSV and metadata in JSON, and is often marketed as supporting the FAIR Guiding Principles (Wilkinson et al., Scientific Data 3:160018, 2016) ↗ so every component can be located and reused. Standard encodings, however, are not a documented open schema. Across 983 public .prism files deposited on Zenodo (978 valid v10/v11 archives across 165 deposits), four structural barriers limit independent reuse:

  • No published schema & headerless CSVs: every data.csv lacks column headers; column order is not self-describing (row titles precede X, generated X sequences occupy zero CSV columns, and trailing empty Y columns can be omitted), error-bar offsets store [Y, +upper, -lower] rather than limits, and analysis outputs sit behind undocumented internal keys and a three-hop JSON indirection chain.
  • Exclusions are omitted from the CSV: EXCLUDED and CENSORED masks are stored separately in data/sets/*.json range tables. Reading data.csv directly in R, Python, or a spreadsheet silently includes excluded outliers.
  • Graphs, layouts, and font tables remain opaque binary blobs: 979 readable archives contain 55,471 opaque binary entries. Every graph (6,978 graphs/*/data.bin) and layout (592 layouts/*/data.bin) is stored in a proprietary PCFFGRA4 binary format rather than JSON, and font tables (933 misc/used_fonts.bin) use legacy PCFF binary records — only optional raster preview.png thumbnails are readable.
  • Undocumented .dt digests block independent writers: every valid archive pairs data tables (20,872 data.dt entries) and analyses (7,021 parameters.dt entries) with undocumented 128-bit lowercase hex .dt files. Across the Zenodo corpus, data.dt is a strict 1-to-1 deterministic function of the exact raw bytes of data.csv alone (0 divergences across 15,097 distinct CSV payloads; all 1,483 empty tables share 130ab2f63ec643bee541b74c960e10db), and parameters.dt is a strict 1-to-1 function of raw parameters.json bytes (0 divergences across 2,818 payloads) — yet neither matches any standard unkeyed cryptographic or non-cryptographic 128-bit hash tested (CRC32, MD2/4/5, RIPEMD-128, SHA-1/2/3, BLAKE2/3, SHAKE, XXH3, FNV-1a, CityHash, SpookyHash, SipHash, or MurmurHash3), indicating a keyed, salted, or custom proprietary external-edit digest. Without the undocumented algorithm, independent tools cannot guarantee conformant .prism write support.

Proprietary file formats slow down scientific progress. When experimental data, outlier exclusions, analysis settings, and figures are locked inside undocumented containers, publicly funded research cannot be audited, reproduced, or reused without purchasing a specific vendor’s license — and becomes harder to open the moment a subscription lapses or a platform changes. Scientific records belong to science, not to a file-format moat.

True interoperability requires a documented, open specification. Read the closest thing we have to an actual specification of .prism and .pzfx files (derived clean-room from the Zenodo corpus). CurveBook’s native .curvebook and unpacked .curvebook.d/ formats ship with a published JSON Schema, zero proprietary binary blobs, and deterministic plain-text diffs.

Desktop app · curvebook

Open, merge, and export in the desktop app

  1. Open or merge a file: choose File › Open… or File › Import to open a .pzfx or .prism file, or choose File › Merge Project… (or drag and drop a file onto an open project) to copy its sheets into the current workspace with automatic ID remapping and removable navigator origin badges.
  2. Review skipped items and imported snapshots: when a file contains unsupported elements or opaque binary chunks, CurveBook opens the Import Warnings dialog (reopenable from the status bar or File › Import › Import Warnings…). Read-only analysis snapshots read from .prism files carry a banner and never enter CurveBook computations or hooks; click Re-run as a CurveBook analysis… to compute fresh CurveBook results.
  3. Export tables: select any table and choose File › Export › CSV Table… (comma, semicolon, or tab delimiter), choose File › Export › Export All Data Tables… to write every data table to a folder, or choose File › Export › .pzfx file… to save data tables and info sheets to .pzfx (reviewing the preflight summary of dropped non-tabular items before writing).

Command line · curvebook-cli

Convert and export from the command line

Every CurveBook download includes the curvebook-cli command-line tool next to the desktop app. Open a terminal in the folder that holds your file.

1. See which tables the file contains

curvebook-cli info experiment.pzfx

The output lists each table with its ID, type, title, and size, followed by any import warnings.

2. Export a table to CSV

curvebook-cli convert experiment.pzfx experiment.csv

Without further options, the first table is exported. Pick another table by its title or ID:

curvebook-cli convert experiment.pzfx groups.csv --sheet "Groups"

Replicate subcolumns appear as side-by-side columns, and an excluded value keeps its number with a trailing * (for example 55*), so no data are silently dropped. Use a .tsv file name for tab-separated output.

3. Convert the whole file to a CurveBook project

curvebook-cli convert experiment.pzfx experiment.curvebook

The project keeps all tables together, ready for analyses, curve fits, and graphs. The same commands work for .prism files.

4. Export data tables and info sheets to .pzfx

curvebook-cli convert experiment.curvebook export.pzfx

Writes every data table and info sheet to a data-only .pzfx copy without modifying the source project, printing warnings to stderr for any dropped analyses, graphs, or layouts. The full option list is in the command-line reference, and the files, import & export reference covers every supported format.

Prefer to work through an AI assistant? CurveBook’s local MCP server can import these files too; see MCP setup.

Good to know

Limits and privacy

  • Local only: files are read on your computer. CurveBook makes no network connections and collects no telemetry (Privacy Policy).
  • Size limits: very large files and archives are refused with an error message instead of being read partially. The exact limits are in the files reference.
  • Problems: if a file does not open as expected, check the known issues or report it on GitHub Issues; please share a file only if its data can be made public.
