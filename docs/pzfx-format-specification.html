Clean-room empirical reference · .prism · .pzfx

The closest thing we have to an actual specification
of .prism and .pzfx files.

Neither .prism nor .pzfx ships with a published schema. This technical reference documents every structural fact CurveBook relies on, including the parts that remain a proprietary blob hidden by the vendor. All observations come from 3,719 public CC-BY-4.0 and CC0-1.0 files on Zenodo (2,240 XML .pzfx, 496 legacy binary PCFF, and 983 .prism archives across v10 and v11) alongside public standards.

Part 1 · .prism archive format

.prism ZIP container layout

Every valid .prism archive observed on Zenodo is a standard Deflate (method 8) ZIP archive with UTF-8 entry names, forward slashes, and zero ZIP64 archives. Across 165 deposits, the corpus contains 978 valid v10/v11 archives, 979 readable ZIPs total, and 4 files missing a ZIP EOCD. Paths are indexed by opaque sheet and table UIDs declared in document.json:

study.prism (ZIP, Deflate method 8)
├── document.json                           # @class="Document", formatVersion, sheets.*, sheetAttributesMap
├── data/
│   ├── sheets/<sheetUid>/sheet.json        # @class="DataSheet", table.uid, format, dataFormat, xDataSetFormat, flags
│   ├── tables/<tableUid>/
│   │   ├── content.json                    # { $id, numberOfColumns, numberOfRows, version }
│   │   ├── data.csv                        # headerless RFC-4180 CSV (no headers, no exclusion flags)
│   │   └── data.dt                         # undocumented 128-bit raw-byte digest of data.csv (keyed, salted, or custom)
│   └── sets/<setUid>.json                  # @class="DataSet" | "SubColumnTitlesDataSet"; titles, decimals, cellAttributes
├── info/<infoUid>/sheet.json               # experimentDate, constants[], notesText (string or rich-text object)
├── analyses/<analysisUid>/
│   ├── sheet.json                          # analysisClass, inputSheets[], resultSheets[], preferredResultSheet
│   ├── parameters.json                     # { version, content } analysis configuration
│   ├── parameters.dt                       # undocumented 128-bit raw-byte digest of parameters.json (keyed, salted, or custom)
│   ├── results.json                        # { version, content } structured raw analysis output
│   └── result_sheets/<rsUid>.json          # indirection hop: { uid, name, dataSheet: <viewSheetUid> }
├── graphs/<graphUid>/
│   ├── sheet.json                          # sheet metadata only (inputDataSets, floatingNotes, mediaCollection)
│   ├── data.bin                            # PCFFGRA4 — proprietary blob hidden by the vendor
│   └── preview.png                         # optional raster thumbnail (200 observed across 6,978 graphs)
├── layouts/<layoutUid>/
│   ├── sheet.json                          # sheet metadata only (linkedGraphSheets, mediaCollection)
│   ├── data.bin                            # PCFFGRA4 — proprietary blob hidden by the vendor
│   └── preview.png                         # optional raster thumbnail (3 observed across 592 layouts)
├── media/<mediaUid>.{pdf,emf,png,svg,wmf}  # embedded raster or vector media
└── misc/
    ├── used_fonts.bin                      # PCFF — proprietary blob hidden by the vendor (933 / 960 valid archives)
    └── <uid>.bin                           # opaque binary struct (18 00 00 00 ...) — proprietary blob hidden by the vendor

Data decoding traps

Headerless data.csv, error offsets, and exclusions

Unzipping a .prism file and loading data/tables/<uid>/data.csv directly in R, Python, or a spreadsheet produces silently corrupted tables unless the companion JSON metadata is applied:

Rule Observed behaviour across corpus
No column headers Every data.csv is headerless (11,244 all-numeric row-0 tables; non-numeric row 0 is predominantly dataFormat="text" analysis views). Column titles live in data/sets/<setUid>.json.
Column order [rowTitles? (0–1 col, before X)] → [X? (0, 1, or 2 cols)] → [Y datasets in table.dataSets order]. Row titles precede X (377 vs 3 reversed). Trailing empty Y columns may be omitted (4 / 1,620 sampled tables) and must be padded.
Generated X series When xDataSetFormat="series", X occupies zero columns in data.csv (639 / 641 tables). Synthesize X from data/sets/<xUid>.json replicates[0].{startValue, interval}. y_single / timeSpan occupy 1 X column; y_errorBar / date_se occupy 2 X columns.
Asymmetric error offsets y_high_low and y_plus_minus carry 3 subcolumns per Y dataset storing non-negative offsets from Y (840 / 840 non-negative across 137 tables) in exact order [Y, +upper_offset, -lower_offset] — not absolute limits.
Compressed replicate ranges In data/sets/<uid>.json (140,805 files), replicates appear in replicates[] and/or compressed "replicate ranges": [{range: "N"|"N~M", replicate}] using inclusive 0-based ~ ranges, carrying valueType (string/real/int/timespan/date) and decimalsLength (1..=15).
Out-of-band exclusions Exclusions never appear in data.csv. They are stored in data/sets/<uid>.json under cellAttributes: [{rows: "N"|"N~M", attributes: ["EXCLUDED", "CENSORED", "SECTION_TITLE", "SCI_NOTATION", ...]}].
Polymorphic rich text title, subcolumn titles (SubColumnTitlesDataSet), and info fields may be a plain string or {string, version, formatting: [{range, attributes: {baseline: "superscript"|"subscript", fontWeight: "bold", italic, horizontalAlignment}}]}.

Results, digests & opaque payloads

Analysis snapshots, .dt digests, and proprietary blobs

Three-hop analysis result chain

Stored analysis results are resolved through three JSON indirection hops, verified 784 / 784 across 7,021 analyses in 694 files. The corpus spans 32 distinct analysisClass values, including the exact wire spellings TRNSFORM and shaproWilks:

analyses/<aUid>/sheet.json              (preferredResultSheet: <rsUid>)
  └─▶ analyses/<aUid>/result_sheets/<rsUid>.json   (dataSheet: <viewSheetUid>)
        └─▶ data/sheets/<viewSheetUid>/sheet.json  (flags: ["ANALYSIS_VIEW"], table.format: "view")
              └─▶ data/tables/<tableUid>/data.csv  (tabular display values; 38 empty views omit data.csv)

Proprietary binary blobs and undocumented .dt digests

Zero checksum or signature keys exist inside any .prism JSON file. Instead, 979 readable archives contain 55,471 opaque non-CSV/JSON/image entries:

Archive entry Corpus prevalence Wire signature Specification status
graphs/<uid>/data.bin 6,978 entries PCFFGRA4 binary Proprietary blob hidden by the vendor — holds all graph styling and plot definitions; only optional preview.png (200 observed) is readable.
layouts/<uid>/data.bin 592 entries PCFFGRA4 binary Proprietary blob hidden by the vendor — holds all page-layout definitions; only optional preview.png (3 observed) is readable.
misc/used_fonts.bin 933 / 960 valid archives PCFF binary Proprietary blob hidden by the vendor — legacy binary font record table.
misc/<uid>.bin 15,717 entries 18 00 00 00 … binary Proprietary blob hidden by the vendor — undocumented binary auxiliary structs.
data/tables/<uid>/data.dt 20,872 entries (960 / 960 valid archives) 32-char lowercase hex (128-bit) Undocumented 128-bit external-edit digest (indicating a keyed, salted, or custom proprietary algorithm): strict 1-to-1 deterministic function of exact raw data.csv bytes alone (0 / 15,097 divergences; all 1,483 0-byte tables map to 130ab2f63ec643bee541b74c960e10db). Matches no standard unkeyed cryptographic or non-cryptographic hash tested (including an exact algebraic inversion ruling out all 264 seeds of MurmurHash3_x64_128).

Matches no standard unkeyed hash tested (CRC32, MD2/4/5, RIPEMD-128, SHA-1/2/3, BLAKE2/3, SHAKE, XXH3, FNV-1a, CityHash, SpookyHash, SipHash, or MurmurHash3).

Part 2 · .pzfx XML format

.pzfx XML grammar and legacy PCFF detection

Before invoking an XML parser on a .pzfx file, check its leading bytes:

  • Legacy binary PCFF files masquerading as .pzfx: On Zenodo, 496 of 2,736 .pzfx-named files (18.1%) begin with the 4-byte ASCII header PCFF. That header marks an older legacy binary container (proprietary blob hidden by the vendor), not XML. Refuse it before UTF-8 decoding.
  • UTF-8 & optional XSLT wrapper: all 2,240 XML .pzfx files are UTF-8 with zero DOCTYPE and zero non-whitespace trailing bytes. 22 files wrap the root element directly inside <xsl:stylesheet version="1.0"> (no intermediate <xsl:template>). 1,437 carry a default xmlns and 803 omit it — match tags by XML local name.

Unanimous XML element order (2,178 direct corpus files)

<Root *XMLVersion="5.00">                 <!-- vendor root element; match by local name -->
  <Created>...</Created>
  <DefGraphButton>...</DefGraphButton>     <!-- optional -->
  <InfoSequence>
    <Ref ID="Info0" Selected="1"/>         <!-- always <Ref>; zero inline info sheets observed -->
  </InfoSequence>
  <Info ID="Info0">                        <!-- 0..N top-level info sheets -->
    <Title>...</Title>
    <Notes>...</Notes>
    <Constant><Name>...</Name><Value>...</Value></Constant>
  </Info>
  <TableSequence>
    <Ref ID="Table0" Selected="1"/>        <!-- always <Ref>; zero inline tables observed -->
  </TableSequence>
  <Table ID="Table0" TableType="XY" XFormat="numbers" YFormat="replicates"
         Replicates="3" EVFormat="AsteriskAfterNumber">
    <Title>...</Title>
    <Info ID="..."/>                       <!-- optional embedded per-table info sheet (31 observed) -->
    <FloatingNote Color="Yellow|Blue|Gray|Red">...</FloatingNote>
    <RowTitlesColumn>...</RowTitlesColumn>
    <SubColumnTitles OwnSet="0|1">...</SubColumnTitles>
    <XColumn Width="..." Decimals="0..15" Subcolumns="1|2">...</XColumn>
    <XAdvancedColumn Version="1" ...>...</XAdvancedColumn>
    <YColumn Width="..." Decimals="0..15" Subcolumns="1..208">...</YColumn>
  </Table>                                 <!-- <HugeTable> and <Table1024> share identical grammar -->
  <Template>...</Template>                 <!-- opaque ASCII/base64-like payload (up to 89 MB) — proprietary blob hidden by the vendor -->
</Root>

Three interchangeable root-level table elements share identical attributes, child order, and <TableSequence><Ref> linkage: <Table> (12,790 tables), <HugeTable> (120 tables, up to 256 Y columns / 208 subcolumns), and <Table1024> (16 tables, up to 745 Y columns). The trailing <Template> block appears in 2,239 / 2,240 files (median 39.9 KB, max 89.0 MB, 657.7 MB total across the corpus). It stores analyses, graphs, and layouts as an opaque proprietary blob hidden by the vendor and must be skipped while streaming.

Table grammar details

.pzfx table archetypes, summary modes, and rich text

Feature Exact wire encoding observed on Zenodo
8 table archetypes (TableType + ExtTableType) OneWay (5,073), XY (4,199), TwoWay (3,272), Contingency (118), PartsOfWhole (116), Survival (61), TwoWay + ExtTableType="Nested" (81, YFormat="replicates"), and OneWay + ExtTableType="MultipleVariables" (6, optional YColumn@MVType="Categorical"|"Continues" [exact wire spelling]).
YFormat modes replicates (6,883, Table@Replicates 1..208), omitted (5,258), SDN (322), SD (288), SE (102), SEN (32), upper-lower-limits (29), low-high (7), and CV (5 tables: 2 subcolumns storing (mean, %CV) directly, verified across 162 pairs). Subcolumns sits on <YColumn>, <XColumn>, and <XAdvancedColumn>, never on <Table>.
XFormat modes none (8,666), numbers (4,193), time (51: numeric elapsed values in <XColumn>, hh:mm:ss strings in <XAdvancedColumn Version="1">), error (15, never "err": both columns carry Subcolumns="2" for X and X-error), and date (1). <XColumn> unanimously precedes <XAdvancedColumn>.
Exclusions & subcolumn titles Table@EVFormat="AsteriskAfterNumber" (99.8%) with <d Excluded="1"> (2,055,926 excluded cells). <SubColumnTitles OwnSet="0|1"> (428 tables) holds shared (0) or per-Y-column (1) subcolumn titles.
Decimals, colors & rich text Decimals appears on column elements as integers 0..=15 (-1 never observed), with optional YColumn@Scientific="1". Table@Highlighted uses 1-based palette index strings "1".."7". Inline rich text uses <I>, <B>, <U>, <SUP>, <SUB>, <Font Color="#RRGGBB">, and <Font Face="Symbol"> (plus Windows Symbol PUA U+F020..=U+F0FE, decoded via Unicode SYMBOL.TXT).

Full evidence ledger & open alternative

Why open formats matter for scientific progress

Reproducibility depends on inspecting the exact data, outlier exclusions, statistical settings, and figure definitions behind a published claim years later — without paying rent to a single software vendor. Undocumented binary blobs and proprietary integrity tokens turn public repositories into software-locked archives. They force researchers to reverse-engineer their own field’s supplementary files instead of building on earlier work. Scientific records should outlive any single application through open, documented, schema-validated formats.
