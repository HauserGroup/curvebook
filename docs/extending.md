# Extending LumenCraft

Follow the existing seams below whenever adding a capability. Every user-facing action must preserve **headless-first parity** (accessible via `lumencraft-engine`, CLI, MCP, and GUI where applicable) and satisfy [AGENTS.md](../AGENTS.md) and [docs/pitfalls.md](pitfalls.md).

## Extension Matrix ("You want to add -> Where -> How")

| You want to add | Where | How |
| :--- | :--- | :--- |
| **Engine command** (`CommandSpec`) | Target: `crates/engine/src/cmd/mod.rs` (`R0.8`)<br>Current transition: `crates/engine/src/catalog.rs`, `crates/engine/src/lib.rs`, `crates/engine/src/{cmd_data,cmd_sci}.rs` | Name the ID per [docs/command-ids.md](command-ids.md) (`<area>.<camelCaseAction>`). Register one `CommandSpec` (or while pre-`R0.8`, add a `CommandDescriptor` in `COMMANDS`, set `is_read_only_command` accurately, and wire dispatch + undo action). Never rename shipped IDs. Add sweep/unit tests (`crates/engine/tests/command_sweep_props.rs`) and run `cargo xtask commands` / `cargo xtask commands --check`. |
| **UI command** (`UiCommandSpec`) | `crates/ui-egui/src/menus/ui_commands.rs` + `crates/ui-egui/` menu/panel wiring + generated `crates/mcp/src/ui_catalog.rs` | Choose a `ui.<camelCaseAction>` (or `app.*`) ID. Add a `UiCommandSpec` entry (currently `(id, label, shortcut, params_doc)` tuple—keep fields strictly ordered!). Wire its UI handler in `crates/ui-egui`. Run `cargo xtask ui-commands` so `crates/mcp/src/ui_catalog.rs` regenerates cleanly, then verify `cargo xtask ui-commands --check` and `cargo xtask commands --check`. |
| **Cursor** | `crates/tools/src/cursors.toml`, `crates/tools/src/lib.rs`, `crates/ui-egui/src/os_integration.rs` | Add/update the entry in `crates/tools/src/cursors.toml` and any cursor SVG/PNG under the asset path. If adding a new `CursorHint` variant in `crates/tools/src/lib.rs`, map it cleanly in `crates/ui-egui/src/os_integration.rs`. Record any new asset files in [ASSETS.md](../ASSETS.md) and run `cargo xtask cursors` + `cargo xtask assets`. |
| **Statistical / Scientific `AnalysisKind`** | `crates/doc/src/analysis.rs` (`AnalysisKind` & typed spec/result structs), `crates/stats` / `crates/fit` / `crates/transform`, `crates/engine`, `crates/ui-egui` | 1. Define typed parameter & result structs + `AnalysisKind` variant in `crates/doc/src/analysis.rs` (handling serde compatibility).<br>2. Implement pure-Rust math in `crates/stats` / `crates/transform` / `crates/fit` with peer-reviewed citations, edge-case coverage, and `D1` oracle checks (NIST StRD / verified reference values).<br>3. Wire execution/recalculation into `lumencraft-engine` (`analyze.run` / typed runner).<br>4. Expose parameters & results views in `crates/ui-egui`, CLI, and MCP. |
| **Curve-fit `ParametricModel`** | `crates/fit/src/library/` (registered via `crates/fit/src/library/mod.rs`) | Implement `ParametricModel` (`id`, `name`, equation display, parameter names, `eval`, analytical `jacobian`, heuristic `initial_guess`, bounds) with peer-reviewed textbook reference in doc comments. Register it in the built-in catalogue in `crates/fit/src/library/mod.rs`, add NIST StRD / `D1` validation tests (including bad/degenerate initial inputs returning typed `Err`, never panics). |
| **`Importer` / `Exporter` format** | Target: `crates/format/src/registry.rs` (`R0.12`)<br>Current modules: `crates/format/src/{pzfx,prism,export}.rs`, `apps/lumencraft-cli/src/cmd_convert.rs` | Implement `Importer` / `Exporter` cleanly (no panics or unchecked indexing on adversarial/malformed inputs; document format assumptions neutrally in clean-room terms). Use `lumencraft-platform` atomic writes for file outputs. Expose via CLI/engine/UI seams as appropriate, add round-trip and malformed-input tests, and register format extension/MIME details cleanly. |
| **Locale / UI string** | `crates/ui-egui/src/i18n.rs` | Add the key in `crates/ui-egui/src/i18n.rs` and provide translations across all active locale tables without duplicating existing keys. Run `cargo xtask i18n-report` to verify zero missing/orphaned keys across locales and `cargo test -p lumencraft-ui-egui`. |
| **Persisted-file version / migration** | `crates/format/src/versioned.rs` *(R0.11)*, `crates/format/src/archive.rs`, config loaders in `apps/lumencraft/src/main.rs` | Bump the format version constant (`CURRENT_SCHEMA_VERSION` or format header version), add a deterministic forward `VersionStep` migration to `MIGRATION_STEPS`, verify that reading a newer unsupported version fails safely without overwriting disk state ([docs/file-formats.md](file-formats.md)), add checked-in golden fixture tests, and regenerate schemas with `cargo xtask schemas` (`--check` in CI). |
| **Asset (icon, image, SVG, sample)** | Asset directory (never `.ttf`/`.otf`/`.woff`/`.woff2`!) + [ASSETS.md](../ASSETS.md) + [ATTRIBUTION.md](../ATTRIBUTION.md) | Verify the asset licence matches [docs/licences.md](licences.md). Add the file (never commit binary font files). Add a metadata row to [ASSETS.md](../ASSETS.md) and third-party credit to [ATTRIBUTION.md](../ATTRIBUTION.md) if applicable. Run `cargo xtask assets` (and `cargo xtask ico` if Windows icon sources changed). |
