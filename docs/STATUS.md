This document summarizes what works in LumenCraft today, the checks that verified it, and the honest limits of the current offline workspace. Every Markdown table below uses unique Column 1 keys (`cargo xtask status` rule).

**Next planned infrastructure task:** [R0.18 — Upgrade to Rust 1.99.1](ROADMAP.md#r018-upgrade-the-workspace-and-build-toolchains-to-rust-1991) is the next immediate roadmap item (`Owner: maintainers`, `Status: todo`). The currently declared workspace minimum and explicit CI pins remain Rust 1.95; the toolchain upgrade and its validation have not been implemented by this roadmap update.

**Next feature priority:** [R7.3 — MCP workflow parity and shared live session](ROADMAP.md#r73-mcp-workflow-parity-proof--shared-live-window) follows the Rust upgrade and precedes new `R10` GUI implementation. MCP readiness for existing capabilities remains `todo`: real stdio/headless workflow coverage, protocol behavior, and a shared visible session must be verified. Future engine additions get MCP coverage when they land; this priority change does not claim functionality is complete. [R7.4 — Accessible MCP guide and minimal README](ROADMAP.md#r74-accessible-mcp-guide-and-minimal-readme) is a `todo` documentation follow-up immediately after verified MCP implementation; the guide and README tidy-up have not been written by this scheduling update.

## Known Limits

1. **Human-operable GUI (`R10`, open, blocks `1.0`):** A 2026-11-15 audit of the rendered desktop window and web canvas found that **`0` of `50`** reference GUI workflows can be completed end to end by a person. Modal dialogs and the Power wizard render as static text without controls and are not hit-tested; 12 of the 26 `ActiveDialog` variants show only a generic placeholder line (`modal_preview_lines` in `crates/ui-egui/src/compositor.rs`) (`B1`); there is no reachable New Data Table picker (`B2`); result sheets are truncated to 4 tabs × 6 rows × the first column with unclickable tabs (`B3`); desktop engine menu items are dispatched with `null` params and the web host has no menu bar (`B4`); toolbar, inspector, formula bar, column headers, context menus, and grid scrolling are not interactive (`B5`). Chrome text is an uppercase-only bitmap font, and graph sheets are stretched to the pane rather than kept at page aspect ratio. `R10.14`–`R10.22` add an external-branding gate, proportional typography, an aspect-ratio canvas, a shared widget/modal library, Navigator/Family/notes, a live inspector, typeset equations, keyboard and screen-reader accessibility, translations for new strings, and UI performance budgets. `R0.15` will require evidence for every "done" GUI marker. The `49` passing `gui_wf_*` tests drive `UiApp` through the semantic agent harness (`dispatch_gui_action`) and do not exercise these rendered surfaces. Engine and dialog state machines exist for `48` of `50` workflows; standalone *P*-value-stack adjustment (`R10.10`) and Compact Letter Display (`R10.11`) are missing. What works for a person today: file open/save/export dialogs and drag-and-drop, navigator clicks and pane toggles, undo/redo, visible-viewport cell editing and TSV paste, and graph/layout canvas brushing, dragging, and zooming. **Release gates:** **Alpha** (`R8.3`/`R8.4` presenters), **Agent-harness workflows** (formerly "Core workflows"; `R8.6`–`R8.8` + `R9.17`, agent harness only), and **Beta** (`R5.4`) are done; the new **Human GUI workflows** gate (`R10.1`–`R10.22`) is open and is required for `1.0` ([`ROADMAP.md`](ROADMAP.md#release-gates)).
2. **Cross-OS target VM QA, live browser execution & Apple notarization (`R8.5`, in progress):** Live OS GPU window presenter (`R8.3` `apps/lumencraft/src/gui_window.rs` via `eframe 0.37` / `egui 0.37` / `wgpu` + `rfd 0.17`), `wasm32-unknown-unknown` `+simd128` Trunk WebGL2 bundling (`R8.4` `lumencraft-web-0.1.0.zip`), `R5.4` native clipboard/print/layout drag, `cjk_rtl_hidpi_desktop_qa`, and universal macOS `aarch64` + `x86_64` `.dmg`/`.zip` packaging + `verify.sh --arch universal` are implemented and verified locally (`23 passed` in `lumencraft`, `13 passed` in `lumencraft-web`). Remaining release QA requires target-OS environments outside a local macOS workstation: Apple Developer ID signing + notarization, Windows VM, Linux X11/Wayland VM (AppImage/deb/rpm/Flatpak), FreeBSD runner, and live browser QA runs.
3. **Hosted GitHub Actions CI & `v*` release runners (`R0.6`, `R0.14`):** `R0.5` (`cargo xtask licenses` + `cargo deny check licenses`), `cargo about` `THIRD-PARTY-LICENSES.html`, `.github/workflows/release.yml` (`tags: ["v*"]` + safe `env:` version resolution), Zero Telemetry (`cargo xtask telemetry`), and local `actionlint 1.7.12` + `shellcheck 0.11.0` (`cargo xtask workflows`, `0` warnings across all `6` workflow files and `14` shell scripts) pass locally. Remaining remote items are a green hosted `ci.yml` run (`R0.6`, open) and tagging/pushing `v0.1.0-rc1` across the 5-OS GitHub Actions release matrix (`R0.14`, open). **Hosted `CI` currently fails on `main`** (every push since 2026-11-14, e.g. `fda1cc0`): the `actionlint` install step in [`.github/workflows/ci.yml`](../.github/workflows/ci.yml) passes `$RUNNER_TEMP/actionlint-bin` to `download-actionlint.bash` before creating that directory, so no Rust gate runs on hosted runners ([`R0.6`](ROADMAP.md#r06-repository-hygiene--ci-cleanup)).
