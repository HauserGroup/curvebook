# GitHub Pages Site: Design & Publication

The site consists of [`index.html`](../index.html), [`faq.html`](../faq.html), [`open-pzfx-files.html`](../open-pzfx-files.html), [`privacy.html`](../privacy.html), [`site.css`](../site.css), the attributed logo and workspace screenshots under [`images/`](../images/), and the static documentation manual entry at [`manual/index.html`](../manual/index.html) (with the canonical `/manual/latest/` mirror alongside frozen release snapshots under `docs/manual/v<major>.<minor>/`, machine-readable `docs/sitemap.xml`, `docs/llms.txt`, and `docs/llms-full.txt`, and root redirect shims `docs/get-started.html` and `docs/troubleshooting.html` generated by `cargo xtask docs-site --release <version>`). `index.html` introduces CurveBook, showcases the desktop workspace, summarizes capabilities and Beta platform packages, and explains full-workspace file sharing; `faq.html` provides a Quick Facts table and structured answers to common questions; `open-pzfx-files.html` documents offline `.pzfx` and `.prism` table import; and `privacy.html` publishes the dedicated plain-language privacy policy at `/privacy.html` for desktop installers, Windows MSIX / Microsoft Store, CLI/MCP, and browser-bundle users. The [design decisions](#design-decisions) below govern content and styling; [preview and checks](#preview-and-checks) and [publishing](#publish-alongside-beta) cover verification and release publication.

## Design decisions

Initial decisions: 2026-11-16–18. **Beta overhaul recorded: 2026-11-23.** Scope: the public GitHub Pages landing page ([`index.html`](../index.html)), privacy policy ([`privacy.html`](../privacy.html)), fallback manual index ([`manual/index.html`](../manual/index.html)), shared stylesheet ([`site.css`](../site.css)), and generated static reference manual.

### Scope

This record governs the public CurveBook website and its GitHub Pages presentation: page structure, visitor-facing copy, visual styling, links, accessibility, and publication. It does not prescribe the desktop application interface, browser application interface, application themes, menus, dialogs, or scientific graph styles (governed separately by [`design-language.md`](../design-language.md)). References to windows, title bars, or desktop styling below describe the website's visual treatment only.

### Warm Stone Coral & readability refinement (2026-11-23)

Preserved 100% of the Classic coral desktop geometry (`0px` corners, crisp two-pixel raised/inset bevels, hard `3px 3px 0` outer window shadow, solid `--desktop` background with no decorative grid texture, zero JavaScript, strict CSP, and `Referrer-Policy: no-referrer`) while refining color harmony, interactive affordance honesty, and long-form readability across [`site.css`](../site.css), [`index.html`](../index.html), [`privacy.html`](../privacy.html), and [`xtask/src/docs_site/template.rs`](../../xtask/src/docs_site/template.rs):

- **Warm Stone Coral palette:** Replaced the slightly olive-cast 1990s grays (`#ECEBE5`, `#D5D5CF`, `#747974`) with clean warm-stone neutrals (`#EFEDE8`, `#DCD9D2`, `#72706B`), lifted document paper to crisp `#FEFEFE`, deepened the title bar to slate-indigo (`#243752`, echoing the desktop app's accent family in [`design-language.md`](../design-language.md)), and cleaned up the coral primary/link accents (`#B83D37` / `#962F2B` / `#9B312D`). Every text and non-text pair exceeds WCAG 2.2 AA (with primary text `>15:1` AAA, muted text on chrome `5.27:1`, and bevel shadow on chrome `3.51:1`).
- **Affordance honesty ("only buttons look like buttons"):** In a beveled desktop aesthetic, raised three-dimensional boxes imply clickability. Raised button bevels are therefore reserved strictly for actual interactive controls (`.button`, active hover states on `nav a`, and clickable `.az-letters a`). Non-interactive metadata is styled as flat or recessed readouts:
  - `.pill-row` / `.pill` (`Pure Rust`, `Zero Telemetry`, `MIT OR Apache-2.0`, `Desktop · CLI · MCP`): flat monospace metadata strip separated by vertical rules.
  - `.platform-tag` (`Signed & Notarized`, `Unsigned Beta`, `AppImage`, `Preview`) and manual `.badge` tags: flat monospace status readouts without raised button chrome.
  - `.file-type` (`.curvebook · .curvebook.d/ · .cbtemplate`): recessed inset well (`--inset` border direction) so it reads as a read-only path display rather than a button.
  - `.az-letters span`: flat muted cell for inactive index letters.
- **Typography & WCAG readability:**
  - Switched `:root` from hardcoded `15px` Tahoma/Verdana to `font-size: 100%` with the native system UI stack (`system-ui, -apple-system, "Segoe UI", Roboto, Tahoma, sans-serif`) so browser default font-size preferences are respected and HiDPI rendering is crisp.
  - Capped prose measure to `64ch–68ch` (`.lead`, `.section-lead`, and `.doc-body > p, ul, ol, dl, blockquote`) while keeping tables, code blocks, figures, math blocks, and card grids full width.
  - Raised small metadata labels to `>= 0.78rem–0.8125rem`, added `font-variant-numeric: tabular-nums` on tables and instrument metadata, added subtle alternating row striping (`--row-alt: #F6F5F2`) on `.doc-body table`, added flat `0px`-radius warm-stone highlights on inline prose `<code>`, upgraded keyboard focus rings to `2px solid var(--title)` (`outline-offset: 3px`), and enabled `scroll-behavior: smooth` inside `@media (prefers-reduced-motion: no-preference)`.
- **Iconic instrument chrome:** Used the existing `<h1>` `<span>` hook for the coral punchline (`h1 { color: var(--title); }`, `h1 span { color: var(--accent); }`), styled `.window-status` and status tags in monospace, added tactile menu-bar hover states on `nav a`, and added a classic recessed `.window-statusbar` along the base of `.desktop-window` (hidden in `@media print`).

### Historical Alpha rationale and choices preserved

- **Focused landing page plus dedicated privacy policy and static reference manual:** Keep the product introduction, workspace showcase, capabilities, sharing summary, and downloads together on [`index.html`](../index.html), paired with [`privacy.html`](../privacy.html) for per-distribution disclosures and [`manual/index.html`](../manual/index.html) for the full generated reference manual.
- **Scientific-software identity:** Describe CurveBook as an open-source, clean-room biostatistics, nonlinear regression, and scientific graphing application written from scratch in pure Rust; keep detailed MCP setup in the beginner and reference guides.
- **Classic coral desktop-era visual language:** Warm-grey `#D5D5CF` chrome, `#ECEBE5` desktop, `#FAFAF6` paper surfaces, `#29394D` slate title bars, `#AB443D` coral primary actions, `#8F3936` WCAG-AA accessible links, `#1D6561` file-type accents, square corners, two-pixel raised/inset bevels, and system sans-serif fonts with zero bundled font binaries or decorative non-functional window chrome.

### Workspace sharing claim

Make **Share your full workspace. All at once.** prominent, backed by `.curvebook` single-file archives, `.curvebook.d/` unpacked directories, and `.cbtemplate` templates. This is manual project-file sharing, not hosted or simultaneous live collaboration.

`ProjectDocument` in [`crates/doc/src/project.rs`](../../crates/doc/src/project.rs) stores data, info/notes, analysis results/specifications, graphs, layouts, and checkpoints; `build_archive_entries` in [`crates/format/src/archive.rs`](../../crates/format/src/archive.rs) serializes the whole document, data-sheet CSV entries, and embedded image assets (see [`file-formats.md`](../file-formats.md)). Linked external CSV/TSV files keep provenance paths and are not automatically attached outside the project; recipients need CurveBook to reopen the project.

### Claims and release honesty

Do not advertise **full feature parity** as achieved or embed mutable feature, test, command, or model counts in hand-written prose ([`pitfalls.md` §2](../pitfalls.md#2-hardcoded-headline-counts-going-stale)). Live engineering status belongs in [`STATUS.md`](../STATUS.md) and [`evidence/overview.md`](../evidence/overview.md).

The clean-room statement refers to developing CurveBook without using commercial statistical or graphing applications, inspecting their internals, or copying their proprietary code/assets, in accordance with [`AGENTS.md`](../../AGENTS.md). Retain the explicit **License:** (`MIT OR Apache-2.0`), clean-room disclosure, zero-telemetry + GitHub Pages IP-log privacy notice, and source code link in the footer.

### Behavior and maintenance

Use native fragment links, semantic headings, a skip link, keyboard focus on destination sections (`tabindex="-1"`), native `<details>` disclosure for long TOCs, and visible `2px solid` focus outlines (`var(--title)`). Reflow cleanly down to `320px` with zero horizontal overflow. Link to the full GitHub Releases list rather than assuming `/releases/latest` (since prereleases do not populate `/releases/latest`).

Keep the site completely buildless to serve: local HTML/CSS/PNG only, zero scripts, zero external fonts, zero analytics, zero forms, and zero background requests across `index.html`, `privacy.html`, `manual/`, and root redirect shims. Preserve `Referrer-Policy: no-referrer` and the strict `Content-Security-Policy`, and keep the GitHub Pages IP-log disclosure accurate against [GitHub documentation](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages#data-collection).

## Preview and checks

Generate a local preview of the full documentation manual (into the gitignored `target/docs-site/` directory) and serve either `docs/` or `target/docs-site/` with a local static HTTP server (`python3 -m http.server`). No external build toolchain, scripts, or external fonts are required:

```sh
cargo xtask docs-site
cargo xtask docs-site --check
```

At release tagging time, generate a frozen versioned snapshot under `docs/manual/v<major>.<minor>/`, update `docs/manual/index.html`, and emit the root redirect shims (`docs/get-started.html`, `docs/troubleshooting.html`):

```sh
cargo xtask docs-site --release <version> --check
```

### Search & AI discoverability metadata (`R12.8`, `R12.10`)

- **Canonical `/manual/latest/` URLs:** `cargo xtask docs-site --release <version>` emits both the frozen versioned snapshot under `docs/manual/v<major>.<minor>/` and the unversioned canonical mirror at `docs/manual/latest/`. Every page in `docs/manual/latest/` carries a self-referencing `<link rel="canonical">` to `.../manual/latest/...`; versioned snapshot pages also point their canonical link to `/manual/latest/` and stay out of `sitemap.xml` so search engines and citations accumulate on stable URLs across releases. `docs/manual/index.html`, root redirect shims (`docs/get-started.html`, `docs/troubleshooting.html`), `README.md`, and hand-written landing pages link to `manual/latest/`.
- **Sitemap (`docs/sitemap.xml`):** Lists the hand-written landing pages (`LANDING_PAGES` in `xtask/src/pages_site.rs`: `index.html`, `open-pzfx-files.html`, `faq.html`, `privacy.html`) and every page of `docs/manual/latest/`, and nothing else: redirect shims and older versioned snapshots stay out so search engines index one copy of each page. `--release` rewrites it; after adding or removing a landing page, regenerate it with:

```sh
cargo xtask docs-site --sitemap
```

- **Open Graph & HTML Microdata (zero `<script>`):** All hand-written landing pages (`index.html`, `faq.html`, `open-pzfx-files.html`, `privacy.html`) and generated manual pages carry Open Graph (`og:type`, `og:site_name`, `og:title`, `og:description`, `og:url`, `og:image`, `og:image:alt`) and `twitter:card="summary_large_image"` metadata pointing to the published base URL. Because the site enforces `script-src 'none'` (`default-src 'none'`), structured data uses HTML Microdata (`itemscope`, `itemtype`, `itemprop`) instead of `<script type="application/ld+json">`: `index.html` declares `schema.org/SoftwareApplication`, and `faq.html` declares both `schema.org/SoftwareApplication` (Quick Facts table) and `schema.org/FAQPage` (Question/Answer items).
- **LLM indexes (`docs/llms.txt` and `docs/llms-full.txt`):** `cargo xtask docs-site` generates deterministic Markdown indexes at the site root following the `llms.txt` convention: `docs/llms.txt` provides a concise structured directory of CurveBook's capabilities, platforms, formats, and canonical `/manual/latest/` links, and `docs/llms-full.txt` bundles the full plain-text reference content (with internal doc links stripped) so AI assistants and retrieval tools can index CurveBook cleanly without scraping HTML chrome. Both files are verified byte-for-byte by `cargo xtask docs-site --check` and listed in `SITE_FILES` in `xtask/src/pages_site.rs`.
- **Single-switch custom domain cutover (`CUSTOM_DOMAIN` in `pages_site.rs`):** `xtask/src/pages_site.rs` defines `CUSTOM_DOMAIN: Option<&str>` (default `None`, publishing under `https://hausergroup.github.io/curvebook/`). When moving to a custom domain (for example `curvebook.org`), set `CUSTOM_DOMAIN = Some("curvebook.org")` and `SITE_BASE_URL = "https://curvebook.org/"` in `pages_site.rs` (so `pages-stage` automatically emits `CNAME` and `robots.txt`), regenerate the site (`cargo xtask docs-site --release <version> --check`), and update the canonical/OG URLs in the hand-written landing pages.
- **Verification & webmaster tools:** `cargo xtask docs-site --check` fails when `docs/sitemap.xml`, `docs/llms.txt`, or `docs/llms-full.txt` is stale, or when a landing page lacks its exact canonical link or required Open Graph tags. Canonical links are the only absolute `<link href>` the checks accept, and only inside `SITE_BASE_URL`. A project site on `github.io` cannot serve its own `robots.txt` (that file belongs to the organisation's root site), so submit the sitemap directly in Google Search Console and Bing Webmaster Tools. Both verify ownership with an HTML file or `<meta>` tag placed in `docs/` and add no script to the pages. A verification file must also be added to `SITE_FILES` in `xtask/src/pages_site.rs`, or it is not published.

### What Pages publishes (`R12.9`)

Pages serves only the files on the publish list in `xtask/src/pages_site.rs`, not the whole `docs/` folder, so the internal Markdown kept under `docs/` (roadmap, audits, planning, evidence, reference sources, schemas) is never served next to the site. The list is the landing pages (`LANDING_PAGES`), the redirect pages (`REDIRECT_PAGES`), `docs/manual/latest/` and every release snapshot under `docs/manual/v<major>.<minor>/` except their `manifest.json`, `SITE_FILES` (`site.css`, `sitemap.xml`, `llms.txt`, `llms-full.txt`), and everything under `images/` (plus generated `CNAME` and `robots.txt` when `CUSTOM_DOMAIN` is set). Markdown and symlinks are never published.

`.github/workflows/pages.yml` runs on pushes to `main` that touch `docs/`, `xtask/`, or the workflow itself (and on demand): it copies the list into `_site` and deploys that folder. Its `deploy` job is the only place outside `release.yml` that may hold `pages: write` and `id-token: write` (`cargo xtask telemetry`). To see or check the list locally:

```sh
cargo xtask pages-stage --list
cargo xtask pages-stage --check
cargo xtask pages-stage target/pages-site
```

`--check` (also part of `cargo xtask docs-site --check`) fails when a published page links to, or redirects to, a local file that is not published, or when `sitemap.xml` names one. A new top-level page or file needs an entry in the list; otherwise its links fail this check and it is not deployed. The repository stays public, so this keeps internal files off the website, not out of view.

**One-time switch from branch publishing (maintainer, admin access).** Until the source is switched, `pages.yml` runs but its `deploy` job cannot publish, so switch right after the workflow lands on `main`:

1. **Settings → Pages → Build and deployment → Source:** choose **GitHub Actions**. GitHub creates the `github-pages` environment, limited to `main`.
2. **Actions → Pages → Run workflow** on `main`, and wait for the `deploy` job.
3. Check that `/`, `/faq.html`, `/open-pzfx-files.html`, `/privacy.html`, `/sitemap.xml`, `/llms.txt`, `/llms-full.txt`, `/manual/`, `/manual/latest/get-started.html`, and the redirect pages return `200`, and that internal files such as `/ROADMAP.md`, `/pitfalls.md`, `/reference/concepts.md`, and `/schemas/preferences.schema.json` return `404`.

Relative asset and page paths (`site.css`, `images/*.png`, `privacy.html`, `manual/index.html`, `index.html`) support deployment below `/curvebook/` or at a domain root. Verify cross-page links (`index.html` ↔ `privacy.html` ↔ `manual/index.html` and generated manual internal `#fragment` links), keyboard focus, WCAG AA text contrast, `@media (forced-colors: active)`, `@media print`, zero external browser network requests, and responsive (`1280px` / `850px` / `700px` / `390px` / `320px`) layouts without horizontal overflow, then run the full gate suite:
