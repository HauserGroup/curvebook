# CurveBook Roadmap

Claimable engineering roadmap for **CurveBook**. For current verified capabilities, test evidence, and known limits, see [`STATUS.md`](STATUS.md). Find completed items and their verification records in the [archive index](#completed-roadmap-items). See [Roadmap History](history/roadmap.md) for earlier sequencing and wave-by-wave progress.

**Baseline:** Rust `1.99.1` (`edition = "2024"`, [`R0.18`](history/roadmap/r0.md#r018-upgrade-the-workspace-and-build-toolchains-to-rust-1991)), the [`R0.20`](history/roadmap/r0.md#r020-rename-lumencraft-to-curvebook) CurveBook cutover, the [`v0.1.0-alpha.1`](https://github.com/HauserGroup/curvebook/releases/tag/v0.1.0-alpha.1) MCP Alpha prerelease, the [`R15`](history/roadmap/r15.md#r15-modern-egui-desktop-gui-overhaul-beta-gate) (`R15.1`–`R15.10`) declarative `egui 0.37` desktop GUI cutover, and [`R10.25`](history/roadmap/r10.md#r1025-automated-gui-completion-of-all-65-workflows-beta-gate) (`65 / 65` five-stage desktop GUI workflow completion) are **done** locally. Active items below track remaining hosted **Beta** release checks, post-Beta interoperability polish (`R17`), and **1.0** full-release work (`R8`, `R10`, `R11`, `R12`).

## How to use this file

1. **Pick the next item** from [Order and dependencies](#order-and-dependencies) whose dependencies are `done` and whose gate matches the current release target.
2. **Claim before branching:** mark the item `Status: in progress — claimed: <handle>, branch <branch-name>` (and later `— in PR #n`) in a small claim commit or PR, and read [`AGENTS.md`](../AGENTS.md), [`pitfalls.md`](pitfalls.md), and [`extending.md`](extending.md) before writing code.
3. **One item per PR:** keep pull requests scoped to a single `R<m>.<n>` item, use branch prefixes `feature/`, `bugfix/`, `hotfix/`, `refactor/`, `docs/`, `test/`, `chore/`, or `audit/` with the roadmap ID, and end squash PR titles with `(R<m>.<n>)`. Fixes for reported GitHub issues outside planned work use `bugfix/issue-<N>-<slug>` and `Fixes #<N>` instead ([`AGENTS.md`](../AGENTS.md) › Git Workflow).
4. **Metadata & checkboxes:**
   - Every item header has the form `### R<m>.<n> <title>` followed by `Owner: maintainers|open · Status: todo|in progress|blocked (why)|done|merged into R<m>.<n> (<date>)|dropped (<date>, why) · Was: <old IDs / notes>`.
   - `- [ ]` lines track concrete pending sub-tasks (surfaced by `cargo xtask pending` under `R0.4`). Mark them `- [x]` only after verification passes.
   - After marking an item `done`, move it to its milestone file in [Roadmap History](history/roadmap.md) and add a direct link in the [archive index](#completed-roadmap-items). Preserve its ID and verification evidence, and update links to the item.
   - When items are merged or dropped, move each to its milestone file in [Roadmap History](history/roadmap.md) with the matching status. Keep its `[x]` lines and decisions, delete its open `[ ]` lines (they now live in the new item, tagged `(from R<old>)`), and list it in the [archive index](#completed-roadmap-items) with the suffix *(merged)* or *(dropped)*.
   - Hour estimates are single-agent implementation estimates (notes only, excluding human review).
5. **Unique table keys:** every Markdown table in `docs/ROADMAP.md` and `docs/STATUS.md` MUST have unique values in Column 1 (`cargo xtask status` enforces this to catch silent merge-conflict duplicates).

## Architecture rules for new work

All roadmap work follows [`AGENTS.md`](../AGENTS.md) §3 (headless-first `L0`–`L5` engine mutations, declarative seam registration per [`extending.md`](extending.md), structured `EngineError`/`DocError`/`FormatError` returns, versioned files with forward-refusal per [`file-formats.md`](file-formats.md), and atomic writes/bounded subprocesses via `curvebook-platform`).

## R11 Usable browser app

**Why this milestone exists.** A 2026-11-17 code audit of `apps/curvebook-web` (code reading only, no browser run) found that the browser evidence behind [`R8.4`](history/roadmap/r8.md#r84-live-wasm32-unknown-unknown-trunk-webgpuwebgl2-browser-hosting), [`R10.7`](history/roadmap/r10.md#r107-web-menu-bar-toolbar--chrome-parity-b4-web), and the web part of [`R10.13`](#r1013-human-operable-50-workflow-acceptance--manual-qa) consists of **native** tests of the Rust host logic. No test executes in a real browser yet (`cargo xtask wasm` runs `wasm32` `check`, `clippy -D warnings`, and `trunk build` on demand; see `R11.1`), and `apps/curvebook-web` currently serves a strict-CSP placeholder until `R11.11` migrates it to `eframe::WebRunner`. Both the desktop (`R10.13`, `R10.24`) and browser (`R11.10`) walkthroughs target the `1.0` full release. The browser app is not a Beta requirement (see the browser decision in the archived [`R0.28`](history/roadmap/r0.md#r028-rein-in-the-number-of-release-install-files)).

**Runtime architecture today.** Inline JavaScript in `apps/curvebook-web/index.html` owns every DOM listener and sends JSON events to `WebBridgeSession::handle_event` (`apps/curvebook-web/src/host_adapters.rs`). Rust rasterises a full RGBA frame per event, base64-encodes it into the JSON reply, and JavaScript uploads it as a WebGL2 texture. There is no `requestAnimationFrame` loop and no worker, so analyses and fits run on the main thread.

| Gap area | Finding (2026-11-17) | Item |
|---|---|---|
| Browser evidence | No `wasm-bindgen-test`, browser automation, or browser QA; the web bundle size budget is checked only when a zip already exists locally (`check_web_bundle_readiness` in `xtask/src/web_fonts.rs`), not in CI or `release.yml` | `R11.1`, `R11.10` |

| Document lifecycle | No save-in-place (every save downloads or asks "Save as"); export does not mark the document clean; opened `.curvebook.d/` folders are never written back (no `SyncDirectory` sender); one shared `"default"` autosave slot with silent restore and no stale-snapshot clearing; wasm timestamps read `unix:0` | `R11.5` |

It may also describe a desktop GUI path once a passing human-path test covers it: a five-stage `WorkflowRun` test ([`R10.25`](history/roadmap/r10.md#r1025-automated-gui-completion-of-all-65-workflows-beta-gate)) or an import/export test ([`R10.30`](#r1030-human-path-tests-for-import-and-export-beta-gate)), with native dialogs stubbed at the host boundary. **File-format naming (`.pzfx files` and `.prism files`):** All user-facing documentation (landing pages, FAQ, manual reference pages, workflow guides, tutorials, and GUI copy) should prefer `".pzfx files"` and `".prism files"` naming where appropriate rather than opaque euphemisms such as `"External Archive"` or `"XML Project"`.
