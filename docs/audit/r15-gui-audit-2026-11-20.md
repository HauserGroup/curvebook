### Finding details

#### R15-GUI-01 — Hand-rolled calendar arithmetic (High, policy)

`is_leap_year`, `days_in_month` and `step_iso_date` (`info_view.rs:728–768`) implement Gregorian leap-year rules and month rollover by hand to validate and step `Date` constants in the InfoSheet.

- **Rule broken:** `AGENTS.md` §1 "Pure Rust, `wasm32` Clean Core, and No `chrono`", item 3: "never hand-roll Gregorian leap-year/calendar arithmetic."
- **Also wrong at the edges:** stepping past `9999-12-31` yields `10000-01-01` and stepping before `0001-01-01` yields `0000-12-31`; both strings fail `is_valid_iso_date` on the next edit. `"+123-01-01"` passes validation because `"+123".parse::<i32>()` succeeds.
- **Fix direction:** validate and step dates through an existing workspace helper (or `curvebook-platform`) rather than in the view, or drop the stepper and keep strict text validation.

#### R15-GUI-02 — Partial batch commit leaves views and recovery journal stale (Medium)

`PendingUiIntents::commit_if_settled` takes the whole queue and applies intents in order with `?` (`mod.rs:1619–1621`). If intent *k* fails, intents `0..k` have already executed (`Session::execute_as_ui` mutates and pushes undo), intents after *k* are dropped, and `app.sync_views()` / `sync_history_with_document` (`:1622–1623`) are skipped. The desktop caller (`gui_window.rs:593–611`) then only sets `status_banner`; it skips `record_ui_mutation_checkpoint`, so no recovery-journal checkpoint or `dirty_commands` label is recorded for the mutations that did land, and skips `notify_preferences_changed` and `pending_unsaved_action`.

- **Scenario:** one frame queues `table.setCells` (succeeds) followed by a `ui.*` command that fails validation (or a `SetShortcutBinding` conflict, which returns `Err` by design at `:2235`). The document is mutated, the grid/inspector caches show the old state until something else syncs, and a crash before the next successful commit loses the edit from crash recovery.
- **Fix direction:** on error, still run `sync_views`/history sync and have the host run `record_ui_mutation_checkpoint` whenever `mutation_seq` moved, regardless of the batch result; return per-intent outcomes rather than short-circuiting.

#### R15-GUI-03 — Live "Model Formula" omits interaction terms (Medium)

`build_live_symbolic_formula` (`stats_modals.rs:1515–1530`) appends only `terms[0]:terms[1]` for order ≥ 2 and only `terms[0]:terms[1]:terms[2]` for order ≥ 3. The engine builds every combination up to the order (`crates/stats/src/anova/sheet/one_way.rs:523–526`, `collect_index_combinations`).

- **Scenario:** three factors A, B, C with `max_interaction_order = 2`. The bar shows `Y ~ A + B + C + A:B`; the fitted model is `A + B + C + A:B + A:C + B:C`. With four factors, the bar omits even more terms. The user is shown a model that is not the one being fitted.
- **Fix direction:** generate all k-subsets up to the order, as the engine does, or ask the engine for the term list.

#### R15-GUI-04 — Unbounded raster threads; `thread::spawn` can panic (Medium)

`composite_async_scene_texture` spawns a new OS thread every time `RasterRequestKey` changes (`canvas_view.rs:427–448`). The key includes `width_px`, `height_px`, `dpi` and `mutation_seq`, so a window-resize drag, a zoom drag, or rapid edits each start another full render (up to 4,096 × 4,096 px) without cancelling or joining the superseded jobs.

- **Scenario:** dragging the window edge across 200 px produces dozens of concurrent full-page renders and their RGBA buffers. `std::thread::spawn` panics if the OS refuses a new thread, which breaks "CurveBook Never Crashes" (`AGENTS.md` §1; `panic` paths in shipped code).
- **Fix direction:** one long-lived worker (or `std::thread::Builder::spawn` with error handling) fed by a latest-request slot, so superseded keys are dropped before rendering.

#### R15-GUI-05 — Intents from discarded passes are lost (Medium)

egui 0.37 passes input only to the first pass of a frame (`Context::run_ui` calls `begin_pass(new_input.take())`, and `RawInput::take` moves `events` and `dropped_files`). CurveBook drops every intent queued in a pass that ends with `will_discard()` (`mod.rs:1615`, `gui_window.rs:536–540`, `lib.rs:1490–1515`). So a click, key or text commit handled in a pass that egui then discards is never applied, and it is not replayed in the next pass.

- **Who discards:** egui itself on a new `Grid` (`grid.rs:468`, used in `stats_modals.rs:2032/2142/3733`, `fit_modal.rs:416`, `import_wizard.rs:1124`, `power_studio.rs:846`), `Resize` sizing passes and `Aligned` size changes, plus `data_grid.rs:332`. The grid guard checks `intents.is_empty()` only for intents queued *before* the grid; widgets rendered later in the same pass (footer, studio rail, modals) can still queue intents that are then dropped.
- **Scenario:** a modal tab click both sets local `state.active_tab` and queues `push_set_edit_params_active_tab`; the newly shown tab contains a first-time `Grid`, egui discards, and the app-level `edit_params.active_tab` keeps its old value while the view shows the new tab.
- **More instances (tranche 4):** `unit_spinners.rs` gates local state changes on `settled_frame`: a unit-badge click (`:370`), Escape in the text editor (`:228–231`) and drag end (`:600–603`) are ignored in a discarded pass. Because egui reports `clicked()`/`drag_stopped()` only in the first pass, a discarded drag end leaves `state.dragging = true`, so the field keeps showing the drag value and stops syncing to the model. The same pattern appears in `inspect_bridge.rs:590–618` (offscreen driver).
- **Fix direction:** keep intents from the first pass of a frame (where input was delivered) and de-duplicate across passes, instead of discarding them; or have widgets queue only from the pass that saw the input.

#### R15-GUI-06 — Empty-column range panic in quick stats (Low, latent)

`scan_dataset_col_range` computes `hi = r_end_incl.min(rows.len().saturating_sub(1))`; for an empty `rows` that is `0`, so `r0 = 0` passes `r0 > hi` and `&rows[0..=0]` panics (`status_footer.rs:331–339`; same shape for `MultipleVariables` at `:396–401`). Today the document invariant (every column has `row_count()` cells) keeps it unreachable, but this footer runs on every selection change, so any invariant slip (import, migration, a ragged foreign-format file) crashes the GUI.

- **Fix direction:** `rows.get(r0..=hi)` with an early return.

#### R15-GUI-07 — Duplicated host-routed command lists (Low, reuse)

`top_chrome::is_desktop_host_routed_command` (`top_chrome.rs:810–833`) and `gui_window::is_host_routed_intent_command` (`gui_window.rs:1237–1260`), plus `desktop_host::resolve_host_or_ui_route`, each hold their own list. They already differ (`edit.copy` is only in the `gui_window` list). Adding a host command to one list and not the others silently sends it to the engine as an unknown command.

- **Fix direction:** one `pub` list (or a flag on `UiCommandSpec`) consumed by all three.

#### R15-GUI-08 — Local suppressions of a denied lint (Low, conventions)

`Cargo.toml` `[workspace.lints.clippy]` sets `too_many_arguments = "deny"`. R15 raised the count of local `#[allow(clippy::too_many_arguments)]` in `crates/ui-egui/src` and `apps/curvebook/src` from 30 to 114, most in `egui_shell/` (for example `center_stage.rs` has 10). `AGENTS.md` "Done Means" requires checks to pass "without … suppressed warnings".

- **Fix direction:** group render parameters into context structs (the code already has `ColumnGridRenderContext` as a model).

#### R15-GUI-09 — Standalone transform always transforms Y (High, wrong result)

In the standalone (Data → Transform) path, the displayed Y choice is `standalone_y_preset.and_then(parse_math_slug).or(Some(Log10))` (`transform_modals.rs:262`) and the command is built with `standalone_y_preset.as_deref().unwrap_or("log10")` (`:1001`). Clicking Y "None" stores `None` (`:397`), so both the display and the executed command fall back to `log10`.

- **Scenario:** the common pharmacology workflow — switch to "Pharmacology (-log10[M])" to convert X concentrations and leave Y alone. The user clicks Y "None", the pill stays on `log10(Y)`, and OK runs `transform.run` with `y_transform: "log10"`. The new sheet holds log-transformed responses the user did not ask for.
- **Related display bug:** standalone `Y + K`, `Y * K`, `Y / K` store the slugs `affine_k`/`multiply_k`/`divide_k`, which `parse_math_slug` does not know, so the pills show `log10(Y)` as active even though OK sends the linear transform.
- **Fix direction:** keep an explicit "no Y transform" state (`Option<Option<…>>` or a `"none"` slug) and drop the `log10` fallbacks; map the K slugs in the display.

#### R15-GUI-10 — Transform Values controls with no effect (Medium)

- `zero_conc_sub_draft` ("Zero X substitution", `:335`) and `create_new_graph` ("Create new graph of transformed results", `:458`) are rendered and recorded for inspection, but nothing reads them when building `transform.run` or the edit draft (only references are the field, the widget and the inspect node).
- In edit mode, `Y + K` / `Y * K` / `Y / K` read `constant_k_draft` once, when the pill is clicked (`:362–378`). Typing K afterwards does not update the draft, so clicking `Y * K` and then entering `2` saves `slope = 1` (a no-op). The standalone path reads K at OK time instead, so the two paths disagree.
- `Y / K` with K = 0 silently becomes slope 1 (`:374`, `:1013`) instead of a validation error; empty K silently means 0 (add) or 1 (multiply/divide).
- **Fix direction:** wire or remove the two dead controls; build the LinearScale preset from K at commit time in both paths; reject K = 0 for division through `validation_error`.

#### R15-GUI-11 — Multi-line X entry lands in the Y data set (Medium)

`commit_aux_inline_edit` for `AuxInlineTarget::XCell` sends text containing a tab or newline to `table.paste` with `start_col: 0, start_subcol: 0` (`data_grid.rs:2593–2606`). `table.paste` anchors on data coordinates, and for XY tables `CellCoord` column 0 is `data_sets[0]` (`crates/doc/src/archetypes.rs:1918`, `crates/format/src/csv.rs:1416`), not the X column. The X subcolumn index is also dropped.

- **Scenario:** in an XY table the user types or pastes `1\n2\n3` into X row 0. The three values overwrite Y data set A rows 0–2; the X column is unchanged. Undo recovers it, but the edit is silent.
- **Fix direction:** split the text and send `table.setXCells` with `edits`, or add an X target to `table.paste`.

#### R15-GUI-12 — Clipboard shortcuts ignore the X-cell selection (Medium)

Clicking an X cell sets `aux.selected_x_cell` but leaves `app.grid.tool` (the Y selection) untouched (`data_grid.rs:1952–1956`), and both stay highlighted. `Cmd/Ctrl+C`, `+X`, `+V` always use the Y selection (`:2846–2863`), while Delete and Cmd+E correctly prefer the X cell (`:2830`, `:2866`).

- **Scenario:** select Y cells B2:B5, then click X row 3 and press Cmd+X. B2:B5 are cut and cleared; the X cell the user is looking at is untouched. Cmd+V likewise pastes at the old Y anchor.
- **Fix direction:** clear the Y selection when an X cell is selected (and vice versa), and route clipboard shortcuts through the same X-first branch as Delete.

#### R15-GUI-13 — Welcome Hub "Open" path is ignored on desktop (Medium)

With a typed path, the Welcome Hub queues `push_engine("project.open", {"path": …})` (`welcome_hub.rs:1575`). The desktop frame loop treats `project.open` as host-routed (`gui_window.rs:555–556`, list at `:1237`) and keeps only the command id, so `execute_menu_command("project.open")` opens the native file picker and the typed path is discarded. On hosts that do not reroute (headless/egui control path, `lib.rs:1512`), the same intent runs `project.open` directly through `Session::execute`, replacing the document without the unsaved-changes prompt (`project.open` carries `MAY_DISCARD_DATA`).

- **Fix direction:** carry params on host-routed intents (or add a host `OpenPath` intent) and go through the same dirty-document check as File → Open.

#### R15-GUI-14 — Wrong project extension in the Welcome Hub (Low)

The Open pane says "Open a .cbk project or .cbtemplate file path." with placeholder `/path/to/project.cbk`, and the mode label reads "Open existing .cbk workspace" (`welcome_hub.rs:1363`, `:1370`, `:1426`). No `.cbk` format exists; projects are `.curvebook` / `.curvebook.d/` (`docs/file-formats.md`). These strings are also hardcoded English rather than i18n keys.

#### R15-GUI-15 — Format Axes drops out-of-placeholder bounds silently (Low)

`render_axis_segments_section` shows an auto (`None`) minimum as `0` and maximum as `100` (`graph_modals.rs:2386–2387`) and only commits a new min if `val < cur_max` and a new max if `cur_min < val` (`:2398`, `:2412`), comparing against those placeholders. Setting min = 150 on an auto-ranged axis whose data reach 1,000 is silently ignored, with no message. The spinner range is also hard-capped at ±1e9.

#### R15-GUI-16 — Fit X-domain filter fixed at [0, 100] (Medium, wrong result)

Ticking "Restrict fit to X domain filter" sets `x_range_filter = Some((Some(0.0), Some(100.0)))` (`fit_modal.rs:978`). No control in the fit modal (or elsewhere in `egui_shell/`) edits those bounds; the only other reference is the min ≥ max alert (`:350`).
- **Scenario:** a dose–response fit on log10[M] X values (−9 to −4). Ticking the box excludes every point, so the fit fails; on X data spanning 0–1,000 it silently fits only the first part of the curve.
- **Fix direction:** add min/max inputs (seeded from the data range) and validate them before enabling the filter.

#### R15-GUI-17 — Initial values and bounds cannot be set meaningfully (Medium)

- "Auto (…)" shows `get_builtin_model(..).initial_guess(&[])` (`:918`), a guess computed from no data, so it differs from the data-driven guess the fit actually uses.
- The only override is a ±0.5 stepper starting from that number (`:943–950`); there is no text entry. Reaching an EC50 of `1e-7` is impossible, and values are shown as `{:.3}`, so small values display as `0.000`.
- `ParameterRule.lower_bound` / `upper_bound` are honoured by alerts (`:370–385`) but have no editor in the Constrain tab (`:803–906`).
- **Fix direction:** numeric text fields (locale-aware) for initial values and bounds; compute "Auto" from the analysed data or label it as a model default.

#### R15-GUI-18 — Command palette sends commands without parameters (Medium)

`commit_palette_row` queues `push_engine(command_id, {})` for every engine command (`command_palette.rs:407–414`). Rows are enabled from the registry `enabled` predicate (`:62`), which checks document state (for example "a graph sheet exists"), not that the command can run without parameters. `apply_single_ui_intent` fills in `sheet_id` for only five `sheet.*` commands (`mod.rs:1649`).

- **Scenario:** Cmd+K → "Update Graph Specification" (`graph.setSpec`) or "Rename Sheet" is enabled, but runs with `{}` and fails with a missing-`sheet_id` error. Under R15-GUI-02, that failure also drops any intents queued after it in the frame.
- **Fix direction:** route parameterised commands to their dialog (as the menus do via `resolve_host_or_ui_route`) or fill the active sheet; hide rows that cannot run.

#### R15-GUI-19 — Shell grid copy/cut: truncation and over-clearing (Medium)

`execute_grid_clipboard_copy` (`mod.rs:2055–2098`) builds its range from `app.grid.all_selected_coords(ds)`, which is capped at `MAX_MATERIALIZED_SELECTION_COORDS = 4,096` (`grid_view.rs:22`, `:1552–1572`), then takes the bounding box of those coordinates.

- **Truncation:** a 2-column × 10,000-row selection copies only the first 2,048 rows; Cut clears only those rows. No message.
- **Over-clearing:** for a discontiguous Cmd-click selection (A1 and C5), Cut clears the whole A1:C5 rectangle (15 cells, including 13 the user never selected).
- **Reach:** used by the headless/egui control paths and `WorkspaceCopy` fallbacks; the desktop host has its own copy/cut (`desktop_host.rs:2872`, `:2984`) based on `selection_bounds`, so the two hosts behave differently (compare R15-GUI-07).
- **Fix direction:** one shared copy/cut helper using the uncapped selection bounds for rectangles and per-cell clears for discontiguous selections.

#### R15-GUI-20 — Import wizard target can be its own source (Medium)

`ImportPasteWizardState.source_sheet_id` is the link **source** for internal-sheet origins (`grid_view.rs:1056`, `import_wizard.rs:327–330`), but `UiIntent::OpenImportWizard` (`mod.rs:1974–1981`) and the desktop openers (`desktop_host.rs:3913`, `:3920`) store the **target** sheet in it. On commit (`mod.rs:1987–2000`), the target is the active data sheet, falling back to `source_sheet_id`.

- **Scenario A:** Paste Link opened for target B while sheet A is active — the import lands in A.
- **Scenario B:** the user picks data sheet A as the link source while a graph is active — the target falls back to A, so A is overwritten by (or live-linked to) itself.
- **Fix direction:** separate `target_sheet_id` from `source_sheet_id` and commit to the explicit target.

#### R15-GUI-21 — Unit edits rename variables used in formulas (Medium, plausible)

Manage Variables splits a title like `Dose (mg/kg)` into name and unit (`manage_vars_modal.rs:87–98`) and saves `combine_title_and_unit` through `table.setTitles` (`:387–389`). Units are not a separate field, so adding a unit to `Dose` renames the variable to `Dose (mg/kg)`. Calculated variables refer to columns by `[Title]` (`crates/doc/src/archetypes.rs:1376`, lookup by exact trimmed title in `find_variable`), and no reference rewriting on rename was found in the engine.

- **Scenario:** `Ratio = [Dose] / [Weight]`; the user adds unit `mg/kg` to Dose; the next recalculation cannot resolve `[Dose]`.
- **Status:** plausible — formula evaluation after rename was not executed in this audit.

#### R15-GUI-22 — Locale-unaware number parsing for Info constants (Low)

InfoSheet validation and commit use `str::parse::<f64>` (`info_view.rs:713`, `:779–780`), as does the studio's Info panel (`trailing_studio.rs:1460`). The grid uses `parse_localized_number_input`. In comma-decimal locales, `1,5` is rejected as a Number in the InfoSheet, and the studio stores it as the text `"1,5"` with `kind: "number"`, so hooked constants cannot use it.

- **Tranche 4 additions:** the heatmap colour-range fields (`graph_modals.rs:647`) and additional-tick values (`:2785`, `:2791`) use the same parser. For the heatmap, a value that fails to parse, or min ≥ max, silently falls back to automatic range (`None`) with no message.

#### R15-GUI-23 — EMF export from the Export dialog saves nothing (Medium)

With "EMF" selected, the Export dialog's commit queues `push_engine("graph.exportEmf" | "layout.exportEmf", {"sheet_id": …})` and closes all modals (`app_modals.rs:1298–1301`). The engine writes a file only when `path` is given; otherwise it returns base64 bytes (`crates/engine/src/cmd/export.rs:808–813`). The desktop frame loop does not host-route these IDs (`gui_window.rs:1237–1260`), and `commit_if_settled` discards the outcome, so the EMF is rendered and thrown away. The desktop host already has a native-save spec for both commands (`desktop_host.rs:1472–1484`); this path does not use it.

- **Scenario:** Export Figure → EMF → Export. The dialog closes as if it succeeded; no file dialog appears and nothing is written.
- **Fix direction:** route EMF through the same host save path as SVG/PDF/PNG (add the IDs to the host-routed list, see R15-GUI-07) or through the dialog's OK action.

#### R15-GUI-24 — Format Axes re-applies a stale frame preset (Medium)

`sync_format_axes_local_drafts` refreshes `format_axes_frame_preset` (and the other local drafts) only when the graph sheet or target axis changes (`graph_modals.rs:2073–2085`). OK always sends `graph.setAxes {frame_preset: state.format_axes_frame_preset}` (`:685–691`).

- **Scenario A:** open Format Axes on graph G, pick a different frame, Cancel. Reopen Format Axes on G (same axis): the cancelled choice is still selected, and OK applies it.
- **Scenario B:** after closing Format Axes, change G's frame from the studio rail (`trailing_studio.rs:2219`) or undo a frame change; reopen Format Axes on G and press OK for an unrelated edit — the old preset overwrites the newer one.
- **Fix direction:** re-sync local drafts whenever the dialog opens (or on Cancel), and send `frame_preset` only when the user changed it.

#### R15-GUI-25 — Preferences settings that go nowhere (Low)

- `PreferencesModalState.default_palette`, `default_error_bar`, `default_unit` and `default_show_en_dash` (`app_modals.rs:91–104`) are edited in the Preferences dialog, but nothing outside `app_modals.rs` reads them, and `ClosePreferences { save: true }` (`mod.rs:2219–2228`) persists only `ui_scale`. They reset on the next launch and never affect new graphs.
- Shortcut changes (`SetShortcutBinding`, `ResetShortcutBinding`, `mod.rs:2229–2250`) are applied immediately rather than on OK, so Cancel does not undo them; Cancel also leaves the edited draft in place for the next open.

#### R15-GUI-26 — Unreachable Recovery dialog (Low)

`render_recovery_modal` (`app_modals.rs:343–455`) is shown only when `UiIntent::OpenRecoveryDialog` sets `recovery_open` (`mod.rs:2254–2257`), and nothing in `crates/ui-egui/src` or `apps/curvebook/src` queues that intent. The chosen `RecoveryDecision` is stored in `last_recovery_decision` (`mod.rs:2258–2261`) and never read. Startup crash recovery restores automatically in `open_startup_session_with_recovery` (`apps/curvebook/src/main.rs:464–467`). The dialog is dead code. If it is ever wired up as it stands, "Discard Recovery" would not discard anything.

#### R15-GUI-27 — "Add constant" can overwrite an existing constant (Medium)

The InfoSheet "+" button sends `info.setConstant {name: "Constant {len+1}", value: ""}` (`info_view.rs:409–412`). `info.setConstant` is an upsert keyed on a case-insensitive name (`crates/doc/src/info.rs:124–136`), and the GUI does not pass `if_exists`.

- **Scenario:** constants `Constant 1`, `Constant 2`, `Constant 3`; delete `Constant 1` (count is now 2) and click "+". The new name is `Constant 3`, so the existing `Constant 3` value is replaced with empty. Any fit parameter or transform hooked to it loses its value. Undo recovers it, but nothing warns the user.
- **Fix direction:** pick the first unused `Constant N`, or send `if_exists: false` and surface the conflict.

#### R15-GUI-28 — Additional ticks bypass the dialog's OK/Cancel (Low)

In Format Axes → Additional Ticks, "Add" queues `graph.setAdditionalTicks` straight away (`graph_modals.rs:2818–2820`, via `push_additional_ticks_update` at `:2831`). The same action stages threshold lines and shaded zones only in the dialog draft, which is applied on OK. Cancelling the dialog therefore keeps the new ticks but drops the new thresholds.

| Medium | 17 | R15-GUI-02 to 05, 10 to 13, 16 to 21, 23, 24, 27 |
| Low | 9 | R15-GUI-06 to 08, 14, 15, 22, 25, 26, 28 |

Three themes account for most findings:

1. **Intent pipeline:** R15-GUI-02 (a failing intent aborts the batch without view sync or journal checkpoint) and R15-GUI-05 (intents and widget state from discarded egui passes are lost). These are shared by every view and should be fixed first; several other findings get worse because of them (R15-GUI-07, 18).
2. **Dialogs whose controls do not reach the model, or reach it with fixed or stale values:** R15-GUI-09, 10, 15, 16, 17, 23, 24, 25, 26, 28.
3. **Duplicated host/shell logic that has drifted apart:** R15-GUI-07 (host-routed command lists), 13 (Welcome open path), 19 (two copy/cut implementations), 20 (import wizard source/target).

Several findings mean the GUI produces wrong scientific output without telling the user (R15-GUI-03, 09, 11, 16). They deserve regression tests through the `EguiHumanPathDriver`, not only engine-level tests.
