# Roadmap maintainability audit

Initial source baseline: `main` at `49c7a303db0dc69dd0b56fcb2a9b16835c656f29`. The release roadmap and its archived milestones supply the review order. Findings cover code present in this checkout and belong to the milestone that introduced or owns the relevant seam. Follow-ups record their own baseline. Source links are relative to this directory and point to the reviewed locations in the current checkout.

This source review looks for custom implementations of general-purpose machinery, repeated ownership of a rule, and simplifications that fit within an existing subsystem. Entries are proposals. Numerical fidelity and runtime acceptance remain covered by their existing gates and audits. GitHub issue and PR listings were unavailable from this checkout, so the review used the local roadmap, worktree and branch inventory, and audit records. The pass combined a workspace-wide search for custom implementations and repeated Rust function bodies with targeted reads of callers and tests. Dependency candidates were checked against the local lockfile or cached manifests.

Good first changes are R0-1, R2-3, R3-2 and R16-1. They remove a redundant parser, an eight-archetype row-shift copy, a duplicate Welch calculation, and a set of dense matrix clones. The format and documentation parser substitutions have a wider compatibility surface.

## R0 · House rules, registries and tooling

**R0-1 · Replace xtask's JSON parser with its existing dependency.** `xtask` maintains a JSON value type and parser for Cargo metadata, coverage reports, dependency licence data, and contributor cache data. The same binary already depends on `serde_json` and uses it for schemas. Move the readers to `serde_json::Value` and `from_slice` or `from_str`. Keep contextual errors and the integer-only coverage counts through `as_u64`. This removes a grammar, Unicode escape handling, and their maintenance without adding a dependency. [Parser](../../xtask/src/json.rs#L1) · [Metadata loader](../../xtask/src/main.rs#L182) · [Coverage reader](../../xtask/src/coverage.rs#L148) · [Existing schema code](../../xtask/src/schemas.rs#L25)

**R0-2 · Feed both quick-CI selectors from one Cargo metadata snapshot.** The quick tier runs Cargo metadata twice. It reads package directories from the workspace-only snapshot and the dependency graph from the resolved snapshot. The resolved response already carries workspace membership, the root, and manifest paths. Pass that snapshot to both consumers and restrict directory ownership to workspace members by package ID. Keep the workspace-only helper for independent callers that need only that view. [Quick tier setup](../../xtask/src/ci_quick.rs#L54) · [Directory selector](../../xtask/src/ci_quick.rs#L146) · [Layer graph reader](../../xtask/src/layers.rs#L232)

**R0-3 · Copy the existing UI catalogue module as a whole.** The generator searches Rust source for two declaration names, backtracks over doc comments and attributes, then copies up to the first `];`. The source module already contains only the spec and its table. Keep it data-only and have the generator prepend its banner to the whole file. This preserves the UI-to-MCP layering and generated public shape while removing the source-fragment parser. Keep the formatting and generated-file sync check. [Source table](../../crates/ui-egui/src/menus/ui_commands.rs#L1) · [Fragment parser](../../xtask/src/ui_commands.rs#L40)

**R0-4 · Share the text decoding primitives used by the policy gates.** The brands and clean-room gates maintain identical UTF-16 endianness detection and lossy decoding functions. Move that pair into a private xtask module and preserve each gate's decision about when to invoke it. This leaves one copy of the detection thresholds and replacement-character handling. [Brands gate](../../xtask/src/brands.rs#L310) · [Clean-room gate](../../xtask/src/cleanroom.rs#L270)
