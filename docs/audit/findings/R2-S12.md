### R2-S12-01 · S1 · `--control-port` MCP attachment neither queries nor propagates `--gui-only` policy on the desktop host

- **Base:** fda1cc0106092834d97b53289ec2a99c1bf0439c
- **Location:** `crates/mcp/src/tools.rs:137-141`, `crates/mcp/src/tools.rs:322-329`, and `apps/lumencraft-cli/src/main.rs:157` at that base (introduced in `461ad33`)
- **Category:** security
- **Defect:** `McpServerState::with_control_port_and_gui_only` and `set_gui_only` never inspect or synchronize the remote desktop control server's `gui_only` state (even though control `ping` already reports `"gui_only": app.is_gui_only()`), allowing bidirectional `--gui-only` policy bypass and desynchronization.
- **Failure scenario:**
  1. Start a confined desktop session with `lumencraft --control 49152 --gui-only` and attach MCP via `lumencraft-cli mcp --control-port 49152` (omitting `--gui-only`): `state.is_gui_only()` stays `false`, so `tools/list` exposes the 10 headless tools and `open_file`, `save_file`, `export`, and `resources/read` execute unimpeded against the host filesystem via `state.session` (`GuiOnlyPolicy::Disabled`), while calling `enable_toolset { "group": "gui" }` simultaneously enables the 8 GUI tools to drive the `--gui-only` host.
  2. Conversely, start `lumencraft --control 49152` (without `--gui-only`) and attach `lumencraft-cli mcp --control-port 49152 --gui-only`: `set_gui_only(true)` only updates `self.gui_host` (`None`), leaving the remote `UiApp` with `gui_only == false` (`ui_inspect` reports `"gui_only": false`, and direct `ui.screenshot` `path` writes remain unblocked on the remote host).
- **Evidence:**
  ```rust
  // crates/mcp/src/tools.rs:137-141, 322-329
  pub fn with_control_port_and_gui_only(port: u16, gui_only: bool) -> Result<Self, String> {
      let mut state = Self::with_control_port(port)?;
      state.set_gui_only(gui_only);
      Ok(state)
  }
  ...
  pub fn set_gui_only(&mut self, gui_only: bool) {
      self.gui_only = gui_only;
      let policy = if gui_only { GuiOnlyPolicy::Strict } else { GuiOnlyPolicy::Disabled };
      self.session.set_gui_only(policy);
      if let Some(host) = self.gui_host.as_mut() {
          host.set_gui_only(gui_only);
      }
  }
  ```
- **Suggested fix:** On `set_control_port` / `with_control_port*` (or lazily on `initialize` / first tool dispatch), handshake with `{"method":"ping"}` on `control_port` and enforce `remote_gui_only || local_gui_only` (failing closed if `local_gui_only && !remote_gui_only` cannot lock the remote host or if `ping` fails).
- **Related:** `R1-S12-09`, `R2-S07-01`, `R2-S10-01`, `R2-S10-04`.

### R2-S12-02 · S1 · `is_unpacked_project_path` and `project.save` classify any existing directory (`path.is_dir()`) as `.lumencraft.d` and delete files in `<dir>/sheets/`

- **Base:** fda1cc0106092834d97b53289ec2a99c1bf0439c
- **Location:** `apps/lumencraft-cli/src/cmd_convert.rs:222-224`, `apps/lumencraft-cli/src/cmd_commands.rs:653`, and `crates/engine/src/cmd/project.rs:372, 444` at that base (introduced in `3cd144d` and `2a57609`)
- **Category:** data-loss
- **Defect:** `is_unpacked_project_path` in `cmd_convert.rs` and `use_unpacked` in `run_project_save` / `run_project_open` evaluate `has_unpacked_dir_suffix(path) || is_unpacked_project_dir(path) || path.is_dir()`, classifying **any** existing directory—even `.` or an ordinary workspace folder without `.lumencraft.d` suffix or `manifest.json`—as an unpacked `.lumencraft.d` project.
- **Failure scenario:** A user runs `lumencraft-cli convert input.csv ./workspace` (intending `./workspace/` as an output folder or making a CLI typo), `lumencraft-cli project.new --out .`, or `project.save` with `{"path": "."}` inside a directory that contains `./sheets/raw_assay.csv` or `./sheets/notes.txt`. Instead of rejecting the non-`.lumencraft.d` directory, LumenCraft writes `manifest.json` and `document.json` into the directory and permanently `std::fs::remove_file`s every regular file inside `<dir>/sheets/` not matching a current `<sheet_id>.csv`.
- **Evidence:**
  ```rust
  // apps/lumencraft-cli/src/cmd_convert.rs:222-224
  pub fn is_unpacked_project_path(path: &Path) -> bool {
      has_unpacked_dir_suffix(path) || is_unpacked_project_dir(path) || path.is_dir()
  }

  // crates/engine/src/cmd/project.rs:444
  let use_unpacked = explicit_unpacked || has_unpacked_dir_suffix(path_ref) || is_unpacked_project_dir(path_ref) || path_ref.is_dir();
  ```
- **Suggested fix:** Remove the bare `|| path.is_dir()` fallback from `is_unpacked_project_path`, `run_project_open`, and `run_project_save`: require an existing target directory to either carry the `.lumencraft.d` suffix or already pass `is_unpacked_project_dir(path)` unless `unpacked: true` (or `--to lumencraft.d`) is explicitly specified.
- **Related:** `R2-S06-01`, `R2-S06-02`.

### R2-S12-03 · S2 · MCP `ui_invoke_menu` omits `"params"`, failing every standard non-`ui.*` menu item with `expected object, got null` while allowing OS subprocess helpers under `--gui-only`

- **Base:** fda1cc0106092834d97b53289ec2a99c1bf0439c
- **Location:** `crates/mcp/src/gui_tools.rs:451-463` (with collaborating handler `crates/ui-egui/src/gui_actions.rs:1120, 1615`) at that base (introduced in `461ad33` and `8ccf0d6`)

- **Defect:** `handle_ui_invoke_menu` forwards `{ "path": ..., "command_id": ... }` without `"params"`, causing `gui_actions::handle_invoke_menu` (and `commit_command_palette_action`) to substitute `Value::Null` and fail root `"type": "object"` schema validation on every zero-argument engine menu command, while still permitting `ui.*` commands that spawn host OS clipboard/printer subprocesses under `--gui-only`.
- **Failure scenario:**
  1. Calling MCP `ui_invoke_menu` on any standard non-`ui.*` menu item—such as `{"path": ["File", "New Project"]}` (`file.new`), `{"path": ["Edit", "Undo"]}` (`edit.undo`), `{"path": ["Edit", "Redo"]}` (`edit.redo`), or `{"path": ["Analyze", "Recalculate All"]}` (`project.recalculate`)—omits `"params"`, so `params.get("params").cloned().unwrap_or(Value::Null)` passes `Value::Null` into `parse_params(&schema, Value::Null)`, failing with `bad_input: expected object, got null`.
  2. Conversely, calling MCP `ui_invoke_menu` under `--gui-only` with `{"command_id": "ui.result.copyMethodsReport"}` spawns host clipboard subprocesses (`pbcopy`/`wl-copy`/`xclip`) and `{"command_id": "ui.print.open"}` spawns `lpstat` (`discover_os_printers`).
- **Evidence:**
  ```rust
  // crates/mcp/src/gui_tools.rs:458-463
  let mut params = Map::new();
  if let Some(p) = path {
      params.insert(String::from("path"), p);
  }
  insert_opt_str(&mut params, "command_id", command_id);
  dispatch_json_result(state, "ui.invoke_menu", Value::Object(params))
  ```
  ```rust
  // crates/ui-egui/src/gui_actions.rs:1120
  let extra_params = params.get("params").cloned().unwrap_or(Value::Null);
  ```
- **Suggested fix:** Default omitted `"params"` to `json!({})` instead of `Value::Null` in `handle_invoke_menu` and `commit_command_palette_action` (while rejecting arbitrary caller-supplied `"params"` under `app.is_gui_only()` per `R2-S10-01`), and gate host OS clipboard/printer subprocess execution when `app.is_gui_only()` is active.
- **Related:** `R2-S10-01`.

### R2-S12-04 · S2 · MCP `open_file` and `save_file` probe unguarded `raw_path` on the host filesystem before `WorkdirGuard` checks containment

- **Base:** fda1cc0106092834d97b53289ec2a99c1bf0439c
- **Location:** `crates/mcp/src/formats.rs:86-95` and `crates/mcp/src/formats.rs:272-280` at that base (introduced in `3cd144d`)
- **Category:** security
- **Defect:** `handle_open_file` and `handle_save_file` invoke `resolve_importer` / `resolve_save_exporter` (`FormatRegistry::importer_for_path` / `exporter_for_path`) on `Path::new(&raw_path)` **before** calling `resolve_mcp_path(state, &raw_path)`, probing host directories and `manifest.json` files outside `workdir` and failing on relative unpacked directories inside `workdir` when process CWD differs.
- **Failure scenario:**
  1. **Pre-guard host probe & oracle:** With `McpServerState::with_workdir("/sandbox")`, calling `open_file { "path": "/outside/dir_no_ext" }` invokes `is_unpacked_project_dir("/outside/dir_no_ext")` (`crates/format/src/archive.rs:229-245`), which canonicalizes `/outside/dir_no_ext`, stats `document.json`, and reads/parses `/outside/dir_no_ext/manifest.json` before `WorkdirGuard` runs—returning `InvalidParams` (`cannot infer file format...`) if it is not an unpacked project vs `PathEscape` if it is, leaking external directory state.
  2. **Broken relative unpacked directories inside `workdir`:** If `/sandbox/my_study` is a valid unpacked project directory without a `.lumencraft.d` suffix and the server's process CWD is `/srv`, calling `open_file { "path": "my_study" }` checks `/srv/my_study` instead of `/sandbox/my_study` and fails with `cannot infer file format without extension`.
- **Evidence:**
  ```rust
  // crates/mcp/src/formats.rs:86-95
  let raw_candidate = Path::new(&raw_path);
  let reg = FormatRegistry::default_registry();
  let importer = resolve_importer(&reg, explicit_format.as_deref(), raw_candidate)?;
  let import_opts = build_import_options(raw_candidate, args)?;

  let resolved_path = match resolve_mcp_path(state, &raw_path) {
      Ok(p) => p,
      Err(err) => return Ok(errors::result_from_engine_error(&err)),
  };
  ```
- **Suggested fix:** Call `resolve_mcp_path(state, &raw_path)` first in both `handle_open_file` and `handle_save_file`, and pass `&resolved_path` (never `raw_candidate`) into `resolve_importer`, `build_import_options`, and `resolve_save_exporter`.
- **Related:** `R1-X1-04`.
