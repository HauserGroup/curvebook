### R2-S10-01 · S1 · `ui.invoke_menu` executes arbitrary engine and `UI_COMMANDS` mutations with caller `params`, bypassing `--gui-only` (`GuiOnlyPolicy::Strict`)

- **Base:** fda1cc0106092834d97b53289ec2a99c1bf0439c
- **Location:** `crates/ui-egui/src/gui_actions.rs:1100-1138`, `crates/ui-egui/src/menus/tooltips.rs:238-250`, and `crates/ui-egui/src/control_io.rs:373-381` at that base (introduced in `8ccf0d6`)
- **Category:** security
- **Defect:** `handle_invoke_menu` resolves any command ID in `cmd::registry()` (all 94 engine commands) or `UI_COMMANDS` (all 45 UI commands, which `menu_bar_tooltips` also buckets into menu sections), forwards caller-supplied `"params"`, and executes via `dispatch_ui_command_as_ui` or `app.execute_command` (`Caller::Ui`), defeating `GuiOnlyPolicy::Strict`.
- **Failure scenario:** Connected to `lumencraft --control <port> --gui-only` (`GuiOnlyPolicy::Strict`), a client sends `{"method":"ui.invoke_menu","params":{"command_id":"table.setCell","params":{"sheet_id":"d1","row":0,"col":0,"subcol":0,"value":99.0}}}`, `{"command_id":"project.save","params":{"path":"/host/out.lumencraft"}}`, `{"command_id":"table.importCsv","params":{"path":"/etc/hosts"}}`, `{"command_id":"export.pdf","params":{"sheet_id":"g1","path":"/host/fig.pdf"}}`, or `{"command_id":"ui.screenshot","params":{"path":"/host/shot.png"}}` (bypassing `handle_ui_screenshot`'s `is_gui_only()` check because `control_io::dispatch_ui_screenshot` writes `"path"` unconditionally). Even via `lumencraft-cli mcp --gui-only` (which omits `params`), `ui_invoke_menu` executes non-menu internal commands such as `ui.shortcut.reset` as `Caller::Ui`.
- **Evidence:**
  ```rust

  ...
  ```

- **Suggested fix:** Restrict `ui.invoke_menu` (and `CommandPalette` under `app.is_gui_only()`) to an explicit allowlist of true parameterless top-level menu actions (dialog openers, view toggles, undo/redo, parameterless sheet creation), reject arbitrary `"params"` when `app.is_gui_only()` is active, and enforce `ErrorCode::GuiOnlyViolation` inside `control_io::dispatch_ui_screenshot` whenever `"path"` is present under `app.is_gui_only()`.
- **Related:** `R2-S10-04`, `R2-S12-01`, `R2-S12-03`.

### R2-S10-03 · S1 · `parse_f64_list` splits on `,` and `;` simultaneously, turning comma-decimal proportions into wrong Goodness-of-Fit *p*-values silently

- **Base:** fda1cc0106092834d97b53289ec2a99c1bf0439c
- **Location:** `crates/ui-egui/src/dialogs_r9.rs:91-117` (called from `crates/ui-egui/src/dialogs_canvas.rs:1032-1034, 2123, 3954`) at that base (introduced in `4dc7b4b`)
- **Category:** wrong-result
- **Defect:** `parse_f64_list` splits string inputs on `[',', ';', ' ']` unconditionally and parses each token with ASCII `.parse::<f64>()`, splitting comma-decimal numbers (e.g. `"0,25; 0,75"`) at their decimal separator into doubled lists of wrong numbers (`[0.0, 25.0, 0.0, 75.0]`).
- **Failure scenario:** A researcher working in a comma-decimal locale (`de-DE`, `fr-FR`, `es-ES`, etc.) opens `AnalyzeSheet` or `EditAnalysisParameters` on a 4-category `PartsOfWhole` table with observed counts `[0, 30, 0, 70]` and enters semicolon-separated expected proportions `"0,25; 0,75"` (or `"0,20; 0,80"`). `parse_f64_list` produces `vec![0.0, 25.0, 0.0, 75.0]`. Downstream, `run_parts_of_whole_gof` (`crates/stats/src/categorical.rs:2091-2118`) sees `weights.len() == 4`, normalizes by `sum = 100.0` to `[0.0, 0.25, 0.0, 0.75]`, skips the `exp <= 0.0 && obs > 0.0` check because slices 0 and 2 have `obs == 0.0`, and **silently returns a valid Chi-square / `G^2` Goodness-of-Fit `ResultSheet` computed against fabricated expected proportions**. Similarly, entering `"1,5; 2,5"` into `FormatAxes` (`axes.thresholds`, `crates/ui-egui/src/dialogs_canvas.rs:3954`) silently plots 4 threshold lines at `1.0, 5.0, 2.0, 5.0` instead of 2 lines at `1.5` and `2.5`.
- **Evidence:**
  ```rust
  let mut out = Vec::new();
  for tok in trimmed.split([',', ';', ' ']).filter(|t| !t.trim().is_empty()) {
      let v = tok
          .trim()
          .parse::<f64>()
          .ok()
          .filter(|x| x.is_finite())
          .ok_or_else(|| format!("`{field}` contains invalid finite number `{tok}`"))?;
      out.push(v);
  }
  ```
- **Suggested fix:** Thread `&LocalePreset` into `parse_f64_list`: when `locale_preset.decimal_separator == ','` (or when `;` is present alongside `,` digits), split list items only on `[';', ' ']` and parse each token via `parse_localized_number_input` rather than splitting on `,`.
- **Related:** `R2-S10-16`, `R1-S10-07`.

- **Location:** `crates/ui-egui/src/gui_actions.rs:1232-1262, 1367`, `crates/ui-egui/src/interaction.rs:466-469, 1568-1571`, and `crates/ui-egui/src/lib.rs:421-426` at that base (introduced in `8c42638` and `8ccf0d6`)
- **Category:** contract-drift
- **Defect:** `handle_answer_dialog` ignores `params.get("dialog_id")` and `patch_active_dialog`'s wildcard `_ => {}` arm returns `Ok(())` (`"updated": true`) without applying or rejecting `fields` on dialogs such as `DuplicateAnalysisPrompt`, `ResultViewer`, `CommandPalette`, or `About`; additionally, `VirtualWorkspaceFolder::open_unpacked_snapshot` deserializes `document.json` without `migrate_document_json` / `validate_project_document` (and `load_from_virtual_workspace` resets `GuiOnlyPolicy`), and `handle_key_down` on `"Backspace"` updates `app.inline_editor` without syncing `app.grid.tool.editing_buffer`.
- **Failure scenario:**
  1. If `AnalyzeSheet` transitions into `DuplicateAnalysisPrompt` and a caller sends `ui.answer_dialog` with `{"dialog_id": "analyze_sheet", "fields": {"family": "t_test"}}`, the mismatched `dialog_id` is ignored and `patch_active_dialog` hits `_ => {}`, returning `{"updated": true}` while dropping all fields; if `"action": "ok"` is also passed, it commits the wrong modal dialog.
  2. Loading a malformed virtual `document.json` via `open_unpacked_snapshot` installs an unvalidated `ProjectDocument` into `Session`, and pressing `Backspace` during inline cell editing leaves deleted characters in `app.grid.tool.editing_buffer`.
- **Evidence:**
  ```rust
  fn handle_answer_dialog(app: &mut UiApp, params: &Value) -> Result<Value, EngineError> {
      if app.canvas_dialogs.active_dialog == ActiveDialog::None {
          return Err(EngineError::with_code(ErrorCode::Conflict, "no modal dialog is currently open"));
      }
      let explicit_action = params.get("action").and_then(Value::as_str).map(|s| s.trim().to_ascii_lowercase());
      let fields = params.get("fields").or_else(|| params.get("values")).or_else(|| params.get("patches")).and_then(Value::as_object);
      if let Some(f) = fields {
          patch_active_dialog(app, f)?;
          if explicit_action.is_none() {
              return Ok(json!({ "updated": true, "dialog": format!("{:?}", app.canvas_dialogs.active_dialog) }));
          }
      }
  ```
- **Suggested fix:** Validate any non-empty `dialog_id` against the active dialog's `dialog_id` from `inspect_ui_tree` (returning `ErrorCode::Conflict` on mismatch), replace `_ => {}` in `patch_active_dialog` with explicit handling or error on fieldless dialogs, run `migrate_document_json` + `validate_project_document` in `open_unpacked_snapshot` while preserving `gui_only_policy` in `load_from_virtual_workspace`, and sync `app.grid.tool.editing_buffer` on `"Backspace"`.
- **Related:** `R2-S10-02`, `R2-S11-03`, `R2-S12-06`.
