### R2-S05-01 · S2 · `DataSheet::set_cell` and `DataSheet::clone_structure` retain stale `CellExclusionNote` entries across cell edits, clones, and `.lctemplate` stripping

- **Base:** fda1cc0106092834d97b53289ec2a99c1bf0439c
- **Location:** `crates/doc/src/links.rs:223-235`, `crates/doc/src/links.rs:359-377` at that base (introduced in `dd6d026`)
- **Category:** wrong-result
- **Defect:** `DataSheet::set_cell` overwrites `slot.excluded` when `!cell.excluded` without removing any matching `CellExclusionNote` from `self.exclusion_notes`, and `DataSheet::clone_structure` clones `self.exclusion_notes` verbatim even when `clear_y_values` clears all cells to `Cell::empty()` (`excluded = false`) or `override_replicates` reduces subcolumn bounds.
- **Failure scenario:** (1) After excluding two cells with reasons (`table.excludeCellsWithReason`), overwriting those cells via `table.setCell`/`DataSheet::set_cell` with normal unexcluded numbers, and later excluding one different cell without a reason, `generate_methods_report` (`crates/engine/src/methods_report.rs:170-172`, `documented_count = ds.exclusion_notes.len()`) emits the impossible audit statement `"1 cell(s) masked as excluded prior to analysis (2 with recorded audit justification note(s))."`; if a previously annotated coordinate is later re-excluded without a reason (`set_excluded(coord, true)`), `table.exclusionAuditReport` (`crates/engine/src/cmd/table.rs:2225`) falsely attributes the overwritten cell's historical `reason_tag`/`note`/`timestamp_utc` to the new value. (2) Cloning a sheet via `sheet.clonePipeline` (`clear_y_values: true`) or exporting a `.lctemplate` (`crates/format/src/archive.rs:615-628`) retains all donor `exclusion_notes` (including private subject notes and out-of-bounds subcolumn coordinates).
- **Evidence:**
  ```rust
  pub fn set_cell(&mut self, coord: CellCoord, cell: Cell) -> Result<(), DocError> {
      self.ensure_mutable()?;
      let Some(slot) = self.archetype.data_cell_mut(coord) else {
          return Err(DocError::CellOutOfBounds { row: coord.row, col: coord.col, subcol: coord.subcol });
      };
      *slot = cell;
  ...
  let mut cloned = self.clone();
  cloned.id = new_id;
  cloned.title = opts.title.clone();
  cloned.frozen = false;
  cloned.linked_regions.clear();
  cloned.floating_notes.clear();
  apply_clone_options(&mut cloned.archetype, opts)?;
  Ok(cloned)
  ```
- **Suggested fix:** In `DataSheet::set_cell`, call `if !slot.excluded { self.exclusion_notes.retain(|entry| entry.coord != coord); }`; in `DataSheet::clone_structure`, retain only `exclusion_notes` whose `coord` remains in bounds and still has `cloned.archetype.data_cell(entry.coord).is_some_and(|c| c.excluded)` after `apply_clone_options`.
- **Related:** `R2-S05-02`, `R2-S07-12`.

### R2-S05-02 · S2 · `.lctemplate` stripping retains `ProjectDocument::checkpoints` (leaking full raw data and results), and archive load/save skips `checkpoints` and `exclusion_notes` validation

- **Base:** fda1cc0106092834d97b53289ec2a99c1bf0439c
- **Location:** `crates/doc/src/project.rs:39-47`, `crates/doc/src/project.rs:63-66`, `crates/format/src/archive.rs:607-639`, `crates/format/src/archive.rs:801-831` at that base (introduced in `dd6d026` and `e7c4d6b`)
- **Category:** security
- **Defect:** `ProjectDocument` added `checkpoints: Vec<NamedCheckpoint>` containing full serialized `ProjectDocument` payloads in `snapshot_json`, but `strip_project_data_for_template` leaves `out.checkpoints` intact when building `.lctemplate` files, and `validate_project_document` / `validate_data_sheet` perform zero validation on `doc.checkpoints` or `ds.exclusion_notes`.
- **Failure scenario:** A researcher records a milestone with `project.createCheckpoint` (`crates/engine/src/cmd/project.rs:809-820`) on confidential clinical/experimental data and then exports a `.lctemplate` (`save_template_bytes` / `project.saveTemplate`, documented at `crates/format/src/archive.rs:68-70` as *"stripping project-specific raw data cell values and cached results"*): the resulting `.lctemplate`'s `document.json` silently embeds every raw data cell and cached statistical result table verbatim inside `checkpoints[].snapshot_json` (regression from Round 1 `S06`, where template stripping had no finding at `ebcc622`). Furthermore, `open_project_bytes` accepts archives with empty checkpoint `id`s, >`MAX_TITLE_BYTES` strings in `checkpoints`/`exclusion_notes`, out-of-bounds `exclusion_notes[].coord`, or recursively nested `snapshot_json` payloads.
- **Evidence:**
  ```rust
  pub fn strip_project_data_for_template(doc: &ProjectDocument) -> Result<ProjectDocument, FormatError> {
      validate_project_document(doc)?;
      let mut out = doc.clone();
      out.schema_version = CURRENT_SCHEMA_VERSION;
      for ds in &mut out.data_sheets { ... }
      for res in &mut out.result_sheets { ... }
      Ok(out)
  }
  ```
- **Suggested fix:** Call `out.checkpoints.clear()` inside `strip_project_data_for_template`, and extend `validate_project_document` / `validate_data_sheet` to enforce count caps, non-empty unique checkpoint `id`s, `validate_title` on checkpoint and `CellExclusionNote` text fields, in-bounds excluded `coord`s, and `checkpoints.is_empty()` inside parsed `snapshot_json`.
- **Related:** `R2-S05-01`, `R2-S07-05`, `S06` (`crates/format/src/archive.rs`).

### R2-S05-03 · S3 · `document.schema.json` (`crates/doc/src/schema.rs`) contradicts runtime `ProjectDocument` invariants on `NamedCheckpoint.created_utc`, UTF-8 title lengths, `SheetId`, and legacy `ErrorCode`s

- **Base:** fda1cc0106092834d97b53289ec2a99c1bf0439c
- **Location:** `crates/doc/src/schema.rs:460-468`, `crates/doc/src/schema.rs:481-490`, `crates/doc/src/schema.rs:573-585`, `crates/doc/src/schema.rs:592`, `crates/doc/src/schema.rs:708` (`docs/schemas/document.schema.json`) at that base (introduced in `dd6d026`, updated in `52e18d7`)
- **Category:** contract-drift
- **Defect:** `project_document_schema()` emits Draft 2020-12 constraints that reject engine-generated `ProjectDocument` JSON (`NamedCheckpoint.created_utc`, legacy `ErrorCode` aliases) while accepting payloads rejected by `lumencraft-doc` / `validate_project_document` (multi-byte titles over 4,096 UTF-8 bytes and whitespace-only `SheetId`s).
- **Failure scenario:** (1) Calling `project.createCheckpoint` without an explicit `timestamp_utc` writes `"created_utc": "unix:<seconds>"` (`crates/engine/src/cmd/project.rs:249-250, 806`), which fails Draft 2020-12 format validation against `NamedCheckpoint.created_utc`'s `"format": "date-time"` (`crates/doc/src/schema.rs:578`). (2) A CJK/Arabic/emoji title of 1,366–4,096 characters (4,098–16,384 UTF-8 bytes) passes `"maxLength": 4096` (which counts Unicode code points in JSON Schema) but fails `validate_title` (`MAX_TITLE_BYTES = 4096` bytes) with `DocError::TitleTooLong`. (3) `"   "` passes `SheetId`'s `"minLength": 1` (`schema.rs:466`) but fails `SheetId::try_new` / `register_unique_sheet_id` (`DocError::EmptyIdentifier`), and historical `ResultStatus::Failed` codes like `"invalid_input"` or `"analysis_error"` accepted by `ErrorCode::from_code_str` (`crates/doc/src/result.rs:138-159`) fail `ErrorCode`'s strict 18-value enum (`schema.rs:487-488`).
- **Evidence:**
  ```rust
  impl JsonSchema for NamedCheckpoint {
      ...
      fn json_schema() -> SchemaNode {
          object_schema(
              vec![
                  ("id", string_schema().with_min_length(1)),
                  ...
                  ("created_utc", string_schema().with_format("date-time")),
                  ("snapshot_json", string_schema()),
              ],
  ```
- **Suggested fix:** Emit real RFC 3339 UTC timestamps in `current_utc_timestamp()` (or drop `"format": "date-time"`), add `.with_pattern(r"\S")` on `SheetId`, document or align UTF-8 byte vs code-point bounds, and either relax `ErrorCode`'s schema or normalize legacy codes during document migration.
- **Related:** none.

### R2-S05-04 · S3 · `preferences.schema.json` and `journal-record.schema.json` (`crates/format/src/schemas.rs`) diverge from actual migrator and serde contracts

- **Base:** fda1cc0106092834d97b53289ec2a99c1bf0439c
- **Location:** `crates/format/src/schemas.rs:140-196`, `crates/doc/src/schema.rs:21` (`docs/schemas/preferences.schema.json`, `docs/schemas/journal-record.schema.json`) at that base (introduced in `e7c4d6b`)
- **Category:** contract-drift
- **Defect:** `preferences_schema()` and `journal_record_schema()` require version fields that are optional in `parse_preferences_json` and serde deserialization, while `SchemaLiteral::Integer(i64)` prevents expressing `u64` upper bounds on journal fields.
- **Failure scenario:** (1) `preferences.schema.json` (`crates/format/src/schemas.rs:144, 149`) requires `"version"` with `"minimum": 1`, rejecting unversioned (`{}`) and `"version": 0` preferences files that `parse_preferences_json` (`crates/format/src/versioned.rs:104-114`) explicitly supports and migrates via `PreferencesV0ToV1`. (2) `journal-record.schema.json` (`crates/format/src/schemas.rs:170, 182`) marks `"format_version"` as required on both `JournalOpRecord` and `JournalLockLease` even though both structs carry `#[serde(default = "default_v1")]` (`crates/format/src/recovery.rs:44, 99`) for pre-envelope v1 compatibility, and omits `u64::MAX` upper bounds on `seq`, `acquired_epoch_ms`, and `ttl_ms` because `SchemaLiteral::Integer` (`crates/doc/src/schema.rs:21`) stores `i64`.
- **Evidence:**
  ```rust
  pub fn preferences_schema() -> SchemaNode {
      object_schema(
          vec![
              ("version", integer_schema().with_minimum(1)),
              ...
          ],
          &["version"],
      )
  }
  ```
- **Suggested fix:** Make `"version"` optional with `"minimum": 0` in `preferences_schema()` and `"format_version"` optional in `journal_record_schema()` to match the migration/serde defaults, and widen `SchemaLiteral` (or add an unsigned bound helper) if `u64` bounds are intended. (`batch-v1.schema.json` contract drift in the same module is tracked under `R2-S06-09`.)
- **Related:** `R2-S06-09` (`batch_v1_schema()`).
