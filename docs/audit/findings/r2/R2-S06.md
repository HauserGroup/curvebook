### R2-S06-01 · S1 · `save_project_unpacked_dir` deletes arbitrary files inside the project directory via untrusted `manifest.json` `csv_path` entries and indiscriminate `sheets/` pruning

- **Base:** fda1cc0106092834d97b53289ec2a99c1bf0439c
- **Location:** `crates/format/src/archive.rs:480-497` and `crates/format/src/archive.rs:520-558` (with permissive manifest validation at `crates/format/src/archive.rs:260-264`) at that base (introduced in `e7c4d6b`)
- **Category:** data-loss
- **Defect:** `save_project_unpacked_dir` trusts any relative path inside an existing `manifest.json` (`sheets[].csv_path`) and unlinks every regular file inside `<dir>/` listed there—as well as every unexpected regular file inside `<dir>/sheets/`—violating its documented guarantee not to disturb `.git` or user files.
- **Failure scenario:** A user clones an untrusted `.lumencraft.d/` Git repository whose `manifest.json` contains a `sheets` entry with `"csv_path": ".git/HEAD"`, `".git/config"`, or `"README.md"` (all of which pass `validate_unpacked_relative_path` / `sanitize_zip_path` on both open and save, and `collect_prior_manifest_csv_paths` does not even verify `manifest.format == FORMAT_MAGIC`), opens it, and saves; `prune_stale_unpacked_files` calls `std::fs::remove_file` on `.git/HEAD`, `.git/config`, and `README.md`, corrupting the Git repository and deleting user files. Saving into a directory with a pre-existing `sheets/notes.txt` likewise deletes `notes.txt` unconditionally.
- **Evidence:**
  ```rust
  let Ok(manifest) = serde_json::from_slice::<ArchiveManifest>(&bytes) else {
      return Ok(Vec::new());
  };
  Ok(manifest.sheets.into_iter().filter_map(|e| e.csv_path).collect())
  ...
  for rel in prior_paths {
      if expected_paths.contains(rel) || validate_unpacked_relative_path(rel).is_err() {
          continue;
      }
      if let Ok(path) = resolve_contained_path(canon_root, rel, true)
          && let Ok(meta) = std::fs::symlink_metadata(&path)
          && !meta.file_type().is_symlink()
          && meta.is_file()
      {
          std::fs::remove_file(path)?;
      }
  }
  ```
- **Suggested fix:** Restrict `SheetManifestEntry::csv_path` in both `parse_and_validate_manifest` and `collect_prior_manifest_csv_paths` (after verifying `manifest.format == FORMAT_MAGIC` and `manifest.kind == ArchiveKind::Project`) to single-level canonical `sheets/<safe_stem>.csv` paths. In `prune_stale_unpacked_files`, only delete stale `sheets/*.csv` files that were tracked in a validated prior `ArchiveManifest`, rather than wiping arbitrary regular files in `sheets/` or elsewhere under `canon_root`.
- **Related:** `R2-S06-02`, `R2-S12-02`.

### R2-S06-02 · S1 · `FormatRegistry::exporter_for_path` treats any existing directory as `.lumencraft.d/`, and single-extension matching shadows unpacked directories with dots

- **Base:** fda1cc0106092834d97b53289ec2a99c1bf0439c
- **Location:** `crates/format/src/registry.rs:254-267` and `crates/format/src/registry.rs:280-293` at that base (introduced in `e7c4d6b`)
- **Category:** data-loss
- **Defect:** `FormatRegistry::exporter_for_path` returns the `lumencraft.d` directory exporter for *any* existing directory (`path.is_dir()`), and both `importer_for_path` and `exporter_for_path` check `path.extension()` before checking `is_unpacked_project_dir(path)`.
- **Failure scenario:** Calling MCP `save_file` (`crates/mcp/src/formats.rs:274, 308-311`) or `FormatRegistry::exporter_for_path` with an existing workspace or output folder such as `"."` or `"./workspace"` dispatches to `UnpackedProjectDirAdapter::export_path` (`save_project_unpacked_dir`), polluting the folder with `manifest.json` and `document.json` and deleting every regular file inside `<dir>/sheets/` (`crates/format/src/archive.rs:539-552`). Conversely, opening or saving a valid unpacked project directory whose folder name ends in a known single extension (e.g. `study.lumencraft/` or `export.json/`) matches `path.extension()` at `crates/format/src/registry.rs:258` / `284`, dispatches to the file-based adapter, and fails with `Is a directory` (`EISDIR`).
- **Evidence:**
  ```rust
  pub fn exporter_for_path(&self, path: &Path) -> Option<&dyn Exporter> {
      if let Some(ext_token) = path_multi_dot_token(path, &self.supported_export_formats()) {
          return self.exporter_by_format(ext_token);
      }
      if let Some(ext) = path.extension().and_then(|s| s.to_str())
          && let Some(found) = self.exporter_by_format(ext)
      {
          return Some(found);
      }
      if is_unpacked_project_dir(path) || path.is_dir() {
          return self.exporter_by_format(DESC_PROJECT_DIR.id);
      }
      None
  }
  ```
- **Suggested fix:** Remove `|| path.is_dir()` from `exporter_for_path` so non-`.lumencraft.d` directories are only treated as unpacked projects when `is_unpacked_project_dir(path)` holds (or an explicit `lumencraft.d` format/suffix is given). Check `is_unpacked_project_dir(path)` (and reject other `path.is_dir()` paths from file-based adapters) before `path.extension()` in both `importer_for_path` and `exporter_for_path`.
- **Related:** `R2-S06-01`, `R2-S12-02` (independent `|| path.is_dir()` bug in `apps/lumencraft-cli/src/cmd_convert.rs:222` and `crates/engine/src/cmd/project.rs:372, 444`).

### R2-S06-05 · S2 · `save_project_unpacked_dir` omits `ZipLimits` byte and entry caps, writing `.lumencraft.d/` projects that `open_project_unpacked_dir` refuses to reopen

- **Base:** fda1cc0106092834d97b53289ec2a99c1bf0439c

### R2-S06-06 · S2 · `unique_sheet_csv_path` uses case-sensitive path deduplication and unclamped stems, corrupting `.lumencraft.d/` saves on macOS/Windows

- **Base:** fda1cc0106092834d97b53289ec2a99c1bf0439c
- **Location:** `crates/format/src/archive.rs:594-604` (called from `crates/format/src/archive.rs:303-309`) at that base (introduced in `e7c4d6b`)
- **Category:** data-loss
- **Defect:** `unique_sheet_csv_path` deduplicates `sheets/<stem>.csv` names using a case-sensitive `HashSet<String>` and does not bound stem length or filter Windows reserved device names (`CON`, `PRN`, `AUX`, `NUL`, `COM1`..`LPT9`).
- **Failure scenario:** A valid `ProjectDocument` with two data sheets whose `SheetId`s differ only by ASCII case (e.g. `"WT"` and `"wt"`, producing `"sheets/WT.csv"` and `"sheets/wt.csv"`) is saved to `.lumencraft.d/` on default case-insensitive macOS APFS or Windows NTFS. `save_project_unpacked_dir` writes `sheets/WT.csv`, then atomically renames `sheets/wt.csv` over the *same* underlying inode, destroying `"WT"`'s CSV and causing `open_project_unpacked_dir` (`crates/format/src/archive.rs:448-453`) to fail with `FormatError::CorruptCrc`. Additionally, a `SheetId` > 251 bytes produces a > 255-byte filename that fails mid-save with `ENAMETOOLONG` after overwriting `document.json`.
- **Evidence:**
  ```rust
  fn unique_sheet_csv_path(idx: usize, id: &SheetId, used: &mut HashSet<String>) -> String {
      let sanitized: String = id.as_str().chars().map(|ch| if ch.is_ascii_alphanumeric() || ch == '-' || ch == '_' { ch } else { '_' }).collect();
      let stem = if sanitized.is_empty() { format!("sheet_{idx}") } else { sanitized };
      let mut candidate = format!("sheets/{stem}.csv");
      let mut suffix = 1_usize;
      while !used.insert(candidate.clone()) {
          candidate = format!("sheets/{stem}_{suffix}.csv");
          suffix += 1;
      }
      candidate
  }
  ```
- **Suggested fix:** Deduplicate `used` using `candidate.to_ascii_lowercase()`, truncate `sanitized` to a safe filesystem component length (e.g. 64 ASCII bytes), and prefix/suffix Windows reserved device stems (`CON`, `PRN`, `AUX`, `NUL`, `COM1`–`COM9`, `LPT1`–`LPT9`) so `.lumencraft.d/` directories are portable across APFS, NTFS, and ext4.
- **Related:** `R2-S06-04`.
