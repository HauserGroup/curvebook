### R2-S04-01 · S1 · `SimulatedDistribution::Binomial` accepts unbounded `trials` up to `u64::MAX`, suffering catastrophic floating-point cancellation in `sample_binomial_btrs` and `f64` integer precision loss above `2^53`

- **Base:** fda1cc0106092834d97b53289ec2a99c1bf0439c
- **Location:** `crates/transform/src/randomize.rs:652-656`, `crates/transform/src/randomize.rs:697`, `crates/transform/src/randomize.rs:761-798` at that base (introduced in `592e396`)
- **Category:** wrong-result
- **Defect:** `validate_distribution` caps `Poisson { lambda }` at `1e15` but places no upper bound on `Binomial { trials, p }`, while `ln_binomial_pmf` adds `ln_choose(trials, k)` (`+O(n H(q))`) and `k ln q + (n - k) ln(1 - q)` (`-O(n H(q))`) separately in `f64`, causing catastrophic cancellation in BTRS acceptance tests and silent integer rounding above `2^53`.
- **Failure scenario:** Calling `table.simulateDistributions` (or `simulate_distribution_columns`) with `Binomial { trials: 1_000_000_000_000_000_000, p: 0.5 }` (`10^18`, or `u64::MAX`) succeeds without error, but `rhs = ln_binomial_pmf(trials, k, q) - ln_pm` oscillates by `±64` in log-probability (or collapses to `0.0` across `±2σ` at `u64::MAX`), returning silently corrupted draws whose empirical SD is `1.43x–2.03x` (`2.05x–4.10x` variance) of the true `sqrt(n p (1 - p))` while rounding adjacent integer outcomes to identical `f64` values above `2^53`.
- **Evidence:**
  ```rust
  SimulatedDistribution::Binomial { p, .. } => {
      if !p.is_finite() || !(0.0..=1.0).contains(&p) {
          return Err(TransformError::InvalidSpec { message: format!("column {col_idx} Binomial probability p must lie in [0, 1], got {p}") });
      }
  }

  fn ln_binomial_pmf(trials: u64, k: u64, q: f64) -> Result<f64, TransformError> {
      let lc = ln_choose(trials, k)?;
      let term_q = if k == 0 { 0.0 } else { (k as f64) * q.ln() };
      let term_1_q = if k == trials { 0.0 } else { ((trials - k) as f64) * (-q).ln_1p() };
      Ok(lc + term_q + term_1_q)
  }
  ```
  Oracle (`Python 3.15.2` IEEE-754 `f64` replica of `ln_choose` + `ln_binomial_pmf` + `sample_binomial_btrs`):
  - `n = 1e16, q = 0.5`: `rhs` at `[-2, -1, 0, +1, +2]σ` = `[-2.0, +1.0, 0.0, +1.0, -2.0]` (exact: `[-2.0, -0.5, 0.0, -0.5, -2.0]`).
  - `n = 1e18, q = 0.5`: `rhs` = `[+64.0, -64.0, 0.0, -64.0, +64.0]`; 500-draw empirical SD = `7.156e8` vs exact `5.000e8` (`1.431x`).
  - `n = 5e18, q = 0.27`: 200-draw empirical SD = `2.011e9` vs exact `9.927e8` (`2.025x`); `n = u64::MAX, q = 0.5`: `rhs = [0, 0, 0, 0, 0]`, empirical SD = `1.881x`.
- **Suggested fix:** Cap `Binomial::trials` in `validate_distribution` to an exact-integer `f64` domain (e.g., `trials <= (1_u64 << 53)` or `<= 1_000_000_000_000` matching `Poisson`'s ceiling), and evaluate `ln_binomial_pmf` via Loader's saddlepoint deviance `-k * ln(k / (n * q)) - (n - k) * ln((n - k) / (n * (1 - q)))` so the `O(n)` terms never cancel.
- **Related:** none.
