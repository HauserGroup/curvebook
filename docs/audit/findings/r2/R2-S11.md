### R2-S11-01 · S1 · Closing a secondary desktop session exits the single OS window and discards unsaved changes in other sessions

- **Base:** fda1cc0106092834d97b53289ec2a99c1bf0439c
- **Location:** `apps/lumencraft/src/gui_window.rs:168-170`, `apps/lumencraft/src/gui_window.rs:191-203`, `apps/lumencraft/src/gui_window.rs:349-354`, and `apps/lumencraft/src/gui_window.rs:663` at that base (introduced in `9db2f2b`)
- **Category:** data-loss
- **Defect:** `LumenCraftNativeApp` hosts the multi-session `DesktopHostRuntime` inside a single OS viewport displaying only `focused_window_id()`, and permitting close on that focused session exits the entire `eframe` process and calls `self.runtime.close_all_force()`, discarding unsaved work in every other open session without prompt.
- **Failure scenario:** A user edits data in window `w1` (`dirty = true`), then opens a second session `w2` via `Window -> New Window` (`apps/lumencraft/src/desktop_host.rs:1421-1423`), by opening or dropping a `.lumencraft` archive onto dirty `w1` (`apps/lumencraft/src/gui_window.rs:277` -> `desktop_host.rs:1361-1368`), or via `lumencraft --new-instance a.lumencraft b.lumencraft` (`apps/lumencraft/src/main.rs:234-236`). First, `w1` disappears behind `w2` inside the single OS window with no viewport or UI switcher to reach it. Second, when the user clicks the OS close button (`X`) while `w2` has no unsaved edits (or clicks `"Don't Save"` on `w2`), `handle_close_request` sees `CloseDisposition::Closed` for `w2`, sets `self.close_confirmed = true`, lets the single OS window close, and `on_exit` invokes `self.runtime.close_all_force()`—destroying `w1`'s unsaved work without any confirmation prompt.
- **Evidence:**
  ```rust
  // apps/lumencraft/src/gui_window.rs:195-202, 663
  match self.runtime.dispatch(DesktopHostEvent::WindowCloseRequested { window_id, force: false }) {
      Ok(outcome) => {
          if matches!(outcome.close_disposition, Some(CloseDisposition::PromptUnsaved { .. })) {
              ctx.send_viewport_cmd(egui::ViewportCommand::CancelClose);
              self.close_dialog_open = true;
          } else {
              self.close_confirmed = true;
          }
      }
  ```
- **Suggested fix:** Spawn a dedicated `egui` immediate/deferred viewport per `DesktopWindowId` in `self.runtime.window_ids()`, or if remaining single-viewport, cancel the OS window close (`ViewportCommand::CancelClose`) whenever `self.runtime.window_count() > 0` after closing `window_id` so remaining sessions surface and run their own unsaved-changes prompts before exit.
- **Related:** `R2-S11-08`.

### R2-S11-03 · S1 · `WebWorkspaceHost::open_project_json_bytes` skips `validate_project_document` and schema migration, aborting WASM on malformed JSON

- **Category:** no-panic
- **Defect:** `WebWorkspaceHost::open_project_json_bytes` deserializes untrusted bytes directly with `serde_json::from_slice` into `ProjectDocument` without running `migrate_document_json` or `validate_project_document`.
- **Failure scenario:** A user drops or opens a crafted or corrupted `.json` project file (or any file whose payload begins with `{`, matched by `sniff_and_open_bytes` at `apps/lumencraft-web/src/lib.rs:497-499`) in the browser (`import_dropped_files` / `open_file_bytes`). Unvalidated documents containing ragged columns, `0` or excessive subcolumns, invalid IDs, non-finite numbers, cyclic DAG links, or unsupported future `schema_version` values are installed directly into `Session` (`lib.rs:199`) and rendered by `summary_render_command` (`apps/lumencraft-web/src/host_adapters.rs:1896, 1901`); any downstream invariant panic aborts the `wasm32-unknown-unknown` instance (`unreachable` trap), permanently crashing the web app and losing all in-memory work.

### R2-S11-04 · S2 · Closing a contending read-only browser tab forces the active holder tab to drop and race its Web Lock

- **Base:** fda1cc0106092834d97b53289ec2a99c1bf0439c
- **Location:** `apps/lumencraft-web/index.html:965-1016` and `apps/lumencraft-web/index.html:1024-1032` at that base (introduced in `461ad33`, wired in `9b7b056`)
- **Category:** data-loss
- **Defect:** Every browser tab broadcasts `{ type: "release" }` on `beforeunload` even when it never held the lock, and every tab receiving `"release"` calls `coordinateDocumentLock` which unconditionally drops its own active `navigator.locks` lease (`releaseCurrentWebLock()`), while non-`navigator.locks` contexts (`http://` LAN) grant `acquire_lock` to every tab simultaneously.
- **Failure scenario:** Tab A holds the exclusive write lock and has unsaved edits; Tab B and Tab C open later and enter read-only contended mode (`lock === null` at `apps/lumencraft-web/index.html:996`). When read-only Tab B is closed or refreshed, its `beforeunload` listener (`:1025-1027`) posts `{ type: "release", docId: "default", tabId: TabB }`. Active Tab A receives `"release"` (`:986-988`), calls `coordinateDocumentLock("default")`, and immediately executes `releaseCurrentWebLock()` (`:967-970`), dropping Tab A's Web Lock; Tab C's concurrent `coordinateDocumentLock` wins `navigator.locks.request`, demoting dirty Tab A to `ReadOnlyContended` so Tab A can no longer edit or sync its unsaved work. On plain HTTP origins (`packaging/web/README.md:18`) where `navigator.locks` is unavailable, `:1013-1015` emits `acquire_lock` in every tab without broadcasting `"holder"`.
- **Evidence:**
  ```javascript
  // apps/lumencraft-web/index.html:966-970, 986-988, 1024-1027
  if (typeof releaseCurrentWebLock === "function") {
    releaseCurrentWebLock();
    releaseCurrentWebLock = null;
  }
  // ...
  } else if (data.type === "release") {
    coordinateDocumentLock(activeLockDocId);
  }
  ```
- **Suggested fix:** Broadcast `{ type: "release" }` in `beforeunload` only when `typeof releaseCurrentWebLock === "function"` (the closing tab actually holds the lock), and ignore `"release"` messages in tabs that already hold `releaseCurrentWebLock !== null`; when `navigator.locks` is absent, coordinate holder election/heartbeats via `localStorage` + `BroadcastChannel` rather than unconditionally emitting `acquire_lock`.
- **Related:** none.
