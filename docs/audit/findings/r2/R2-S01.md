### R2-S01-01 · S2 · `ProcessCommand::run` blocks indefinitely on `stdin_handle.join()` and leaks pipe reader/writer threads on timeout

- **Base:** fda1cc0106092834d97b53289ec2a99c1bf0439c
- **Location:** `crates/platform/src/process.rs:203-214`, `crates/platform/src/process.rs:269-274`, `crates/platform/src/process.rs:447-455`, `crates/platform/src/process.rs:469-473` at that base (introduced in `7b5bafa`)
- **Category:** resources
- **Defect:** `ProcessCommand::run` joins `stdin_handle` without any deadline after `stdout`/`stderr` reach EOF and detaches blocked `stdin`/`stdout`/`stderr` OS threads on timeout while only killing the direct child PID (if not already reaped).
- **Failure scenario:** (1) If a child spawns a background helper that closes `stdout`/`stderr` while inheriting `stdin` without draining it and `stdin_bytes` exceeds the OS pipe buffer (~64 KiB, e.g., figure PDF/SVG clipboard or print payloads in `crates/ui-egui/src/os_integration.rs:503, 525, 945`), `wait_for_completion` returns `Ok(status)` and `join_best_effort(stdin_handle)` hangs forever inside `stdin.write_all(&bytes)`, completely bypassing both `wall_timeout` and `idle_timeout`. (2) On `Err(TimedOut | OutputLimitExceeded)` when the direct child already exited after forking a daemon that keeps pipes open (including Linux `wl-copy`/`xclip` idle timeouts), `ChildGuard::try_wait` has already cleared `self.child = None`, `guard.kill_and_wait()` is a no-op, and `cancelled` is never checked while `reader.read(&mut buf)` blocks in the kernel, leaking OS threads, pipe file descriptors, and buffers on every timeout.
- **Evidence:**
  ```rust
  let status = match state.wait_for_completion(&mut guard, &rx, &cancelled) {
      Ok(status) => status,
      Err(err) => {
          cancelled.store(true, Ordering::Relaxed);
          guard.kill_and_wait();
          return Err(err);
      }
  };

  join_best_effort(stdin_handle);
  ```
- **Suggested fix:** Emit a completion event from `spawn_stdin_writer` into `wait_for_completion` so `stdin.write_all` is governed by `wall_deadline`/`idle_deadline` instead of an unbounded post-loop `h.join()`, and spawn subprocesses in a dedicated process group (`process_group(0)` on Unix / Job Object on Windows) so `kill_and_wait` terminates pipe-inheriting descendants and unblocks reader/writer threads.
- **Related:** `R1-S11-08` (covers the `os_integration` `wl-copy`/`xclip` caller attaching `Stdio::piped()`, which triggers the leaked-reader path on Linux clipboard copy).

### R2-S01-02 · S2 · `PATH_PARAM_KEYS` includes bare `"template"`, breaking `table.importPlateMap` across CLI and sandboxed MCP

- **Base:** fda1cc0106092834d97b53289ec2a99c1bf0439c
- **Location:** `crates/platform/src/path_guard.rs:38`, `crates/platform/src/path_guard.rs:138-144`, `crates/platform/src/path_guard.rs:175-185` at that base (introduced in `7b5bafa`, extended to MCP in `3cd144d`)
- **Category:** wrong-result
- **Defect:** `PATH_PARAM_KEYS` classifies bare `"template"` as a filesystem path key even though no engine command takes a file path under `"template"` and `table.importPlateMap` (`crates/engine/src/cmd/table.rs:3995, 4089-4096`) defines `"template"` as an inline `PlateMapTemplate` JSON object or inline `.lctemplate` JSON string.
- **Failure scenario:** Invoking `table.importPlateMap` via `lumencraft` CLI direct commands (`apps/lumencraft-cli/src/sandbox.rs:9`, `apps/lumencraft-cli/src/cmd_commands.rs:133`), `lumencraft run-batch` (`apps/lumencraft-cli/src/cmd_run_batch.rs:202`) — even without `--workdir` (`PathResolver::Unconstrained`) — or via `--workdir`-guarded MCP (`crates/mcp/src/formats.rs:72`) unconditionally runs `sanitize_params`: passing `"template": { "geometry": "96", ... }` fails immediately with `parameter 'template' must be a string path`, while passing `"template": "{\"name\":...}"` rewrites the JSON payload into `"./{\"name\":...}"` (or `"/workdir/{\"name\":...}"`), causing JSON parsing or path canonicalization to fail.
- **Evidence:**
  ```rust
  pub const PATH_PARAM_KEYS: &[&str] = &[
      ...
      "template",
      "template_path",
      "templatePath",
      ...
  ];

  fn sanitize_path_value(resolver: &PathResolver, key: &str, val: &mut Value) -> Result<(), PlatformError> {
      match val {
          Value::String(raw) => {
              let resolved = resolver.resolve(raw)?;
              *raw = resolved.to_string_lossy().into_owned();
              Ok(())
          }
          Value::Null => Ok(()),
          _ => Err(PlatformError::InvalidPath { reason: format!("parameter `{key}` must be a string path") }),
      }
  }
  ```
- **Suggested fix:** Remove bare `"template"` from `PATH_PARAM_KEYS` (mirroring the intentional omission of bare `"csv"` documented at `crates/platform/src/path_guard.rs:18-20`), since `project.instantiateTemplate` uses `"path"`/`"template_path"`/`"templatePath"` and batch manifests resolve top-level `manifest.template` explicitly in `parse_batch_manifest`.
- **Related:** `S07` (`table.importPlateMap`), `S12` (CLI & MCP `--workdir` callers).

### R2-S01-03 · S3 · `write_atomic` resets existing file permissions to default umask and clobbers symlinks instead of updating target files

- **Base:** fda1cc0106092834d97b53289ec2a99c1bf0439c
- **Location:** `crates/platform/src/fs.rs:71-81`, `crates/platform/src/fs.rs:111-120` at that base (introduced in `7b5bafa`)
- **Category:** security
- **Defect:** `write_atomic_with_hook` creates `.{stem}.tmp.{pid}.{seq}` with default `OpenOptions` mode (`0666 & ~umask`) and renames it directly over `path` without preserving existing file permissions or following symbolic links to their target path.
- **Failure scenario:** Saving over a user-restricted `0600` `.lumencraft` archive, CSV/JSON export, or `preferences.json` on Unix silently widens permissions to `0644` (world-readable under a standard `0022` umask), exposing sensitive study data on multi-user hosts; saving to a symlinked project or dotfiles-managed `preferences.json` unlinks and replaces the symlink itself with a regular file, leaving the symlink target stale.
- **Evidence:**
  ```rust
  let (parent, file_stem) = validate_target_path(path)?;
  let (mut file, tmp_path) = create_unique_sibling_temp(parent, &file_stem)?;
  let mut guard = TempFileGuard::new(tmp_path.clone());

  file.write_all(bytes).map_err(|err| io_err(&format!("write temp file `{}`", tmp_path.display()), &err))?;
  file.sync_all().map_err(|err| io_err(&format!("sync temp file `{}`", tmp_path.display()), &err))?;
  drop(file);

  before_rename(&tmp_path).map_err(|err| io_err(&format!("pre-rename hook for `{}`", path.display()), &err))?;
  std::fs::rename(&tmp_path, path).map_err(|err| io_err(&format!("rename `{}` to `{}`", tmp_path.display(), path.display()), &err))?;
  ```
- **Suggested fix:** When `path` already exists, resolve symlink chains to the final target file (creating the sibling temp file in the resolved target's parent directory) and copy `std::fs::metadata(&resolved_target)?.permissions()` onto the temp file before `sync_all()` and `rename()`.
- **Related:** none.

### R2-S01-04 · S3 · `CanvasPreviewFilter` serde encoding (`PascalCase`) contradicts `as_str()`/`from_name()` (`lowercase`), rejecting `"grayscale"` in `WebBridgeEvent`

- **Base:** fda1cc0106092834d97b53289ec2a99c1bf0439c
- **Location:** `crates/palette/src/cvd.rs:57-93` at that base (introduced in `dd6d026`)
- **Category:** contract-drift
- **Defect:** `CanvasPreviewFilter::as_str` is documented as the *"Canonical serialization / CLI identifier"* (`"normal"`, `"deuteranopia"`, `"protanopia"`, `"tritanopia"`, `"grayscale"`), yet `CanvasPreviewFilter` derives default `serde::Serialize`/`serde::Deserialize` (`"Normal"`, ..., `"GrayscalePrint"`), which rejects every string returned by `as_str()`.
- **Failure scenario:** Desktop/UI command `ui.previewFilter.set` (`crates/ui-egui/src/control_io.rs:1297`) accepts `"grayscale"` and `"deuteranopia"` via `CanvasPreviewFilter::from_name`, whereas `WebBridgeEvent::from_json_value` (`apps/lumencraft-web/src/host_adapters.rs:1403-1404`) deserializes `SetPreviewFilter.filter` via serde and fails with `WebAdapterError::Serialization("unknown variant `grayscale`, expected one of `Normal`, `Deuteranopia`, `Protanopia`, `Tritanopia`, `GrayscalePrint`")` when a web host sends canonical `as_str()` filter names.
- **Evidence:**
  ```rust
  #[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, Default, serde::Serialize, serde::Deserialize)]
  pub enum CanvasPreviewFilter {
      #[default]
      Normal,
      Deuteranopia,
      Protanopia,
      Tritanopia,
      GrayscalePrint,
  }

  impl CanvasPreviewFilter {
      /// Canonical serialization / CLI identifier.
      #[must_use]
      pub const fn as_str(self) -> &'static str {
          match self {
              Self::Normal => "normal",
              ...
              Self::GrayscalePrint => "grayscale",
          }
      }
  ```
- **Suggested fix:** Implement custom `Serialize`/`Deserialize` on `CanvasPreviewFilter` delegating to `as_str()` and `from_name()` (while continuing to accept PascalCase `"Normal"`/`"GrayscalePrint"` in `from_name` for backwards compatibility).
- **Related:** `S11` (`apps/lumencraft-web/src/host_adapters.rs`).

## Checked, no finding

- **`WorkdirGuard::resolve` symlink and non-existent tail containment (`crates/platform/src/path_guard.rs:88-99, 200-231`):** Walks upward to the deepest existing ancestor, rejects broken/dangling symlinks via `symlink_metadata` + `canonicalize`, canonicalizes the existing ancestor (resolving macOS `/var` -> `/private/var` and case-insensitive APFS/NTFS casing), appends the non-existing suffix after rejecting `Component::ParentDir` (`..`) and NUL bytes, and enforces `resolved.starts_with(&self.canonical_root)`. Multi-component non-existent tails under symlinked parents (`symlink_to_outside/new_subdir/file`) canonicalize `symlink_to_outside` to the outside path and are rejected cleanly.
- **`write_atomic_with_hook` crash/cleanup safety (`crates/platform/src/fs.rs:67-85, 111-126`):** Uses `OpenOptions::new().write(true).create_new(true)` with PID + monotonic atomic counter to prevent symlink-clobber/TOCTOU races on temp creation, `sync_all()` before `rename`, `TempFileGuard` cleanup on any write/sync/hook/rename error, and best-effort parent directory `sync_all()`.
- **CVD & grayscale simulation math (`crates/palette/src/cvd.rs:19-54, 97-105`):** Machado, Oliveira & Fernandes (2009) matrices and ITU-R BT.709 relative luminance (`0.2126, 0.7152, 0.0722`) are applied in linearised sRGB (`color.to_linear()`), clamp non-finite `severity` (`NaN`/`±inf` -> `0.0`) and output channels (`[0.0, 1.0]`), and preserve `alpha`.
