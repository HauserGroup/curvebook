    - Baseline valid `.curvebook.d` returned `input_bytes = 2226` via `curvebook-cli bench <dir> --json`.
    - Adding symlink `untracked_leak` pointing to a `1_048_576`-byte (`1 MiB`) file outside `.curvebook.d` yielded `input_bytes = 2358` (`delta = 132` bytes = symlink path string length; `direntry_follows_symlink = false`).
    - Adding two directory symlinks `a -> .` and `b -> .` (which would cause `O(2^depth)` hang if symlinks were followed) exited cleanly (`status.success() == true`) with `loop_hung = false` (`< 20 ms`).
    - Only real non-symlink untracked files inside `.curvebook.d` are summed without depth or entry-count limits (`after_real_untracked = 1050934` for a `1 MiB` regular file), affecting reported `input_bytes`/`bytes_written` metadata (`cmd_bench_perf.rs:44`, `cmd_convert.rs:421`; `cmd_convert` itself ignores `_input_bytes` at `:148`) without traversing symlinks or escaping `--workdir`.
